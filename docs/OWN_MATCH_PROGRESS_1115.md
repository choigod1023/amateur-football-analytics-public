# 우리 경기 기준 학습·평가 개선

2026-11-15. 이번 변경은 평가 자료의 학습 혼입을 차단하고, 같은 조건에서 역할 분류를 재학습해 비교한 작업이다. 선수 신원 추적·미니맵 위치·코칭 정확도까지 개선됐다는 결과가 아니다.

## 실제로 고친 문제

역할 학습 자료에 `source_provenance.split`이 있었지만, 기존 일부 학습 경로는 이를 무시하고 고정된 네 이미지 외의 자료를 학습에 사용했다. 현재 전체 평가 자료 기준 277개 답이 이 방식의 학습에 포함될 수 있었다. 이 경로를 다시 실행한 401/413 정답은 평가 혼입 진단이며 성능으로 사용하지 않는다.

`train_team_role.py`, `retrain_reviewed_team.py`, `retrain_capacity_answers.py`에서 명시된 train 자료만 학습하게 수정했다. eval, buffer_excluded, 출처 미지정 및 서로 충돌하는 split은 학습에서 제외한다. 기존 사람 답은 수정하지 않는다. 새 실험은 시간 정보도 확인해 평가 구간과 60초 간격을 확보하고, 시각 출처가 불완전한 자료는 제외한다.

## 분리 후 재학습 결과

동일한 14개 이미지·413개 사람 답으로 평가했다. 두 모델 모두 평가 이미지를 학습에서 제외했다. 기본 학습 207개 답·6개 이미지에 기존 어려운 장면 224개 답을 더해 431개 답·13개 이미지로 학습한 결과다. 모델 구조·학습 횟수·seed·수락 임계값은 고정했다.

| 지표 | 분리한 기본 모델 | 기존 어려운 장면 추가 |
|---|---:|---:|
| 전체 정답 | 368/413 (89.10%) | 377/413 (91.28%) |
| A팀 | 126/136 | 130/136 |
| B팀 | 127/139 | 129/139 |
| 심판 | 20/30 | 23/30 |
| 관중 | 95/108 | 95/108 |
| 확신 기준을 통과한 답 중 정답 | 358/399 | 370/404 |

관중 전체 정답 수는 같지만 관중을 선수로 분류한 오류는 3→4건으로 증가했다. 그래서 전체 정확도 향상만으로 운영 교체하지 않는다. 역할 평가 판정도 이 오류를 별도 항목으로 검사해 새 후보를 regression으로 기록한다.

413개는 독립된 413명의 선수가 아니라 같은 경기 이미지에 있는 인물 답이다. 같은 경기의 개발 평가이며 새로운 경기의 최종 시험이 아니다. 기존 배포 모델의 학습 명세가 불완전하므로 배포 모델 대비 개선율로 보고하지 않는다. 골키퍼 개인 식별과 신원 연결을 검증한 것도 아니다. 자세한 분리·정답·모델 해시는 [역할 평가 보고서](OWN_ROLE_SPLIT_1115.md)에 기록한다.

## 추적 변경 자동 판정

`app/evaluation_gate.py`를 실제 추적 비교 스크립트에 연결했다. 정답 매칭이 늘더라도 미매칭 출력·중복 또는 같은 관측 기회에서의 ID 변경이 증가하면 regression으로 기록한다. 정답·평가 분리가 부족하면 needs_validation이며, 미확인 값을 0 오류로 바꾸지 않는다. 통과해도 운영 승인 대신 별도 shadow 시험 자격만 부여한다.

앞선 두 후보를 실제 기록으로 판정했다. 저점수 확정 후보는 회귀 항목 3개, 활성 ID 우선 후보는 4개로 차단됐다. 미매칭 출력은 인간이 확정한 오탐과 다르며, 이 판정은 보수적인 개발 기준이다. 코칭과 실시간 지연을 대신 평가하지 않는다.

## 사람 확인과 운영 반영

기존 동일인 답은 이미 학습에 사용됐으므로 새 독립 정답으로 재사용하지 않는다. 추가 영상 선정·기존 답 재사용·정답이 없는 범위는 [고정 평가 자료](OWN_MATCH_BENCHMARK_1115.md)에 기록한다. 새 평가용 정답은 학습 답과 분리해서 보관해야 한다.

모델과 산출물은 프로젝트 `work/own-match-benchmark-20261115/`에 별도 저장했다. 운영 서버·기존 모델·녹화·대시보드 게시 경로는 교체하지 않았다. 배포 조건은 역할 분류 향상에 더해 신원·실제 위치·장면별 코칭·지연 증거가 확보되는 것이다.

두 분류 모델을 실제 `run_live_feedback.py`에 연결해 같은 녹화 6초씩 실행했다. 양쪽 모두 정상 종료했고 각 31개 관측과 별도 대시보드 snapshot을 생성했다. 양쪽 코칭 알림은 0개다. 이는 모델 파일과 실행기 연결 확인이며 실시간 지속 성능이나 코칭 개선 증거는 아니다. `shadow-smoke/`의 실행 명령·관측·로그를 보존했다.

최종 전체 테스트 672개 통과, 1개 건너뜀. 사용자 JSON 1,204개는 이전 SHA256과 모두 같고 추가·삭제가 없다. PR은 선행 개발 브랜치를 대상으로 하며, 병합·배포는 별도다.
