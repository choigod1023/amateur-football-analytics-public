# 저장된 재등장 답 반영과 운영 검증

## 반영한 답

- d0108 same: 기존1004를 검토 경계50.2초부터845로 연결.
- d0109 same: 기존1055를57.6초부터16으로 연결.
- d0110 different:638과824는 분리 유지.

원본 녹화 SHA256, 질문 fingerprint, 인간 답 출처를 검증한다. 실행 중 검토 당시 양끝 시각과 상자(IoU≥0.9)가 실제로 재현되어야 적용한다. 이전ID와 새ID가 동시에 나타나거나, 같은ID를 중복 생성하는 승인 충돌, 새로0.6초 넘게 끊긴 관측, 시간 되감기에서는 연결을 중단한다. 누락 중 위치는 만들지 않는다. `source_id`에 원래 ID를 남긴다.

CLI `--reviewed-links-store <store>`는 **정확히 검토한 녹화 파일 전용**이다. 다른 파일 hash에는 승인 후보가 없으며 SRT 등 라이브 스트림에는 사용할 수 없다. 이 답을 다른 경기의 같은 숫자 ID에 일반화하지 않는다. 분류기 투표와 기본 추적기는 원래 ID를 유지하고, 검증된 연결만 지표·코칭 입력과 화면 ID에 반영한다.

## 실제 GPU 재생 전후

같은60초 녹화,5fps,300분석프레임을 현재 운영 설정으로 다시 실행했다. 추가한 동시 승인 충돌 방어는 최종 코드로 저장 관측을 재실행해 결과가 같음을 확인했다.

| 항목 | 결과 |
|---|---|
| 인간 same 경계 |2/2 적용|
| 인간 different 쌍 |분리 유지|
| 화면에 등장한 서로 다른 ID |56→54|
| 바뀐 화면 관측 |1004→845:42개,1055→16:9개|
| 기존 탐지·raw 추적 상자 |전체 프레임 동일|
| 원래ID로 환산한 위치·팀 |전체 프레임 동일|
| 중복 화면ID |0|
| 코칭 알림 |전체 프레임 동일(박스공격·수비선 관측변동)|

이는 기존 답을 올바르게 적용했는지 확인한 **정답 반영 회귀검증**이다. 독립 평가에서 ID 정확도가 몇% 올랐다는 뜻이 아니다. 탐지 누락 동안 점이 계속 나타나게 만든 변경도 아니다. 기존1190개 JSON SHA256을 보존한다.

## 미탐 복구 모델 승격 보류

학습 검증 자료14장면에서 첫·중간·끝 타일42개를 뽑아 같은조건(conf0.10,imgsz768,대응IoU0.5)으로 CPU 비교했다. 기존 모델과ft_n2 모두 같은126개 정답 상자를 대상으로 했다.

| 항목 | 운영 모델 | ft_n2 |
|---|---:|---:|
| 정답 대응 |116|115|
| 놓친 정답 |10|11|
| 정답 미대응 탐지 |37|40|

미대응은 부분 인물·불완전 라벨일 수도 있어 확정 오탐으로 세지 않는다. 그러나 알고 있는 인물 회수도 줄고 미대응도 늘었으므로 새 모델을 운영에 승격하지 않는다. 이전6개 선택 장면의4/6 후보 발견만으로 교체하는 판단을 피했다. 이 검증 자료는 모델 선택에도 쓰였으므로 독립 경기 평가가 아니다.

기존의 낮은 신뢰도 실제 관측 표시 보충은 유지한다. 운영 모델 가중치와 원본 영상·사용자 답은 교체하지 않는다.
