# 추적 유지와 팀 자동 분류: 자료와 검증 계획

## 현재 코드에서 확인한 문제

* 원본 25fps SRT를 분석할 때 최신 프레임 한 장만 남기므로 처리 속도가 부족하면 중간 프레임을 버린다. 이는 지연 누적을 막지만 움직임 예측·매칭에는 불리할 수 있다. 실제 수신 속도와 프레임 차이를 함께 기록해야 한다.
* 전체 6500×1000 영상을 한 번에 640으로 줄이면 선수가 매우 작아진다. 같은 영상 두 구간의 타일 추적 정답 매칭과 원본 비교는 [광각 추적 검증](wide-tracking-validation.md)을 참고한다.
* 타일 탐지 단계의 기본 confidence 0.35는 현재 ByteTrack 설정의 low 0.10과 high 0.25보다 높다. 약한 탐지로 기존 트랙을 복구하는 단계에 필요한 박스가 미리 걸러질 수 있다. detector 문턱을 낮추는 동시에 새 트랙 생성 문턱을 유지하는 실험이 필요하며 오탐·ID 교체도 함께 비교해야 한다.
* 내부 트래커의 손실 보관과 대시보드 출력은 별개다. 서버는 검출된 위치를 주로 출력하고 실험 미니맵의 별도 예상은 최대 0.8초만 표시한다. 시간이 길어질 때의 오차 가늠은 [가림 시간 실험](occlusion-duration-study.md)을 참고한다.
* 0~30, 30~60, 60~90초는 원본 연속 구간이나 현 로컬 실험 재생기는 매 30초마다 확인 상태를 초기화했다. 90→120초 건너뛰기와 150→0초 반복은 실제 불연속이다. 로컬 네 조각만의 문제이며 일반 SRT에서 30초마다 리셋하는 것은 아니다. 불연속 시 미니맵만이 아니라 추적기·색상 후보도 초기화해야 한다.
* 두 팀 색상 후보는 매 프레임 흔들리며 A/B를 실제 홈·원정이나 선수 역할로 확정하지 않는다. 유니폼 외형이 비슷한 선수, 심판·골키퍼, 작고 어두운 크롭, 오탐과 ID 전환을 따로 살펴야 한다.

## 검토한 1차 자료와 적용 후보

1. [ByteTrack 논문 및 공식 코드](https://github.com/FoundationVision/ByteTrack): 낮은 confidence 탐지까지 기존 궤적과 연계하는 접근. 사용자 기기에는 Ultralytics 구현이 이미 설치돼 있으며 참고용 원 저장소의 MIT와 설치된 구현의 라이선스는 별개다. 실시간 데이터의 낮은 신뢰도 후보가 늘면 잘못된 연결도 늘 수 있어 실제 비교가 필요하다.
2. [BoT-SORT 공식 코드](https://github.com/NirAharon/BoT-SORT): 운동·외형 재식별 및 카메라 움직임 보정을 결합한다. 원 코드 저장소는 MIT이지만 외형 모델과 가중치의 이용 조건은 각각 확인해야 한다. 동색 유니폼 선수끼리는 외형이 비슷하므로 특정 모델의 MOT 결과를 이 영상의 성능으로 옮길 수 없다.
3. [SoccerNet 게임 상태 복원 공식 코드](https://github.com/SoccerNet/sn-gamestate): 추적·재식별·역할·팀·등번호·경기장 위치를 조합한다. 소스는 GPL-3.0이며 데이터·가중치 조건은 별도다. 별도 사용 조건 검토와 기기 성능 측정 전에 기존 서버에 직접 결합하지 않는다.
4. [Roboflow Sports 축구 예제](https://github.com/roboflow/sports/blob/main/examples/soccer/README.md): 선수 이미지의 SigLIP 임베딩과 UMAP/KMeans로 두 팀 후보를 만든다. 모델 및 가중치 라이선스, 최소 해상도, 심판/GK와 동일 유니폼 오류, 운영 GPU 비용을 별도로 확인해야 한다.
5. [SoccerNet-GSR 논문](https://openaccess.thecvf.com/content/CVPR2024W/CVsports/html/Somers_SoccerNet_Game_State_Reconstruction_End-to-End_Athlete_Tracking_and_Identification_on_CVPRW_2024_paper.html): 선수 위치·역할·팀·등번호를 함께 평가하는 접근이다. 11대11은 과도한 궤적 생성을 억제하는 부드러운 단서가 될 수 있으나, 가려진 사람의 실제 좌표나 신원을 증명하지 않는다.

## 평가 원칙

서로 다른 경기의 라벨로 모델을 사전학습하고, 현재 광각 경기는 학습·검증에 사용하지 않은 평가 영상으로 둔다. 팀의 A/B 인덱스는 평가 구간의 정답을 보고 매 프레임 뒤집지 않는다. 초기 무라벨 적응을 허용할 경우 시간과 방법을 고정하고 정답은 사후 평가에만 사용한다. 같은 경기 인접 프레임은 독립 사례가 아니므로 경기 수, 프레임 수와 선수 수를 구분한다.

정답 박스 매칭률과 매칭되지 않은 검출을 함께 보고, 사라진 뒤 같은 ID로 돌아온 횟수와 다른 ID로 이어진 횟수도 측정한다. 정답 누락은 오탐처럼 보일 수 있다. 표준 IDF1/HOTA는 공식 평가 절차·프레임 정렬·주석 조건을 갖춘 후 별도로 계산하고 단순 재등장 카운트와 혼동하지 않는다. 팀은 맞음·틀림·미분류뿐 아니라 심판/GK·미매칭 탐지 혼입을 함께 보고한다. SRT의 수신 프레임과 원본 정답의 시각을 확인하지 못하면 실시간 전후 매칭률은 주장하지 않는다. 선수·위치가 불확실할 때는 신뢰도와 마지막 관측 경과 시간을 표시하고 코칭 결론의 강도를 낮춘다.
