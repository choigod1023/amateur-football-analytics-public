# 신규 트랙 확정·연결 순서 수정의 실제 영상 비교

2026-11-15. 낮은 탐지 점수를 확정 단계에서 다시 곱하면 같은 상자가 반복돼도 확정하지 못하는 조건을 재현했다. 확정 및 활성 트랙 우선 로직을 구현해 비교했으나, **이번 후보 중 운영 기본값으로 승격할 만큼 누락·오연결이 함께 개선된 것은 없다.** 합성 회귀 수정과 실제 전체 추적 품질 향상을 구분한다.

## 고정 평가

- AI Hub 305·306, 각각 0–30/300–330/600–630초. 30fps 원본에서 5fps, 각 450프레임, 총 900프레임.
- YOLO11n, imgsz=1280, conf=.1, GPU device=0으로 실제 영상을 재추론했다. 두 추적기에 동일한 배열을 제공했고, JSONL 캐시의 SHA256을 재생 시 검증한다. 영상·라벨·가중치·후보 코드 해시도 기록했다.
- BYTETracker high/new=.12, low=.06, buffer=50, match=.98, fuse_score=True 고정. 정답 ID는 평가에만 사용했다.
- 모든 지표는 greedy IoU>=.5 기반 진단이다. 공식 HOTA/IDF1이 아니며, 상자 미매칭을 인간이 확인한 오탐으로 간주하지 않는다.
- 아래 조건은 개발 중 순차 비교했다. 임계값 최적화는 하지 않았으나 같은 평가 결과를 보고 구조를 수정했으므로 독립 최종시험이 아니다. 4개 비교 중 유리한 숫자만 골라 성능으로 보고하지 않는다.

공통 연속 관측은 두 방식 모두 앞뒤 프레임에 같은 GT 선수가 매칭된 경우만 비교했다. 각 후보의 관측 집합이 달라 분모도 다르다.

첫 후보는 기존 확정 성공까지 기하 조건으로 교체해 정답 매칭을 잃었다. 두 번째는 기존 성공을 먼저 보존하고 남은 score<.3 후보만 IoU>=.5, 양방향 최선·차선 차이>=.1, 세 관측으로 확인했다. 정답 매칭은 14건 늘었지만 미매칭 출력도 474건 늘어 승격하지 않았다.

세 번째는 활성 트랙을 먼저 연결해 같은 관측의 ID 변경을 698→630으로 줄였지만, 정답 매칭을 139건 잃었다. 마지막 조건은 IoU>=.5와 양방향 .1 차이를 만족하는 명확한 활성 트랙만 우선하고 나머지는 원래 공동 연결로 보냈다. 매칭 +11건, ID 변경 +8건, 미매칭 출력 +22건으로 전체 개선 근거가 없다.

## 새 출력의 구성

같은 프레임의 detection index로 기존·후보 출력을 비교했다. raw track ID는 알고리즘마다 달라 직접 비교에 쓰지 않았다.

- 저점수 세 관측 확인: 새 출력 784건 중 GT 매칭 50, 미매칭 734. 삭제 출력 296건 중 GT 매칭 37.
- 명확한 활성 트랙 우선: 새 출력 202건 중 GT 매칭 68, 미매칭 134. 삭제 출력 169건 중 GT 매칭 55.

예측 상자가 달라져 공통 출력의 GT 매칭도 바뀌므로 이 차이가 전체 매칭 증감과 정확히 같지는 않다. 추가 출력이 관중·오탐·라벨 누락 중 무엇인지는 별도 영상 검수가 필요하다. 최종 조건의 GT 중복 주장 수는 기존과 같은 10건, 출력 간 IoU>=.8 쌍도 양쪽 0이었다. 높은 IoU 중복이 없다는 것이 오연결 없음을 뜻하지 않는다.

사용자 녹화 6초를 기존 실행기와 저점수 확인 실행기로 각각 읽었다. 양쪽 모두 정상 종료, 31개 분석 관측과 독립 대시보드 snapshot을 생성했다. 코칭 알림은 양쪽 0건이었다. 출력 위치는 `work/tracker-confirmation-fix-20261115/smoke/`이며 운영 게시 디렉터리는 건드리지 않았다. 이는 실행 연결 확인이며, 코칭 정확도 개선의 증거가 아니다.
