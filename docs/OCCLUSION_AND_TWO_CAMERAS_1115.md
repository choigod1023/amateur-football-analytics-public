# 겹침 ID 감사와 두 카메라 검토

## 이번에 확인하고 수정한 것
기본 TeamVotes 경로는 서로 겹친 인물 상자의 혼합 유니폼 특성도 누적했다. guarded 경로는 당장 라벨을 보류했지만 기본 누적 카운터와 과거 이력을 보유했다. 겹친 후 raw ID가 다른 사람에 붙으면 이전 팀 정보까지 이어질 위험이 있다.

상자 교집합/작은 상자 면적 비율 0.35 이상인 ID의 팀 투표를 초기화하고 겹친 크롭을 누적하지 않는다. 겹침 동안 라벨은 보류하고 분리 후 기본 3회 깨끗한 관측으로 재확인한다. 주변의 겹치지 않은 ID는 보존한다. ID 자체나 사용자 분류 답·모델 가중치는 변경하지 않는다. 동일 유니폼 두 선수의 ID 교환을 해결하는 알고리즘은 아니다.

## 두 카메라 결론
두 시점의 겹치는 시야는 한쪽 가림을 다른 쪽 관측으로 보완할 수 있다. 축구 다중 카메라 연구는 외형만이 아니라 선수 이동과 주변 관계, 공통 경기장 좌표를 사용한다. 다만 해당 연구는 4~6개 카메라를 상정하므로 우리 2대 야간 환경에 향상률을 옮길 수 없다.

출처: [Graph-Based Multi-Camera Soccer Player Tracker](https://arxiv.org/html/2211.02125v1), [MIT multiview soccer tracking](https://dspace.mit.edu/entities/publication/2bd86bbf-9053-4e9e-8ded-df7b835ab5bf), [다중 시점 축구 데이터](https://www.mdpi.com/2076-3417/13/9/5361).

설치 제안(연구로부터 도출한 설계 판단): A는 현재처럼 높은 광각 고정 위치, B는 반대편 또는 대각선 높은 위치에서 교차가 잦은 구역을 함께 보도록 배치한다. 바로 옆 동일 시선은 가림을 공유할 수 있다. 두 반쪽을 중첩 없이 촬영하면 화질/범위 개선은 가능하나 교차 ID 해결 근거는 약하다.

SRT latency는 네트워크 전달과 패킷 간격 복원이며 아이폰 두 대의 촬영 시계를 자동 동기화한다는 뜻이 아니다. [Haivision 공식 문서](https://github.com/Haivision/srt/blob/master/docs/features/latency.md). 공통 영상 신호로 시차를 맞추고 녹화 중 드리프트도 확인해야 한다. 서버 도착 시각만으로 합치지 않는다. 6m/s 가정의 시간오차 계산: 33.3ms 약0.20m, 50ms 0.30m, 100ms 0.60m, 200ms 1.20m. 실측 위치 오차가 아니다.

## 구현/시험 제안
1. cam_a/cam_b 별도 수신·녹화 경로. 현재 운영 설정은 변경하지 않음. [MediaMTX SRT 경로](https://mediamtx.org/docs/features/srt-specific-features).
2. 두 영상을 같은 경기장 좌표로 각각 보정. 지면에 닿은 선수 발 위치의 2D 미니맵부터 시작. 공중 공의 3D는 별도 문제.
3. (camera_id,local_track_id)를 global_player_id에 연결. 동기화 오차·위치·팀·이동·외형을 함께 보며 각 카메라의 탐지를 한 선수에 중복 배정하지 않음. 불확실 대응은 보류.
4. 제한된 동기화 버퍼, 오래된 영상 폐기, 한쪽 끊김 시 단일 카메라로 동작.
5. 5~10분 동시 녹화로 같은 장면의 A만/B만/A+B 비교. ID switch, IDF1/HOTA, 가림 복귀, 실제 위치 오차, 지연/메모리 측정. 교차 전후 동일인 정답 일부 필요. 같은 영상을 복제한 송출은 부하 시험만 가능하고 시점 추가 이득 검증은 아님.

각8Mbps 두 영상이면 합계16Mbps, 영상 저장 약7.2GB/시간, 5시간36GB(오디오·컨테이너·재전송 제외). 카메라별15fps면 합계30fps이며 단순 직렬 처리 예산33ms/프레임. RTX5070 실제 처리 가능 여부는 두 영상 실측 전 미확정.

참고 소스: [TrackTacular](https://github.com/tteepe/TrackTacular), [MVDeTr](https://github.com/hou-yz/MVDeTr). 구조 참고이며 우리 환경에서 설치·학습·라이선스 확인을 완료한 상태가 아니므로 코드를 복사하거나 배포하지 않았다.

전체 회귀 검사에서 직전 PR의 match-roster.js가 공개 대시보드 정적 파일 허용목록에 빠진 404도 발견해 함께 수정했다. 기존 DOM 모의 실행만으로 놓친 연동 결함이며, 실제 root 페이지의 모든 자산 HTTP 응답 회귀 검사로 검증한다.
