# 선수 추적·미니맵 실제 녹화 비교

2026-11-15. 사용자 녹화 60초를 두 역할 모델로 각각 전체 실행했다. 이후 같은 좌표에 변경 전후 위치 검사를 적용해 역할 분류 효과와 위치 코드 효과를 분리했다. 운영 서버와 기존 답은 변경하지 않았다.

## 실제 수정: 거절 좌표로 다음 정상 위치까지 거절하는 문제

기존 PositionGuard는 튄 위치를 거절해도 그 위치를 다음 프레임의 기준으로 저장했다. 예를 들어 0m→10m(거절)→0.1m에서도 정상 복귀한 0.1m를 다시 거절했다. DisplayPositionGuard는 표시를 생략할 때 마지막 정상 위치 기록도 지워 다음 프레임의 급격한 이동을 검사하지 못했다.

둘 다 마지막 허용 좌표만 최대 0.6초 기억하도록 수정했다. 기억한 좌표를 선수 출력에 추가하거나 화면 밖 위치를 생성하지 않는다. 실제 새 관측이 들어왔을 때만 검사한다. 장기 공백과 시계 역전은 별도 구간으로 초기화한다.

표시 관측 수는 인원수가 아니라 모든 프레임의 인물 관측 합이다. 위치 처리 수정은 과속 조건을 위반하는 연결을 제거한 것이며, 실제 미터 위치 오차가 줄었다는 증거가 아니다. 실제 발점 정답은 없다. 표시 관측이 감소하므로 누락 감소로 해석하지 않는다.

코칭은 기본 모델에서 7초 box_attack·20초 gap_wide에 수정 후 29초 box_attack이 추가됐다. 후보 모델에서는 전후 모두 15초 line_drop·23초 gap_wide·35초 box_attack이었다. 알림의 실제 장면 적합성은 아직 검증하지 않았다. 알림 수 증가를 코칭 개선으로 보고하지 않는다.

## 역할 모델만 바꿨을 때

- 원시 추적과 구간 ID 배열은 300프레임 모두 동일, 관측 9,153개.
- 같은 ID의 인접 팀 전환: 36→16회.
- 어느 한 팀이 11명을 넘는 프레임: 157→24개.
- 추적 ID는 계속 있는데 미니맵에서 사라지는 전환: 88→82회.
- 표시 관측은 5,294→5,213으로 81개 감소. 역할 제외도 늘어났으므로 위 지표만으로 정확도 향상을 단정할 수 없다.

따라서 새 분류 모델은 팀 표시와 과다 인원 진단에 영향을 줬지만, 자동으로 선수 재연결을 개선하지 않았다. 기존 관중→선수 오분류 증가도 남아 있어 후보 모델을 운영에 교체하지 않았다. 자세한 실행 명세는 [역할·추적 비교](ROLE_TRACKING_1115.md)에 있다.

## 이미 확인한 사람 답 재적용

현재 영상 SHA256과 검토 항목 fingerprint를 검증한 기존 답 8개를 확인했다. 자동 추적만 사용하면 same 답 7개는 여전히 서로 다른 ID였다. 기존 ReviewedReconnector로 정확한 시각과 상자를 재현한 경우에만 답을 적용하면 same 7건은 연결되고 different 1건은 분리를 유지했다.

이것은 기존 수동 수정 기능이 해당 녹화에 적용되는지 검증한 것이다. 답을 적용한 뒤 같은 답으로 확인했으므로 100% 독립 정확도나 새로운 모델 학습 성과가 아니다. 새 라이브의 임의 ID에 이 연결을 이식하지 않는다. 사용자의 답 파일은 그대로다.

선수 신원 전체 정답·발점 위치 정답·코칭 장면 정답은 아직 없으므로 정확도는 null이다. 입력 추적이 잘못된 경우 위치 검사가 같은 사람임을 보증하지 않는다. 수정 코드는 위치 안전성을 높이지만 완전한 추적 해결책은 아니다. 운영 재시작·배포는 하지 않았다.

수정된 실행기 자체로도 같은 녹화 6초를 별도 실행했다. 정상 종료했고 31개 관측·대시보드 snapshot을 생성했으며 알림은 0건이었다. 이는 실행 연결 검증이고 코칭 정확도 증거는 아니다. 전체 테스트 684개 통과, 1개 건너뜀. 사용자 JSON 1,204개의 해시가 모두 유지됐다.
