# 동일 탐지 상자를 이용한 ByteTrack 연결 비교 (2026-11-11)

9경기 학습 모델과 탐지 confidence 0.95를 고정하고, 동일한 타일 탐지 결과를 서로 다른 ByteTrack 설정에 전달했다. `match_thresh`는 연관 비용의 허용 문턱으로 0.9가 0.8보다 완화된 설정이다. 각 실험은 SoccerTrack `match-20200220` 100프레임, 시작 350, 두 원본 프레임마다 처리했다. 이 경기는 이전 개발에 사용되어 독립 최종 시험이 아니다. 매칭은 IoU 0.5 기준 탐욕 알고리즘이며, 표준 HOTA/IDF1이 아니다. 같은 정답 선수가 주석에 계속 있는데 일시적으로 매칭되지 않은 뒤 돌아오는 경우만 계산한다.

60–90초 추가 감사에서 여러 정답 선수에게 매칭된 추적 ID는 두 설정 모두 10개, 여러 추적 ID와 매칭된 정답 선수는 12명에서 11명이었다. 이 값은 정답과의 박스 매칭 오류도 포함할 수 있어 실제 ID 혼동 횟수와 동일하지 않다. 낮은 문턱 0.6은 60–90초 같은 ID 44, 변경 95로 더 나빴다. 버퍼 길이 5와 90도 따로 비교했으나 일관된 개선이 없었다.

0.9는 후속 실험 후보이나 한 경기, 100프레임씩의 제한된 구간과 불완전한 지표만으로 다른 선수와 잘못 이어지는 문제나 화면 밖 복귀를 검증할 수 없다. 결과는 이전에 공개된 평가 구간을 참고했으므로 새 경기에서 사전에 정한 평가로 재확인해야 한다. 0.9를 운영값으로 바꾸지 않았다. 실제 SRT와 아이폰은 시험하지 않았고, 이 실험에서 속도는 다른 GPU 부하에 영향을 받으므로 평가하지 않았다.
