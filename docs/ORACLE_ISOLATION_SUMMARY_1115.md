## 병렬 작업 결과

### 선수 추적

AI Hub 305·306 영상의 고정된 세 구간씩, 총 900개 평가 프레임을 사용했다. 추적기에 정답 상자만 주고 선수 정답 ID는 평가기에만 줬다. 15fps 조건도 동일한 5fps 프레임에서 평가했다.

- 5fps: 정답 18,112건 중 현재 탐지와 연결된 출력 9,192건(50.8%). 연속 관측된 선수의 ID 변경 2,486/5,610회(44.3%).
- 15fps: 현재 탐지와 연결된 출력 14,021건(77.4%). 연속 관측 ID 변경 3,358/11,313회(29.7%).
- BoTSORT와 카메라 움직임 보정 15fps: 출력 13,034건(72.0%), 연속 관측 ID 변경 2,952/10,356회(28.5%). BYTE15보다 미출력이 987건 늘어 채택하지 않았다. 추적기와 보정을 함께 바꾼 조건이므로 보정 단독 효과는 아니다.
- ID 변경 절대 건수만 비교하면 안 된다. 더 많이 관측하면서 비교 가능한 경우도 늘었기 때문이다. 분모와 관측률을 함께 보고해야 한다.
- 정확한 상자를 줘도 문제가 남으므로 탐지 재학습만으로 해결되지 않는다. 팀 정답이 곧 개인 신원 정답인 것도 아니다. 같은 팀 안의 연결 문제를 별도로 해결해야 한다.
- 실행 중 내부 상태를 확인하니 5fps 미출력 8,920건, 15fps 미출력 4,091건은 모두 신규 트랙의 `is_activated=False` 상태와 일치했다. 상자 누락 자체보다 기존 ID 연결 실패와 새 트랙 확인 정책이 출력 단절에 관여한다. 신규 상자를 즉시 전부 표시하면 실제 탐지의 오탐도 늘 수 있으므로 정답 상자 결과만으로 정책을 풀지 않았다.

추가 추적기·카메라 보정 비교와 상세 조건은 [추적 보고서](ORACLE_TRACKING_1115.md)에 기록한다. 이 자료는 이미 개발에 사용된 평가 영상이며 최종 독립 시험이 아니다.

### 코칭

실제 60초 녹화 관측 300프레임에서 기존 3초 시점 박스 알림을 제거했고 24초 수비선 알림은 유지됐다. 남은 알림이 실제 전술상 맞다는 검증까지 끝난 것은 아니다. [코칭 보고서](ORACLE_COACHING_1115.md).

### 공

### 미니맵

cam3 클릭 기준점 재적합 RMS 0.961m, 한 점씩 제외한 최대 오차 4.115m는 기준점의 일관성이다. 실제 선수 발점·위치 정답이 없어 선수 좌표 정확도로 보고할 수 없다. 보정이 틀리면 추적을 개선해도 잘못된 위치로 코칭하게 된다.

## 다음 개선 순서

1. 정답 상자 실험에서도 남는 추적 연결 오류를 먼저 줄인다. 관측률, 오연결, ID 변경을 함께 비교하고 실제 탐지를 넣어 다시 검증한다.
2. 사람이 저장한 팀·역할 답은 보존하고 분류 학습에 쓴다. 개인 재연결에는 앞뒤 장면의 동일인 정답과 다른 사람 정답을 따로 사용한다.
3. 미니맵은 대표 장면의 실제 접지점과 경기장 기준점을 확인받아 위치 오차를 측정한다. 같은 팀을 반복 분류시키는 것으로 이 문제를 해결하지 않는다.
4. 공은 빈 화면 오탐과 후보 선택 실패를 별도로 학습하고, 학습과 분리한 경기에서 검증한다. 미래 프레임을 쓰는 저장 영상 경로는 지연 조건을 정한 뒤 라이브에 통합한다.
5. 코칭은 알림 생성 여부뿐 아니라 해당 앞뒤 영상에 맞는 설명인지 평가한다. 정확하지 않은 입력으로 알림 개수를 늘리지 않는다.
