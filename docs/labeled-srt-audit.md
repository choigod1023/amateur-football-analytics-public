# 실제 SRT 구간과 재등장 ID 검증

## 입력과 정답 동기화

`scripts/evaluate_labeled_srt.py`는 저장된 경기 영상의 상단 하늘 영역에 10비트 원본 프레임 번호와 8비트 검사값을 새겨 로컬 임시 영상으로 만들고, FFmpeg→루프백 SRT→MediaMTX→RTSP→실제 분석 프로그램 경로를 사용한다. 추론된 프레임에서 검사값이 맞는 번호만 읽어 같은 번호의 SoccerTrack 주석 박스와 IoU 0.5 이상으로 일대일 매칭한다. 프레임 누락·번호 오류를 별도로 세고, 개인 정보·이미지 원본은 저장소나 외부 서버에 내보내지 않는다. 번호와 경기장 밖 마커가 있는 MJPEG 임시본과 SRT용 H.264 두 번의 인코딩 때문에 원본 그대로의 최종 평가가 아니다. 체크섬은 오류 검출을 강화하지만 모든 손상을 증명해 주지 않는다.

20200220 경기 60~90초 구간 프레임 350~549를 이 PC의 루프백에서 두 번 송출했다. COCO 사전학습 YOLO11n은 confidence .35, 9개 AI Hub 경기로 학습한 후보는 다른 개발 경기에서 미리 선택한 .95를 사용했고 둘 다 동일 타일 방식과 ByteTrack을 썼다. 이 경기는 9경기 가중치의 신규 학습·개발에 넣지 않았지만, 이 프로젝트의 이전 실험에는 반복 사용된 자료이므로 완전한 최종 블라인드 평가는 아니다.

두 번의 실제 SRT 수신·분석에 공통으로 등장한 **12프레임**의 정답 상자 264건 중 기본 모델은 82건(31.1%), 9경기 후보는 93건(35.2%)을 IoU 0.5 이상으로 매칭했다. 예측 상자 중 정답과 매칭된 비율은 각각 82/125(65.6%)와 93/187(49.7%)였다. 미매칭 탐지는 주석 누락이나 매칭 실패일 수도 있다. 공통 표본 중 매칭이 끊겼다 돌아온 후 이전 ID를 유지/변경한 건수는 기본 8/6, 후보 5/4였다. 매우 작은 상관 표본이어서 성능 우열을 확정할 수 없다.

같은 12프레임을 프레임별로 짝지어 보면 9경기 후보의 매칭 수가 더 많았던 프레임은 8개, 더 적었던 프레임은 2개, 같았던 프레임은 2개였다. 정답에 연결되지 않은 예측은 11개 프레임에서 증가하고 1개에서 감소했다(총 51건 증가). 매칭 증가가 미매칭 증가와 함께 발생했음을 보여주는 기술 통계일 뿐, 주석 누락 가능성 때문에 미매칭을 모두 오탐으로 확정하거나 연속 프레임 12개를 독립 표본으로 해석하면 안 된다.

두 송출 중 H.264 디코더 오류가 출력되고 스트림이 일찍 끊겼다. 송출기가 살아있는 동안 수신이 끊긴 관측도 있어 장애 원인이 정상 종료인지 자원·부호화/전송 문제인지 확인되지 않았다. 따라서 이 결과는 **동기화한 루프백 SRT 경로의 불완전한 예비 시험**이며, 안정적인 라이브 성능이나 아이폰 셀룰러 전송 성능을 보증하지 않는다. 원본 캡처·정답·두 모델 출력의 프레임 교집합 JSON은 로컬 `work/srt-holdout-eval`에만 있다. 이 영상 주석을 모델 학습에 주입하지 않았다.

로컬에 저장한 두 `--output` JSON과 해당 주석 CSV가 있으면 `python scripts/compare_labeled_srt.py --first <첫_결과.json> --second <둘째_결과.json> --labels <주석.csv>`로 동일 프레임 집계와 재등장 ID 대조를 재현할 수 있다. 프레임 중복, 주석 누락, 수량 불일치와 중복 매칭은 거부한다. 표식 송출은 `python scripts/evaluate_labeled_srt.py --help`로 인자를 확인하며 별도 로컬 전용 포트 23574/TCP, 23974/UDP를 사용한다.

## 재등장과 프레임 드롭 진단

`evaluate_wide_tracking.py`의 `--stride`는 모델이 받아들이는 원본 프레임 간격이고 `--score-stride`는 모델 추론은 유지하면서 평가만 건너뛰는 간격이다. 현재 25fps 경기의 원본 350,353,…,437 동일한 30시점에 대해 일반 모델 confidence .35를 비교했다. 90프레임을 모두 처리한 뒤 3번째마다 평가하면 320/660(48.5%) 정답 매칭과 누락 후 재등장 34건 중 ID 변경 9건이었다. 원본 3프레임마다 30회만 처리하면 동일 평가 시점에서 156/660(23.6%)과 재등장 17건 중 ID 변경 13건이었다. 전체 처리 속도는 약 6.2fps로 실시간 25fps는 아니다. 고정 간격 오프라인 모의이며 실제 유동 프레임 드롭·다른 경기 일반화를 뜻하지 않는다.

재등장 지표는 주석상 선수가 계속 남아 있는 평가 시점에서 모델과의 매칭이 한 번 이상 빠진 다음 다시 매칭될 때만 계산한다. 그 사이 미관측이 평가 간격 밖에서 일어난 경우, 영상에서 실제로 나간 경우, 주석이 없는 경우 또는 종료 전에 복구되지 않은 경우는 세지 못한다. 인접 평가 시점의 ID 변경과도 별도이며 표준 IDF1/HOTA가 아니다.

## 경계 reset

현재 로컬 데모의 첫 세 구간(0~30, 30~60, 60~90초)은 같은 경기의 연속 영상이고 다음 120~150초는 30초가 건너뛰어진다. 주석의 공통 인물 중심 이동 중앙은 앞의 두 연속 경계에서 원본 각각 1.98·1.57픽셀, 불연속 및 반복 경계에서는 235.68·243.4픽셀이었다. 각 MP4는 25fps·30초다. 모든 30초마다 재설정하면 연속 경계에서도 미니맵 예측 이력과 수동 확인이 지워진다. 반대로 실제 불연속에서 기존 추적기를 유지하면 다른 사람에게 같은 ID가 넘어갈 수 있어, 명시된 불연속 신호에서 ByteTrack·색상 군집·예측 이력을 함께 비우도록 구현했다. 추가 `tracking_generation`은 ID가 재사용될 수 있음을 클라이언트가 구분하도록 돕는다. 자동 장면 전환 탐지나 iPhone 입력의 끊김 판별은 아니다.
