# 관찰자가 직접 확인한 선수만 분석하기

`manual_player_assignments: true`는 자동 팀 분류와 별도의 선택 모드다. 기본값은 false이며 `temporal_team_consensus`와 함께 사용할 수 없다. 경기 영상에서 사람을 자동 탐지하되 처음에는 모두 `unknown`이다. 관찰자가 실제 화면을 확인해 필드 선수와 팀을 지정한 ID만 팀 간격 지표에 포함한다. 심판·골키퍼와 미확인 ID는 팀 `unknown`으로 남는다. 이는 자동 역할 인식이 아니다.

1. 보정과 실제 경기장 치수는 별도로 확인한다. 보정이 없거나 `validated`가 false인 경우 사용자 확인을 해도 위치·코칭은 나오지 않는다.
2. 로컬 분석이 실행 중일 때 `GET /api/v1/manual-snapshot`을 호출한다. 응답은 같은 분석 프레임의 `image_jpeg_base64`, `captured_at`, `snapshot_token`과 `players`를 담는다. 각 사람의 `bbox_image_norm`은 이미지 왼쪽 위 기준 정규화된 `[x1,y1,x2,y2]`, `id`, `annotation_token`을 담는다. 지정은 이 이미지와 박스를 함께 표시하고 확인한 후에만 해야 한다. 별도 `/frame.jpg`와 `/analysis`는 서로 다른 프레임일 수 있으므로 둘을 섞어 확인하지 않는다.
3. `POST /api/v1/manual-track`으로 같은 스냅샷의 `snapshot_token`, 선택한 사람의 `id`, `annotation_token`을 `token`으로 보내고, 실제 확인된 `role: "player"` 및 `team: "home"` 또는 `"away"`를 지정한다. 예: `{"snapshot_token":"...","id":"...","token":"...","role":"player","team":"home"}`. 심판·골키퍼·unknown은 role을 각각 `referee`, `goalkeeper`, `unknown`, team을 `unknown`으로 보낸다. `home`과 우리 팀의 관계는 기존 `own_team` 설정으로 정한다.
4. 해당 확인은 최대 10초이고, 추적 ID가 한 프레임이라도 사라지거나 중복되면 즉시 취소된다. 영상 입력 재시작·전환에도 초기화된다. 이전·변조·만료 스냅샷/토큰, 새 분석이 1초 이상 없는 상태, 이미 사라진 트랙을 사용하면 409다. 오래된 프레임의 팀·지표·피드백은 응답에서 보류한다. 불일치·재출현 뒤에는 다시 확인한다.

추적기가 사람을 다른 사람으로 바꾸면서도 같은 ID를 유지하는 경우나, 관찰자가 잘못 지정한 경우를 자동으로 확실하게 감지할 수 없다. 선수 가림, 영상 지연, 화면 밖 인원과 카메라·보정 오류가 남는다. 확인된 소수 선수의 화면 내 간격이며 팀 전체의 형태나 전술 성공·실패 판정이 아니다. 대시보드의 선수 확인 화면은 같은 분석 프레임과 박스를 표시하고 사람별 확인을 받는다. 선택적인 색상 그룹은 미확인 힌트이며 팀이나 역할을 자동 확정하지 않는다.

이 API는 기본 로컬 서버에서만 사용하도록 설계했다. 공개 평문 데모 게이트웨이의 경로 허용 목록에 추가하지 않았다. 별도 TLS·Bearer 프록시를 운영자가 이미 안전하게 준비한 경우, 프록시 프로세스에 `FOOTBALL_PROXY_ALLOW_MANUAL=1`을 명시하면 수동 스냅샷 GET과 수동 확인 POST만 추가 중계한다. 기본값은 꺼짐이다. 기존 소스 IP 제한·TLS 인증서·32자 이상 토큰·정확한 CORS origin 설정이 여전히 필요하다. 토큰은 읽기뿐 아니라 수동 선수 지정을 허용하므로 신뢰할 수 있는 사람에게만 전달하고, URL·코드·로그·채팅에 넣지 않는다. CORS는 인증이 아니다. 프록시 설정을 추가한다고 기존 공개 데모가 자동으로 보호되지는 않는다.

프록시의 `FOOTBALL_PROXY_SERVE_DASHBOARD=1`은 같은 HTTPS 출처에 한정된 정적 웹 자산을 제공한다(기본 꺼짐). 영상·분석·확인 API와 `/api/v1/proxy-capabilities`는 여전히 Bearer 토큰과 소스 IP 제한이 적용된다. 정적 자산은 비밀이 없는 UI 코드만 제공하며 업로드·실시간 입력 전환·장면 저장 제어는 프록시에서 허용하지 않는다. 브라우저가 POST에 전송하는 Origin이 일치하도록 `FOOTBALL_PROXY_ALLOWED_ORIGIN`에 실제 대시보드의 정확한 `https://호스트:포트`를 설정해야 한다. 신뢰할 수 있는 인증서, 사설망, 실제 맥북 접속 및 인증 테스트는 별도로 필요하며 이 코드는 기존 운영 프로세스나 방화벽을 바꾸지 않는다.
