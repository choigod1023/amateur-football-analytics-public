# 사람 답 반영 재학습 및 다른 경기 비교 — 2026-11-14

새 답을 반영해 재연결 모델을 학습했지만 다른 경기의 오연결이 늘었다. 후보는 운영에 적용하지 않았다. ID 변경 수만 낮아졌다고 정확도가 좋아졌다고 판단하지 않는다.

## 반영한 답과 고정 비교

요청한 d0113·d0114·d0115는 모두 same으로 저장됐다. 같은 시점에 d0111·d0112도 same으로 저장되어 평가 결과를 보기 전에 주 모델을 기존 4쌍 + 신규 5쌍, 총 9쌍으로 정했다. 같은 사람 8쌍, 다른 사람 1쌍이다. 세 답만 추가한 7쌍 모델은 학습 진단용으로 별도 보관하고 평가 성능을 보고 모델을 골라 바꾸지 않았다.

사람 답의 출처·장면 fingerprint·원본 프레임 해시를 검증했다. 학습 source 두 파일의 SHA256을 모델에 기록하고 평가 원본과 중복되지 않는지 검사했다. 원본 JSON 1,204개는 변경하지 않았다. 상세는 [학습 기록](IDENTITY_TRAINING_1114.md)을 참고한다.

기존/새 모델을 동일 TemporalLinker, 동일 탐지·추적 상자, 동일 0.4초 확인 지연으로 비교했다. 승인 점수 0.9, 후보 차이 0.15, 운동 잔차 제한 1.5는 바꾸지 않았다. 평가 정답은 채점에만 썼다.

## 학습하지 않은 경기의 결과

AI Hub 경기 305·306에서 각각 0–30초, 300–330초, 600–630초를 5fps로 분석했다. 총 180초/900프레임이다.

| 지표 | 기존 | 재학습 |
|---|---:|---:|
| ID 변경 | 3,263 | 3,252 |
| 승인한 재연결 | 15 | 40 |
| 앞뒤 경계 감사: 정연결 | 5 | 6 |
| 앞뒤 경계 감사: 오연결 | 2 | 14 |
| 앞뒤 경계 감사: 미확정 | 8 | 20 |
| 정답과 매칭된 관측 | 5,878 | 5,878 |

ID 변경은 11회(약 0.34%) 감소했으나 오연결은 12회 늘었다. 더 많은 연결을 승인하며 서로 다른 선수를 합친 문제가 커졌다. 단일 연결 시점만 보는 기존 집계는 오연결 2→15이며, 위 표는 직전 관측과 확인 프레임을 함께 검토하는 별도의 경계 감사 기준이다. 두 기준을 섞지 않는다.

ID 변경은 기존 IoU 기반 진단 지표이며 공식 HOTA/IDF1이 아니다. 미매칭 탐지를 모두 오탐으로 계산하지 않는다. 이 경기들은 학습에 넣지 않았지만 이전 실험에서 이미 확인했으므로 완전히 새로운 최종 시험 세트는 아니다. [평가 기록](IDENTITY_EVALUATION_1114.md) 및 `work/identity-retraining-20261114/evaluation-summary.json`에 상세 결과가 있다.

## 실제 촬영 영상에서 답이 반영되는 범위

원래 녹화의 원시 추적 300프레임과 실제 프레임을 다시 읽어 두 TemporalLinker를 실행했다. 운영의 팀/위치 필터와 IdentityGuard를 제외한 재연결 단계 시험이며, 학습 자료에 대한 동작 확인이다.

- d0111: 이전/재학습 모두 지정 경계 359→845를 연결했다.
- d0112·d0113: 재학습 후에도 연결하지 못했다. 실제 최근 1.01초의 앞쪽 관측이 2개뿐이어서 필요한 최소 3개 관측을 충족하지 못한다.
- d0114: 이전에는 미연결이었지만 재학습 후 29→431을 연결했다. 출생 시각 20.0초, 승인 20.4초, 점수 0.941이다.
- d0115: 학습 점수는 0.674→0.904로 올랐으나 운동 잔차 1.590이 제한 1.5를 넘어 미연결로 남았다.

`own-runtime.json`에 실제 승인 이벤트를 남겼다. 오프라인 학습의 앞 5장과 실시간 1.01초 창이 일치하지 않는 사례가 있으므로 학습 점수 상승만으로 실시간 복구를 보장할 수 없다. 이를 숨기거나 프레임을 임의로 추가하지 않았다.

## 판단과 다음 개선

새 답이 잘못됐다는 근거는 없다. 현재 학습 집합은 같은 사람 8쌍/다른 사람 1쌍으로 작고 편중돼 있다. 기존 다른 사람 예시의 연결 점수도 0.190→0.504로 상승했다. 이는 같은 사람을 승인하는 경향이 커졌다는 진단과 일치하지만, 모든 오연결의 원인을 클래스 비율 하나로 확정한 것은 아니다.

다음 변경은 학습 시퀀스를 실제 시간 창에 맞추고, 학습 전용 자료에서 비슷한 유니폼의 서로 다른 선수 쌍을 확보하는 것이다. 평가 영상의 오연결 정답을 그대로 학습에 넣고 같은 영상에서 개선됐다고 보고하지 않는다. 관측이 부족한 장면은 탐지/추적의 연속성 문제를 따로 해결해야 한다. 승인 기준이나 위치 제한을 느슨하게 풀어 숫자만 늘리지 않는다.

## 코드와 운영

새 스크립트는 학습 자료 준비, 동일 조건 평가, 실제 녹화의 연결 가능성 감사를 재현한다. 모델 파일·프레임·원본 데이터는 Git에 넣지 않는다. 운영 서버·분석 모델·기존 질문 페이지는 변경하거나 재시작하지 않았다.

전체 테스트는 **623 passed, 1 skipped**(43.32초), 기존 FastAPI/Starlette 사용 중단 예정 경고 3개였다. 학습 준비 스크립트를 다시 실행해 모델 weights/bias/mean/scale과 정책 값이 정확히 재현됨을 확인했다. 모든 기존 JSON 1,204개의 전후 해시는 동일했다. 테스트 통과와 실제 영상의 정확도 향상은 별개의 검증이다.
