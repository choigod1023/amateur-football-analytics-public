# 미니맵 표시 연속성 재검증

앞서 제공한 합성 영상은 관측 좌표를 직접 그려 브라우저 MinimapMotion의 0.4초 유지조차 적용하지 않았다. 따라서 실제 대시보드 수정의 증거로 적합하지 않았다. 이번 영상은 실제 web/minimap-motion.js 전후 버전의 출력 좌표를 렌더링한다. 웹 캡처는 아니다.

## 수정
- 3회 연속 같은 팀·ID로 짧게 이동한 관측만 마지막 위치를 최대 0.8초 유지한다. 그 외는 기존 0.4초다. 마지막 위치는 빈 원이며 현재 위치나 예측 위치가 아니다.
- 새 탐지가 가까우면 유지하지 않는다. 기존 팀당 11명 제한, 세션 변경/보정 무효/긴 시간 간격의 초기화 유지. 관측 자체가 이미 11명 초과라면 그것을 임의로 숨기지 않는다.
- 프리뷰의 source_time_s를 보간 시계에 사용한다. 같은 영상 프레임의 반복 API 응답을 새 관측으로 취급하지 않는다.
- UI의 최대 유지 시간 안내를 수정했다. 기존 화면과 색은 유지하며 unslop(Damir Sokolovsky, @heydamir, CC BY 4.0)의 상태 구분 원칙을 참고했다.

## 고정 입력 비교
두 추론 결과는 같은 60초 녹화 구간의 각 300프레임이며 독립적인 두 경기 표본이 아니다. 기존 guard를 통과한 위치를 동일하게 전후 브라우저 로직에 입력했다. 영상 시간으로 200ms씩 진행해 각 시점에 표시된 ID 집합에서 사라지는 수를 집계했다. 사용자 분류 답과 모델 가중치는 수정하지 않았다.

|입력|표시 사라짐 전→후|마지막 위치 샘플 전→후|팀 과다 프레임 전→후|
|---|---:|---:|---:|
|baseline|197→185|139→207|155→155|
|candidate|160→136|203→316|26→26|

candidate 표시 사라짐은 15% 줄었지만 마지막 위치를 오래 보여준 효과다. 실제 미탐·ID 변경·오연결·위치 정확도가 개선됐다는 뜻이 아니다. 추가 표시가 실제 현재 선수와 일치하는지도 정답 자료로 확인하지 못했다. 0.8초가 지나면 사라지며 장기 손실은 해결되지 않는다. 공·전술 계산에는 이 표시 위치를 넣지 않는다.
