# 유니폼 색상 쌍 비교 실험

경기마다 두 팀의 색상과 좌우 라벨이 바뀌므로, 서로 다른 경기의 색상 히스토그램 쌍을 이용해 같은 팀인지 학습한다. 새 경기에서는 사람이 팀을 확인한 상의 표본을 `home`, `away`에 각각 3~100개 지정해야 한다. 이 기능은 기본 분석 API와 연결하지 않은 연구용 오프라인 도구다. 현재 탐지기는 심판과 골키퍼를 일반 사람과 분리하지 못하므로, 검증되지 않은 역할을 선수로 강제하면 잘못된 팀과 코칭을 만들 수 있다. `role`이 명시적으로 `player`인 경우에만 분류한다.

계정 없이 접근 가능한 [SoccerNet GSR 2024](https://huggingface.co/datasets/SoccerNet/SN-GSR-2024)의 train.zip에서 서로 다른 경기 3개의 프레임과 정답 박스를 일부 추출했다. 경기 4로 쌍 비교 모델을 학습했고, 경기 6으로 출력 거절 문턱을 골랐다. 경기 9는 가중치 학습과 문턱 선택에서 제외했다. 경기 9 초반의 팀별 정답 표본 8개씩을 사용해 동일 경기의 최소 2초 이후 43프레임에 있는 정답 선수 박스 624개를 분류했다. 결과는 일치 575, 오분류 10, unknown 39였다. 같은 표본을 쓴 기존 median은 일치 84·오분류 11·unknown 529, guarded는 6·0·618이었다.

프레임이 서로 상관되고 경기 9의 표본 선수 일부가 평가에서도 반복된다. 위는 탐지기가 아닌 정답 박스를 이용한 선수 분류이며 골키퍼·심판과 오탐, 야간 영상, 이동 카메라, 스트림은 평가하지 않았다. 단일 평가 경기에서 신뢰도나 일반화를 보장할 수 없다. 표본 팀 대응도 수동 확인이 필요하다. 기준 선수나 조건이 바뀌면 새로 평가해야 한다. [SoccerNet 공식 FAQ](https://www.soccer-net.org/faq)에 따라 데이터는 비상업 연구용이다. 해당 자료로 학습한 실험 가중치는 프로젝트에 포함하거나 운영에 배포하지 않는다.

실험 데이터·재현 스크립트·JSON 가중치는 독립 실험 위치 `work/gsr-team`에 두었다. 가중치와 입력 경로를 명시해 `python scripts/experimental_team_pairs.py --weights WEIGHTS.json --inputs INPUT.json`으로 실행한다. 입력 JSON은 `support.home`, `support.away` 배열에 `image`, `box`(x1,y1,x2,y2)를 담고, `targets` 배열에 같은 필드와 확인된 `role: "player"`를 담는다. 입력 `home`을 우리 팀으로 지정하는 것은 호출자의 책임이며, 심판·골키퍼나 역할 미확인은 `unknown`이다. 출력은 실험 표시와 팀 후보이며 미니맵 좌표 또는 전술 결론이 아니다.
