# 코칭 대상과 미니맵 표시 검증

## 변경
- 코칭의 기존 관찰·해석·제안·한계 필드를 유지하고 directive를 추가했다. 대상 그룹, 대상 선정 근거, 행동, 관측 근거, 적용 조건을 제공한다. 기존 제안 문구에도 모두 포함된다.
- 실제 신원과 포지션이 검증되지 않아 특정 선수 ID를 임의로 지목하지 않는다. track_ids는 빈 배열, individual_assignment_verified는 false다.
- 예: 팀 종방향 간격이 5초간 반복해서 32m를 넘으면 중원·수비 그룹을 대상으로 지원 거리를 조정하되, 어느 라인을 움직일지는 공 위치와 압박을 확인하도록 제안한다. 후퇴 근거가 없으면 코치 확인만 요청한다.
- 미니맵에서 한 명의 좌표가 null이면 모든 선수의 표시 유지가 꺼지던 로직을 해당 ID에만 적용했다.
- 탐지가 한 프레임 비어도 보정이 유효하면 기존 마지막 관측 위치를 최대 0.4초 표시한다. 빈 점선 원이며 현재 관측이나 코칭 입력에 추가하지 않는다. 반복 수신으로 만료 시간을 연장하지 않는다.
- 일반 라이브의 유효한 경기장 보정 상태에서는 분석 요청 간격을 2.5초에서 0.2초로 줄였다. 서버 자체의 추론 속도를 높인 것은 아니다. 세션 변경, 시간 역행, 0.6초 초과 관측 간격, 보정 무효에서는 연결 표시를 유지하지 않는다.
- 관측 수와 마지막 위치 수를 구분한다. 기존 색·배치·디자인은 유지했다. UI 검토에 unslop(Damir Sokolovsky, @heydamir, CC BY 4.0)의 상태 구분·가독성 원칙을 참고했다.

## 녹화 관측값 비교
기존 minimap 검증의 clean_baseline / clean_candidate observations.jsonl 각 300프레임, 60초를 PositionGuard·DisplayPositionGuard·LiveAnalyzer에 재입력하고 브라우저 MinimapMotion 전후에 동일한 위치를 전달했다. 원본 관측·분류 답은 변경하지 않았다.

|입력|표시 ID 사라짐 전→후|마지막 관측 표시 샘플 전→후|팀 11명 초과 프레임 전→후|
|---|---:|---:|---:|
|baseline|197→197|139→139|155→155|
|candidate|160→160|203→203|26→26|

이번 600프레임에서는 새로 고친 전체 빈 프레임·개별 null 분기가 발생하지 않아 수치 개선을 확인하지 못했다. 표시 ID 사라짐은 오연결/ID 변경 정답 지표가 아니다. 초과 인원은 현재 관측 입력 자체를 숨기지 않기 때문에 남는다. 표시 유지 때문에 새로 늘어난 것은 아니다. 0.4초 이상 미탐과 새 ID 부여는 이번 수정으로 복구되지 않는다.

## 검증과 한계
Python 전체 테스트와 Node 미니맵 경계조건·대시보드 DOM 모의 실행을 확인했다. 실제 외부 브라우저·아이폰 라이브 부하 및 화면 육안 검증은 아직 진행하지 않았다. 관련 로컬 결과: work/coaching-target-continuity-20261115/comparison.json.

코칭 대상은 조건부 역할 그룹이다. 개별 선수 지시를 하려면 팀·역할·동일인과 공 상황이 검증되어야 한다. 전술 정답이나 실제 위치 오차 개선을 이번 결과로 주장하지 않는다. 운영 서버는 재시작하지 않았으며 배포 전 별도 확인이 필요하다.
