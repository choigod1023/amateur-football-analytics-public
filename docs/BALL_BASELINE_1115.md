# 공 후보 선택·경로 연결 실제 재검증 — 2026-11-15

공이 없는 장면의 오탐까지 포함하면, 이번 저장 영상 경로 추론의 정밀도는 **64.5%, 재현율은 32.3%**였다. 신뢰할 수 있는 실시간 공 추적이 완성됐다는 결과가 아니다. 공 후보가 있었던 정답 프레임은 93.5%여서, 이 표본에서는 후보를 고르고 연결하는 단계의 손실이 더 컸다.

## 재현과 범위

프로젝트 루트의 `work/human-labels/public-own-match-review-20261111/ball`에 저장된 사용자 녹화 장면 b37~b39의 JPG 150장을 실제 CPU 추론했다. 기존 `work/ball-rerank-v2/model.pt`, `work/ball-people-20261112` 사람 상자, 저장된 공 후보를 사용했다. 모델·임계값·사용자 답을 변경하지 않았다. 사람 정답은 추론 후 평가 및 명시적인 후보 oracle 상한 계산에만 사용했다.

5fps, 3개 10초 클립 중 `ball/verified=ok` 62개, `none` 74개를 평가했다. `rejected` 14개는 공 없음으로 바꾸지 않고 제외했다. b37과 b38은 같은 경기의 가까운 시각이므로 독립 경기 표본이 아니다. 기존 모델에 학습 클립 명세가 없어 이번 영상의 학습 미사용 여부를 증명할 수 없다. 따라서 일반화 성능·독립 최종시험으로 부르지 않는다.

실행 명령(저장소 루트에서, Python 환경 경로는 설치 환경에 맞춰 지정):

```powershell
python scripts/audit_ball_baseline.py <프로젝트루트> <프로젝트루트>/work/oracle-isolation-20261115/ball
python -m pytest tests/test_ball_baseline.py -q
```

고정 판정 반경은 원본 이미지 좌표 12px, 모델 선택 임계값은 기존 0.7이다. 정확한 공 궤적의 미터 오차, 속도 오차, 이벤트 정답은 이 시험에 없다. 사용자가 후보 중심을 눌렀으므로 중심 오차 중앙값 0도 나타나며, 실제 공 중심을 픽셀 단위로 완벽하게 찾았다는 의미가 아니다.

## 동일 장면 단계별 결과

| 단계 | 정위치 | 공 있는 장면 오위치 | 미응답 | 공 없는 장면 오탐 | 전체 정밀도 | 재현율 |
|---|---:|---:|---:|---:|---:|---:|
| 기존 후보 점수 1위, 기권 없음 | 18 | 44 | 0 | 74 | 13.2% | 29.0% |
| 현재 재순위 모델 1위, 0.7 이상 | 30 | 13 | 19 | 37 | 37.5% | 48.4% |
| 현재 경로 연결 + 머리 후보 제거 | 20 | 1 | 41 | 10 | 64.5% | 32.3% |
| 경로 연결, 머리 후보 제거 해제 | 20 | 1 | 41 | 14 | 57.1% | 32.3% |
| 정답으로 후보를 고른 상한(실제 모델 아님) | 58 | 0 | 4 | 0 | 해당 없음 | 93.5% |

정밀도 = 정위치/(정위치+오위치+공 없는 장면 오탐), 재현율 = 정위치/62다. 단일 공 후보 선택 기준의 프레임 측정이며 일반 물체 검출 AP와 다르다. 후보 oracle은 정답을 이용하므로 모델 개선 성과에 포함하면 안 된다.

머리 제거를 없애는 단순 변경은 이번 표본에서 빈 장면 오탐 10→14로 악화했다. 운영에 적용할 이유가 없다. 현재 경로 연결은 프레임별 재순위보다 오위치 13→1, 빈 장면 오탐 37→10으로 줄였지만, 정답 30→20도 잃었다. 손실은 짧은 경로를 제외하는 규칙, 확률 임계값 및 이동 거리 비용에 영향을 받는다. 각 규칙의 인과적 기여는 추가 분리 시험이 필요하다.

CPU 재순위·연결 시간은 2.597초였다. 영상 디코딩/공 후보 생성/사람 탐지/전송은 빠져 있으므로 이것을 실시간 처리 FPS라고 보고하지 않는다. 재순위 특징은 앞뒤 후보를 이용하고 경로 연결은 클립 전체를 보기 때문에 동일 동작을 실시간으로 구현하려면 명시적인 버퍼 지연 계약이 필요하다.

## 확인한 측정 코드 결함 수정

기존 학습 보고서의 `precision`은 공이 있는 장면만 분모에 넣었다. 과거 threshold=0.7 결과는 정위치249, 오위치20, 공 없음 오탐140으로, 표시된 92.6%는 조건부 정밀도였다. 전체 응답 정밀도는 **249/(249+20+140)=60.9%**다. 이 정정은 과거 수치에 대한 것이며, 이번 64.5%와 전후 모델 개선으로 비교할 수 없다.

`train_ball_rerank.py`의 기존 `precision` 필드는 호환을 위해 유지하면서 정의를 명시하고 `conditional_precision_ball_present`, `overall_precision`을 추가했다. `apply_ball_rerank.py`의 93% 표현도 바로잡았다. 과거 metrics.json과 모델 파일은 수정하지 않았다. 분모, 검수 거절·불명확 라벨 제외, 무응답 사례의 회귀 테스트 3개가 통과했다.

## 운영과 다음 단계

현재 운영의 `run_live_feedback.py` 선수 분석 루프는 이 저장 영상 공 경로를 자동으로 실행하지 않는다. 별도의 FastAPI 공 후보 기능 및 보고서 재순위 설정이 존재하는 것과 라이브 전술 피드백에 공이 통합된 것은 구분해야 한다. 이번 시험으로 공 점유·패스·슛 코칭을 활성화하지 않았다.

우선순위는 모델을 무작정 오래 학습하는 것이 아니라, (1) 학습에 쓰지 않을 다른 경기의 공 존재/부재 및 정확한 중심 정답을 고정하고, (2) 현재 빈 장면 오탐과 재순위에서 놓치는 후보를 별도 학습 자료로 분리하고, (3) 같은 시험에서 짧고 빠른 경로 복구가 오탐을 늘리는지 측정하는 것이다. 후보 자체가 없는 4프레임도 확대 영상으로 확인할 필요가 있다. 사람에게 같은 후보 중심만 다시 고르게 하지 말고, 후보 밖 공 중심 추가와 `공 없음/판독 불가`를 분리해야 한다.

자료는 이미 보관된 사용자 녹화 및 사용자 분류 답이며 외부 자료를 새로 다운로드하지 않았다. 이 메모는 공개 배포권·촬영 당사자 동의를 추가로 부여하지 않는다. 외부 탐지 모델의 기존 라이선스·출처 제한은 그대로 유지되며, 과거 외부 9장 검출 시험의 한계는 `docs/ball-research.md`에 별도 기록돼 있다.

재실행 출력은 프로젝트 루트 `work/oracle-isolation-20261115/ball/metrics.json`, `predictions.json`이다. 모델 및 평가 답의 SHA-256을 metrics에 기록했다. 사용자의 답은 읽기만 했으며 운영 재시작·배포·재학습은 하지 않았다.
