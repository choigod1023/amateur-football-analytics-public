# 실시간 전술 피드백 가이드

경기 영상을 실시간으로 받아 몇 초 안에 짧은 전술 알림을 내보내는 기능의 구조, 현재 성능, 앞으로 개선할 순서, 그리고 사용자님이 분류해 주셔야 할 자료를 정리한 문서입니다.

## 1. 지금 만들어진 것

```
영상(파일, 카메라, 스트림)
  → 사람 찾기(타일 검출) → 추적(ByteTrack) → 팀 구분(팀 역할 모델)
  → 경기장 좌표(보정) → LiveAnalyzer → 알림(화면 띠, 터미널, alerts.jsonl)
```

| 파일 | 역할 |
| --- | --- |
| `app/live_feedback.py` | 최근 24초만 기억하고 1초마다 규칙을 확인해 알림을 만드는 엔진 |
| `scripts/run_live_feedback.py` | 영상이나 스트림을 읽어 엔진에 넣고 알림을 출력하는 실행 스크립트 |
| `scripts/replay_live_feedback.py` | 저장된 추적 결과를 실시간처럼 재생해 규칙을 평가하는 스크립트 |
| `tests/test_live_feedback.py` | 엔진의 기본 동작 시험 |

알림 종류는 다음과 같습니다.

- 박스 침투 공격: 우리 선수 3명 이상이 상대 페널티 지역에 2초 이상 머뭅니다.
- 수비 라인 뒤 침투: 우리 선수가 상대 수비 라인을 넘어 달렸습니다.
- 상대 침투 허용: 상대가 우리 수비 라인 뒤로 달렸습니다.
- 고립된 공격수: 가장 앞선 선수가 6초 이상 동료와 12미터 넘게 떨어져 있습니다.
- 수비 라인 하락: 우리 수비 라인이 10초 안에 14미터 이상 내려갔습니다.
- 라인 간격 벌어짐: 공격 라인과 수비 라인 간격이 5초 넘게 32미터를 넘습니다.

알림이 한꺼번에 쏟아지지 않도록 종류마다 대기 시간(20~90초)이 있고, 한 번에 하나만 보냅니다. 박스 침투와 상대 침투 허용은 급한 알림이라 간격 제한을 받지 않습니다.

### 실행 예시

```bash
python scripts/run_live_feedback.py <영상 또는 스트림 주소> <calibrations.json> cam1 --direction -1 --team B \
  --detector yolo11n.pt --classifier <팀 역할 모델>.pt --reference-bg 1.000657 0.000035 -0.67 -0.47 \
  --pitch-length 89 --pitch-width 62 --video-out preview.mp4 --alerts alerts.jsonl
```

- `--direction`: 우리 팀이 화면 오른쪽으로 공격하면 1, 왼쪽이면 -1입니다. 전반과 후반에 바뀝니다.
- `--realtime`: 파일을 실제 속도로 재생하며 시험할 때 씁니다.
- 스트림(RTSP 등)은 주소를 그대로 넣으면 되고, 이때 시각은 실행한 시각 기준입니다.

## 2. 지금 성능 (측정한 것만)

- 속도: 5장/초로 분석했을 때 30초 분량을 36초에 처리했습니다(모델 로딩 포함, 리뷰 영상 제작과 동시에 실행). 거의 실시간이지만, 여유가 없어서 최적화가 필요합니다.
- 인식: 화면 한 장에서 우리 팀 평균 6~7명, 상대 평균 8~9명이 경기장 좌표에 올라왔습니다. 11명이 모두 잡히지 않아 팀 구조 수치는 실제보다 좁거나 어긋날 수 있습니다.
- 알림 양: 저장된 전반과 후반을 재생했을 때 분당 약 2.2회였습니다. 코치가 읽기에는 아직 많은 편입니다.
- 득점 경고: 확인된 득점 장면 중 절반 이상에서 득점 전 20초 안에 박스 침투나 침투 알림이 있었습니다. 나머지는 알림이 없었습니다.
- 알림이 맞았는지(정밀도)는 아직 측정하지 못했습니다. 정답 자료가 없기 때문입니다. 아래 3번이 이 부분입니다.

## 3. 사용자님이 분류해 주셔야 할 것

우선순위가 높은 순서입니다.

1. **빠진 선수 그리기** (`/train`의 장면 100~123, 계속): 인식되는 인원이 가장 큰 병목입니다. 특히 멀리 있는 선수, 박스 안에 몰린 선수, 후반 카메라 오른쪽 구석을 우선해 주세요.
2. **알림 판정 자료**: `alerts.jsonl`의 알림 50~100개를 보고 "맞음 / 틀림 / 맞지만 쓸모없음"으로 표시해 주세요. 이것이 알림 정밀도를 재는 유일한 정답입니다. 판정 화면은 아직 없고, 다음 단계에서 `/report` 대시보드에 붙이는 것이 좋습니다.
3. **경기 사건의 시각**: 득점 장면, 슛(득점 아님), 코너킥과 프리킥 시작 시각, 상대 침투를 허용한 장면, 공을 빼앗긴 직후 역습 장면. 초 단위가 아니라 5초 정도 오차는 괜찮습니다.
4. **팀과 역할 라벨**: 심판, 골키퍼, 관중, 교체 선수. 팀 구분 모델이 관중과 심판을 선수로 잘못 센 사례를 줄입니다.
5. **공 위치**: 골 장면 클립 b37~b54의 공. 공을 쓰면 패스, 점유, 슛 알림을 만들 수 있습니다.
6. **새 경기장이나 새 카메라마다**: 경기장 모서리와 선 위 점을 클릭하는 보정, 경기장 실제 크기, 우리 팀 옷 색, 공격 방향.

## 4. 개선 순서 (제안)

| 단계 | 내용 | 이유 |
| --- | --- | --- |
| 1 | 사람 찾기 성능 높이기: 라벨이 더 쌓이면 타일 검출기를 다시 학습하고, 가려진 선수는 앞뒤 위치로 보정 | 모든 알림이 인원 수에 의존합니다 |
| 2 | 알림 정밀도 측정과 규칙 조정: 사용자님 판정으로 임계값(3명, 12미터, 14미터 등)을 경기에 맞게 정하기 | 지금 임계값은 한 경기 경험에서 정한 것입니다 |
| 3 | 속도: 검출을 GPU 한 장에 묶어 처리, 타일 수 줄이기, 분석 속도를 상황에 맞게 조절 | 지금은 거의 실시간 수준입니다 |
| 4 | 카메라 흔들림 보정을 프레임마다 적용하고, 전후반 공격 방향과 팀 옷 색을 시작할 때 자동 확인 | 지금은 사람이 값을 입력합니다 |
| 5 | 공 찾기를 실시간에 붙이기(후보 검출 + 재순위 모델) | 패스, 점유, 슛 알림에 필요합니다 |
| 6 | 알림 전달: 대시보드 실시간 화면, 코치 태블릿 알림, 경기 후 알림 모음 자동 보고서 | 현장에서 쓰이려면 필요합니다 |
| 7 | 스트림 안정성: 끊김 재연결, 프레임 지연 감시, 전원 문제에 대비한 기록 저장 | 한 경기 내내 돌려야 합니다 |

## 5. 알려진 한계

- 공을 쓰지 않으므로 패스, 점유, 슛 알림은 없습니다.
- 한 카메라에서 팀당 평균 6~9명만 올라와 수치가 경향 수준입니다.
- 카메라를 움직이거나 줌을 바꾸면 보정이 맞지 않으므로 고정 위치에서 촬영해야 합니다.
- 규칙의 임계값은 한 경기에서 정했고, 다른 경기에서는 검증되지 않았습니다.

## 6. 알림에 붙는 패스길과 공간 한 줄, 그리고 패스길 예측

박스 침투, 고립된 공격수, 수비 라인 뒤 침투 알림(우리 공격에 대한 알림)에는 `detail`이 붙습니다. 수비 쪽 알림(상대 침투 허용, 라인 하락, 라인 간격)에는 붙지 않습니다.

- `detail.line`: "앞선 선수 기준 패스길: 열림 N개, 막힘 M개, 곧 닫힐 수 있는 길 K개 · 공간 한 줄" 형태의 한 줄입니다. 배너의 세 번째 줄로 나옵니다.
- `detail.scene`, `detail.space`: 보고서와 같은 장면과 공간 문장입니다(`app/attack_options.describe`, 과거 8초만 사용하므로 라이브에서 그대로 쓸 수 있습니다).
- `detail.lanes`, `detail.carrier`, `detail.closing`: 사진에 패스길을 그리는 데 쓰는 값입니다. `run_live_feedback.py`는 알림이 나올 때 `<alerts 파일 이름>_<초>.jpg`로 패스길 그림을 저장합니다.
- 공을 가진 선수를 모르므로 패스길의 출발점은 "가장 앞선 선수"입니다(`carrier_source`가 `most advanced`).

### 패스길 예측(`app/lane_forecast.py`)의 측정 결과

저장된 전후반 전체에서, 팀이 상대 진영에 있는 1초 간격 시점마다 가장 앞선 선수에서 팀 동료까지의 패스길을 골라 실제 N초 뒤 상태와 비교했습니다(`scripts/evaluate_lane_prediction.py`, 라벨 불필요).

| 앞서 내다본 시간 | 패스길 수 | 상태를 맞힌 비율: 그대로 유지한다고 가정 | 직선 예측 | 지금 열린 길 중 계속 열린 비율 | 닫힌 길을 예측으로 찾은 비율 | "곧 닫힘" 호출이 틀린 비율 |
| --- | --- | --- | --- | --- | --- | --- |
| 1.0초 | 11,736 | 84.3% | 85.3% | 74.6% | 52.1% | 38.3% |
| 1.5초 | 10,557 | 79.8% | 80.0% | 68.6% | 53.1% | 40.3% |
| 2.0초 | 10,065 | 77.9% | 77.6% | 65.2% | 54.9% | 39.4% |

- 패스길 상태 전체를 맞히는 비율은 "그대로 유지한다"는 가정과 거의 같습니다(1.5초에서 79.8% 대 80.0%).
- 다만 지금 열린 길이 닫히는 경우(31%)의 약 절반을 예측으로 찾아내고, "곧 닫힘"이라는 호출은 약 60%가 맞습니다. 닫힌다는 사실을 아무것도 모르는 기준(31%)보다는 높습니다.
- 그래서 알림에서는 "곧 닫힐 수 있는 길"이라는 **힌트**로만 쓰고, 판정으로 쓰지 않습니다.
- 한 시점의 패스길은 같은 선수를 공유하므로 서로 독립이 아닙니다. 비율의 정확한 오차 범위는 구하지 않았습니다.

## 7. 알림 평가 화면 (`/alerts`)

- 실시간 분석을 서버 저장소에 연결해서 실행하면 알림이 평가 화면에 나옵니다.

```bash
python scripts/run_live_feedback.py <영상 또는 스트림> <calibrations.json> cam1 --direction -1 --team B --detector yolo11n.pt \
  --store <서버 저장소 폴더> --session 11월13일전반
```

- 알림은 `<저장소>/alerts/<세션>/alerts.jsonl`에, 패스길 그림은 같은 폴더의 `alerts_0000.jpg` 같은 이름으로 저장됩니다. 사진 번호는 알림이 파일에 적힌 순서(0부터)와 같습니다.
- 브라우저에서 `/alerts`(리포트 화면의 "알림 평가" 칩)를 열고 알림마다 **맞음 / 틀림 / 맞지만 쓸모없음**을 누릅니다. 같은 버튼을 다시 누르면 평가가 지워지고, 메모를 200자까지 붙일 수 있습니다.
- 위쪽 표에는 알림 종류별로 알림 수, 평가한 수, 맞음, 틀림, 쓸모없음, "도움이 된 비율"(맞음 ÷ 평가한 수)이 나옵니다. 10초마다 새로 불러옵니다.
- 평가는 알림 하나당 파일 하나(`<저장소>/alerts/labels/<세션>-<번호>.json`)로 저장되어 두 사람이 동시에 눌러도 서로 덮어쓰지 않습니다.
- 평가 화면에는 접속 인증이 없는 시제품 상태입니다(장면 평가 `/events`도 같음). 공개 배포 전에는 인증을 추가해야 합니다.
- 이 표시를 임계값 조정에 쓰는 방법: 종류별로 "틀림"과 "쓸모없음"이 많은 알림의 `kind`와 시각을 보고 `app/live_feedback.py`의 기준(3명, 12미터, 14미터, 32미터, 대기 시간)을 바꾼 뒤, `scripts/replay_live_feedback.py`로 알림 수가 어떻게 달라지는지 확인합니다. 아직 이 조정을 자동으로 해 주는 코드는 없습니다.
