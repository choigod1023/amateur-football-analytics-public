# 사람 확인 답을 이용한 재연결 재학습 — 2026-11-14

요청한 d0113·d0114·d0115 세 답은 모두 `same`이었다. 같은 시각에 이전 대기 질문 d0111·d0112도 `same`으로 저장되어, 평가를 보기 전에 기존 네 쌍 + 새 다섯 쌍의 **9쌍 모델**을 주 후보로 정했다. 같은 사람 8쌍/다른 사람 1쌍이다. 요청한 세 답만 추가한 7쌍 모델도 학습 자료 진단용으로 별도 저장했다. 어느 쪽도 운영에 적용하지 않았다.

## 보존과 출처

각 답의 human 출처, 질문 fingerprint, ID, verdict 및 파일 SHA256을 확인했다. 기존 네 쌍의 원시 프레임과 provenance는 그대로 유지했다. 새 세 쌍은 `dropout-review-20261114/audit/candidates.json`, 앞선 두 쌍은 run73 원시 추적 기록에서 질문의 정확한 시간·ID·상자를 대조해 재구성했다. 원래 30fps 녹화의 해당 프레임을 직접 추출했으며 보간 상자나 합성 프레임을 만들지 않았다.

모든 추가 자료의 경기 그룹은 `own-match-20261111`이다. 실제 두 원본 영상의 SHA256을 다시 계산해 `model.json`의 `train_source_sha256`에 저장했다. 동일 경기의 전체 영상과 발췌 파일은 해시가 달라도 같은 그룹이므로, 평가에서는 해시와 경기 그룹을 함께 확인해야 한다. 답 JSON 1,204개 전후 해시를 확인했고 변경은 없었다.

## 고정 학습 조건과 점수

기존 `train_temporal_reconnect.py`를 그대로 사용했다. 기존 14개 특징, 학습률 .05, 1,200회, 정규화 .15, 승인 점수 .90, 후보 차이 .15, 양방향 운동 잔차 1.5높이를 바꾸지 않았다. 별도 영상 평가를 보고 임계값을 조정하지 않았다.

| 질문 | 기존 점수 | 9쌍 재학습 점수 | 남는 제한 |
|---|---:|---:|---|
| d0111 | .9111 | .9421 | 단일 쌍 조건 통과, 실제 경쟁·예약 ID는 별도 검증 |
| d0112 | .3444 | .8863 | 점수·운동 제한 미달, 최근 1.01초 관측 2개 |
| d0113 | .8528 | .9505 | 학습 점수 통과하나 최근 1.01초 관측 2개 |
| d0114 | .8672 | .9413 | 단일 쌍 점수·운동 조건 통과 |

점수는 보정된 동일인 확률이 아니다. 학습 사례 점수 상승을 다른 영상 정확도 향상으로 주장하지 않는다. 유일한 다른 사람 쌍 d0110의 점수는 .1904→.5042로 올라갔지만 .90 승인 기준과 운동 제한에서 여전히 차단된다. 양성 8개/음성 1개의 작은 학습 집합이라는 한계가 크다.

## 학습과 실시간 관측 창의 차이

기존 학습은 앞 최대 5장·뒤 3장을 사용하지만 실시간 연결기는 최근 1.01초 안의 관측만 보관한다. d0112·d0113은 학습용 앞 5장 중 이 시간 안에 2장만 남아 실시간 특징 계산의 최소 3장 조건을 만족하지 못한다. d0113을 점수만으로 복구 성공이라고 부르면 잘못이다. 이 차이를 `runtime_history` 진단과 회귀 테스트에 명시했다. 관측 창을 임의로 늘리거나 동일인 답을 인접한 다른 쌍에 자동 전파하지 않았다.

실제 실시간 연결 여부는 부모 작업의 원영상 실행에서 확인하며, 이 문서의 점수표는 학습 자료 진단이다.
