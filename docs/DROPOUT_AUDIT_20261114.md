# 미니맵 소실 원인 감사 — 2026-11-14

`app/dropout_audit.py`와 `scripts/audit_dropouts.py`는 원시 추적 → 팀/투영 → 위치 필터 → 표시 좌표 단계를 비교한다. 선수가 화면 밖으로 나갔는지, 가려졌는지, 탐지기가 놓쳤는지는 원시 추적 부재만으로 확정하지 않는다. 기존 답이나 운영 설정을 변경하지 않는다.

## 실제 60초 영상 비교

`replay-1950-2010.mp4`의 run73 기록 300프레임과 이번 계측 재생 300프레임을 비교했다. 원시 `source_tracks`는 **300/300프레임 완전히 동일**했다. 두 실행은 팀 투표의 공백 초기화 여부가 다른 버전이므로 아래 감소를 이번 감사 코드의 정확도 개선으로 해석하면 안 된다.

| 직전 표시 ID가 다음 샘플에서 사라진 단계 | run73 | 계측 재생 |
|---|---:|---:|
| 원시 추적 관측 없음 | 182 | 153 |
| 위치 보호 필터 제외 | 84 | 73 |
| 경기장 밖이라 대시보드 좌표 null | 1 | 1 |
| 팀/투영 중 어느 단계인지 기록 부족 | 3 | 0 |
| 명시적인 팀 투표 제외 | 0 | 3 |
| 저신뢰 임시 복구 표시 종료 | 5 | 5 |
| 표시 필터/표시 좌표 제외 | 2 | 2 |
| 합계 | **277** | **237** |

분모는 사람 수가 아닌 **표시 소실 사건**이다. 프레임별 위치 거절 전체는 117→103건이며 위 84→73은 그중 직전까지 보이던 ID가 사라진 사건만 센 것이다. 팀별 위치 후보는 5,358→5,224건으로 줄었다. 덜 표시하면 소실 수도 감소할 수 있으므로 정확도 향상으로 단정하지 않는다.

이번 계측에서 원시 추적이 사라진 153건 중 이전 상자와 IoU≥0.3인 현재 탐지는 38건, 다른 ID의 추적 상자는 32건이었다. 근처 탐지가 없는 경우는 115건이다. 이는 조사 단서이며 해당 선수가 실제로 그 위치에 있다는 정답이나 미탐률이 아니다. 5fps 사이 이동, 가림, 시야 이탈을 분리하려면 영상과 전후 궤적을 확인해야 한다.

코칭의 팀별 11명 초과 차단은 54→23프레임이었다. 이 조건은 코칭을 막으며 미니맵 선수 자체를 삭제하는 규칙이 아니다. `web/app.js`·`web/minimap-motion.js`의 표시 전용 보간·짧은 잔류도 추적 정답으로 취급하지 않았다. 이 보고서의 소실은 서버 출력 기준이며 브라우저 화면의 지각적 깜박임 횟수와 다르다.

## 최소 동일인 질문 후보

현재 source SHA256으로 묶인 기존 검수 질문을 먼저 확인했다. 845→1004, 16→1055의 같은 사람 답과 638→824의 다른 사람 답은 보존하며 다시 묻지 않는다. 역할·팀 답은 동일인 답으로 환산하지 않는다. 이미 대기 중인 같은 source pair도 제외한다.

원본 프레임의 앞 5장·뒤 3장으로 직접 계산했다. 점수는 동일인 확률이 아니며, 4개 학습 쌍으로 만든 기존 모델의 순위 점수다. 이 후보만 따로 계산했으므로 전체 경쟁 후보와의 차이까지 검증한 자동 승인 결과도 아니다. 이 세 질문의 미디어 생성·게시 여부는 별도 배포 보고에서 확인해야 한다. 감사 스크립트 자체는 질문을 서버에 게시하지 않는다.
