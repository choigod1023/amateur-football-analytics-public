# 운영 대시보드 코칭·미니맵 원인 점검

## 점검 대상과 운영 상태

2026-11-13 공개 대시보드 HTTP 응답, 브라우저 화면, 운영 프로세스와 완료된 관측 로그를 확인했다. 당시 입력은 실제 SRT가 아니라 `replay-1950-2010.mp4`의 60초 반복 재생이었다. 분석기와 웹은 당시 운영 중이던 버전을 사용했다. 최신 실험 `motion-speed-1113`은 운영되지 않았다. 따라서 실험용 카메라 보정 결함을 현재 운영 장애의 원인으로 설명하면 안 된다.

## 확인한 원인

- `run-73-observations.jsonl`의 300프레임 중 54프레임에서 한 팀의 위치 후보가 11명을 초과했다. 최대 12명이었다. 기존 runner는 이때 분석기를 매번 새로 만들었다. 32.6초 이후 정상 관측의 최장 연속 구간은 3.4초였다. 고립의 6초, 라인 간격의 5초 연속 조건을 채우기 어렵다.
- 알림은 3초 박스 침투, 25초 수비선 관측 변동의 두 건이었다. 후자는 실제 후퇴를 입증하지 못한 진단이다. 8초 표시 제한과 차단 구간 삭제로 79프레임에서만 알림이 보였고 221프레임은 비었다. 빈 화면은 항상 분석 중단을 뜻하지 않는다.
- UI는 한국어로 온 인원 초과 사유를 알 수 없는 코드로 취급했다. `warnings`도 표시하지 않아 미검증 보정 상태와 알림 없음의 이유가 전달되지 않았다.
- `run-74-observations.jsonl`의 유효 미니맵 점은 사라짐 277회, 이전에 본 같은 ID의 재등장 243회, 고유 ID 54개였다. 같은 ID의 연속 프레임 팀 변경도 11회였다. 미니맵은 관측 목록에서 빠진 ID를 즉시 삭제했다. 큰 좌표 점프(정규화 거리 >0.04)는 없었다. 좌표 단위와 보간 시간 단위 불일치는 발견하지 못했다.
- 공개 페이지 영상은 현재 WebRTC가 아닌 JPEG 폴링이다. 브라우저 코드는 127.0.0.1에서만 WebRTC를 시도하고, 운영 분석기 영상 생산은 약 5fps다. 미니맵의 보간을 개선해도 영상이 연속 동영상으로 바뀌지는 않는다.
- 60초마다 새 분석 프로세스와 세션이 시작되어 ID도 초기화된다. 이것을 선수의 실제 퇴장이나 새로운 선수 등장으로 해석하면 안 된다.

## 이번 수정과 전후 결과

1. 불량 관측에서는 시간 증거를 끊되 알림 재발행 대기 시간은 보존한다. 잘못된 관측을 연결하거나 11명 제한을 풀지 않는다. 보정 실패 때 publisher가 기존 피드백과 지표를 내보내는 경로도 차단했다.
2. API에 차단/관측/알림 상태, 이유 코드, 8초 표시 기간을 추가했다. 기존 필드를 유지하고 UI는 한국어 사유, 경고, 추정 보정 상태를 설명한다.
3. 미니맵 누락은 최대 400ms 동안 마지막 위치를 빈 점선 원으로 표시한다. 현재 위치나 예측 위치가 아니며 코칭 계산에 들어가지 않는다. 세션 전환·보정 실패·전체 관측 소실 시 유지하지 않는다. 근처에 다른 탐지가 있거나 팀별 11명/총 22명 제한에 걸리면 추가하지 않는다. 기존 관측 자체의 인원 초과를 임의로 잘라 숨기지는 않는다.

| 같은 운영 기록 재생 | 기존 | 수정 |
|---|---:|---:|
| run-74 표시 ID 사라짐 | 277 | 199 |
| run-74 같은 ID 재등장 | 243 | 165 |
| 표시 유지 때문에 새로 생긴 팀 11명 초과 프레임 | — | 0 |
| run-73 생성 알림 | 2 | 2 |
| run-73 알림 표시 프레임 | 79/300 | 79/300 |

이 수치는 표시 안정화와 안전장치 검증이다. 실제 선수의 정답 ID 기준 오연결/IDSW, 위치 오차 또는 코칭 정확도 향상을 입증하지 않는다. 남은 잘못된 후보와 분류를 해결해야 코칭의 연속 관측을 복구할 수 있다. 이번 수정이 전체 기능 정상화를 의미하지 않는다.
