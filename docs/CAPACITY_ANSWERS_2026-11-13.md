# 저장된 답 반영: 재학습과 실제 영상 재검증

## 답과 추가 설명

장면 130~133에서 새 답 5개를 확인했다: 430=A팀 선수, 259=A팀 골키퍼, 909=관중, 998/748=B팀 선수. 모두 human_confirmed_detection이며 model_candidate는 상자 출처이지 자동 답이라는 의미가 아니다. 원본 영상 SHA와 시각, 상자 좌표가 운영 기록과 일치한다.

사용자의 추가 답은 큰 상자가 작은 상자를 포함한다는 설명이다. 큰 상자가 작은 상자를 포함한다는 설명으로 보존했다. 두 ID가 같은 사람이라는 확인은 아니므로 합치거나 사용자 역할·팀 답을 변경하지 않았다. 추가 설명은 work/capacity-answers-followup-20261113/geometry-note.json에 있다.

## 직접 확인한 결함과 수정

430은 23.4초 이후 9.2초간 관측되지 않다가 32.6초 다시 등장했다. 그 프레임의 모델 A팀 확률은 0.9877인데 과거 B17:A2 누적 투표 때문에 운영은 B팀으로 표시했다.

실제 영상 시각을 TeamVotes에 전달하고 0.6초 초과 관측 공백 뒤 해당 ID의 표만 초기화한다. 다른 ID는 보존하고 시각 역행 때 전체 초기화한다. 초기화 사유는 team_vote_resets에 기록한다. 3개 새 관측을 요구하는 기준은 유지한다. 실제 430은 연속 관측이 부족해 이 수정으로 B 오분류를 보류하지만 A로 복구하지는 못한다.

## 재학습

기존 735개 학습 답의 대조 모델과 새 5개 답을 더한 740개 답의 후보를 동일 구조·500 epochs·3 seeds로 CPU 학습했다. 기존 136개 홀드아웃을 고정하고 이미지 SHA로 학습 누출을 검사했다.

| 항목 | 운영 모델 | 동일조건 대조 | 새 후보 |
|---|---:|---:|---:|
| 홀드아웃 정답 |125/136|125/136|126/136|
| 새5개 학습 답의 단일크롭 정답 |3/5|4/5|4/5|

후보도 909 관중을 팀 선수로 잘못 분류한다. 새 5개 답은 학습에 사용했으므로 독립 평가가 아니다. 현 모델의 4개 클래스는 심판/관중/A팀/B팀으로 골키퍼를 팀에 합친다. 골키퍼 역할이 개선됐다고 주장할 수 없다. 결과와 가중치는 work/capacity-answers-retrain-20261113에 있다.

## 전체 파이프라인 GPU 재실행

같은 60초 영상을 새 모델과 시간 공백 수정으로 다시 300프레임 분석했다. 기존에 사람이 확인한 재연결 옵션은 유지했고 실험적 상자 교체와 guard-team-votes는 켜지 않았다. 원래 ByteTracker 출력은 300프레임 모두 기존과 일치했다.

| 지표 | 기존 운영 기록 | 후보 |
|---|---:|---:|
| 한 팀11명 초과 프레임 |54|26|
| 같은ID 팀 변경 |11|9|
| 위치 후보 중앙값 |18|17|
| 위치 거부 |117|104|
| 미니맵 표시 사라짐 |277|238|
| 이전ID 재등장 |243|205|
| 코칭·진단 알림 |2|3|

이것은 일관성 지표다. 사람이 사라지면 사라짐·재등장 수도 줄 수 있으므로 추적 정확도 개선과 같지 않다. 골키퍼나 동일인 정답 기반 IDSW·미터 오차 평가가 아니다.

새 사람 답 5개를 실제 시각 출력과 대조하면 기존은 3개 일치/2개 오류, 후보는 2개 일치/1개 오류/2개 보류다. 430은 B 오분류 대신 미분류, 748은 맞던 B 표시도 미분류, 909 관중은 여전히 A팀이다. 259의 팀 A와 998의 팀 B는 유지한다. 사람이 확인한 역할 중 골키퍼는 출력하지 않는다.

후보 알림은 3초 박스 침투, 15초 수비선 후퇴, 30초 박스 침투였다. 이전 25초 수비선 관측 변동보다 강한 15초 후퇴 지시가 생겼지만 실제 영상의 전술 정답으로 검증하지 못했다. 알림 증가를 성공 판정으로 사용하지 않았다. 전체 로그·명령·비교는 work/capacity-answers-live-replay-20261113에 저장했다.

별도 CPU 투표 재생에서는 기존 분류 5,241개를 완전히 재현했다. 기존 모델과 공백 수정만으로 초과는 54→23, 후보 모델과 함께 쓰면 26이었다. CPU 비교는 기존 분류 대상에 한정되며 전체 GPU 실행과 코칭 건수가 다르므로 혼용하지 않는다.

## 운영 판정과 보존

운영 적용은 보류한다. 인원 초과는 줄었지만909 관중 오탐과 748 표시 소실이 남았고 새 코칭의 타당성도 확인되지 않았다. 질문 답과 모델 학습 결과는 저장했으며 운영 모델·서버 프로세스를 교체하지 않았다.

현재 코드 관련 회귀 테스트 42개가 통과했다. 원래 답을 고치거나 단순히 12번째 후보를 삭제하지 않았다. 다음에는 909 같은 관중 오탐을 색상뿐 아니라 인물 형상·주변 경기장 영역으로 판별하는 방식과, 공백 뒤 소속을 보류하는 동안 실제 선수 표시를 잃지 않는 방식을 검증해야 한다. 중복 여부는 상자 포함만으로 판정하지 않는다.

재현 스크립트는 retrain_capacity_answers.py와audit_capacity_answer_replay.py이며, 개인 가중치·영상·답은 Git에 넣지 않는다.
