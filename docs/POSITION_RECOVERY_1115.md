# 미니맵 위치 검사 상태 복구 수정

2026-11-15. 위치 검사에서 거절한 좌표를 다음 관측의 기준으로 쓰거나, 표시를 한 번 생략하면 마지막 정상 위치까지 잊는 두 결함을 수정했다. 새로운 선수 위치를 추정하거나 ID를 재연결한 작업은 아니다.

## 재현한 결함

`PositionGuard`에 같은 선수의 0초 0m, 0.2초 10m, 0.4초 0.1m 관측을 넣었다. 10m는 과속으로 거절하지만 기존 코드는 그 좌표를 `previous`에 저장해 다음 정상 복귀 0.1m도 거절했다. 수정 후에는 마지막 허용 관측 0m와 비교해 0.1m를 출력한다.

`DisplayPositionGuard`는 표시를 거절할 때 해당 ID의 기록을 지웠다. 따라서 0m 뒤 10m는 거절하고 10.1m는 새 관측처럼 허용할 수 있었다. 표시 쪽도 마지막 허용 위치를 제한된 시간 동안 기억하도록 수정했다.

## 변경한 계약

- 마지막 **허용 관측**만 기준으로 유지한다. 거절·빈 프레임·유효하지 않은 좌표는 기준을 갱신하지 않는다.
- 원래 설정인 최대 간격 0.6초, 최대 속도 12m/s는 유지한다. 기록은 0.6초 안에서만 살아 있으며, 그 이후 관측은 새 구간으로 시작한다. 오래된 위치에 영구적으로 붙잡지 않는다.
- 누락된 사람이나 거절한 좌표 대신 과거 위치를 출력하지 않는다. 실제 현재 입력 좌표만 출력한다. 화면 표시의 발점 필터는 기존 방식이며 별도로 표시 속도도 검사한다.
- 같은 시각 중복 입력과 비유한 시각은 새 관측으로 세지 않는다. 시각이 뒤로 돌아가면 새 시간축으로 초기화한다. 같은 팀·ID 중복 출력도 막는다.

기존 테스트는 0m→10m(거절)→10.1m를 0.4초에 즉시 허용하도록 기대했다. 이는 0.4초 동안 10.1m 이동한 것처럼 표시할 수 있는 기존 계약이다. 이 기대를 바꿔 0.4초에는 계속 거절하고, 0.8초처럼 0.6초 기록이 만료된 뒤 새 관측을 허용하도록 검사했다. 테스트를 단순 삭제하지 않고 즉시 재정착 금지와 장기 공백 후 복구를 모두 검증한다.

## 실제 녹화 관측 재생

`work/reviewed-reconnect-live-20261113/run-73-observations.jsonl`의 300개 프레임, 5,358개 원래 투영 좌표를 동일하게 넣었다. 탐지·팀 분류·보정을 다시 추정하지 않은 분리 실험이다. 입력 SHA256은 `2d4bde6e8f1d70231ce6b14058adbda99ab21cb5895a77bf5ef1b4e75db45e2a`다.

미니맵의 짧은 공백을 가로지르는 과속 표시를 없앴지만 표시 관측은 7개 줄었다. 따라서 선수 누락 자체가 줄었다거나 미터 단위 실제 위치 정확도가 좋아졌다고 주장하지 않는다. 표시가 부드러워 보이도록 가상의 위치를 채우지도 않았다. 보정 오류·틀린 ID가 속도 제한 안에 있으면 이 검사만으로 해결할 수 없다.

코칭 재생은 같은 raw 좌표, 카메라 준비 상태, 팀당 11명 제한과 현재 LiveAnalyzer를 사용했다. 전체 운영 상태를 재현한 것은 아니며, 알림이 그대로라는 사실도 그 알림이 전술적으로 맞다는 증거는 아니다.
