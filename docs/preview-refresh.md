# 대시보드 영상 미리보기 갱신

기존 구현은 분석 결과 프레임을 최대 초당 2회 JPEG로 만들고 브라우저가 초당 1회 가져와, 영상 입력과 추론이 더 빨라도 화면은 초당 약 1장만 바뀌었다. 서버 생성 간격을 0.5초에서 0.1초로, 브라우저 요청 간격을 응답 완료 후 1초에서 0.125초로 바꿨다. 네트워크 왕복·브라우저 처리와 분석 속도에 따라 실제 속도는 더 낮다. 연결이 끊기거나 오래된 프레임은 종전처럼 숨긴다. 프레임·분석 결과의 시점은 일치한다고 보장하지 않는다.

이는 최대 약 초당 8장의 정지 이미지 미리보기로, 30fps의 연속 동영상이나 아이폰에서 화면까지의 지연 측정이 아니다. 960×540 이하 JPEG(품질 65)를 보통 초당 여러 장 전송하므로 데이터 사용량이 증가하며, 다수 사용자는 각각 전송량이 발생한다. 부하와 전송 데이터가 문제인 환경에서는 영상 전용 WebRTC 등 별도 경로가 필요하며 인증·암호화·네트워크·브라우저 호환 검증 전에는 공개하지 않는다.

AI Hub 로컬 경기 영상 SRT를 동시에 읽는 별도 서버로 짧게 시험했다. 이전 서버에 약 초당 8회 요청한 6초 동안 서로 다른 JPEG는 12장, 변경 서버에서는 6.1초 동안 45장이었다. 양쪽 분석 FPS 평균은 각각 약 32.6, 31.7이었다. 두 측정은 같은 시점의 통제된 반복 실험이 아니고 실제 브라우저, 맥북, 인터넷 측정도 아니어서 일반 성능을 보장하지 않는다. 이 AI Hub 데이터는 로컬에서만 처리했다. 장당 평균 크기는 변경 후 약 63KB였다.

HTTPS 프록시의 콘텐츠 보안 정책은 미리보기가 사용하는 `blob:` 이미지를 차단하던 문제가 있어 이미지 출처에 한해 이를 허용한다. 스크립트 출처나 API 인증은 변경하지 않는다.
