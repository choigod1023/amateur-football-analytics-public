# 녹화 영상 실시간 재분석과 대시보드 검증

## 실행 범위

사용자가 촬영한 `match_from_17min.mp4`의 1950–2010초를 FFmpeg로 정확히 추출하고 30fps로 맞췄다. 원본 OpenCV FPS는 약44.7로 보고되어 프레임 번호 기반 seek와 시간 비교를 그대로 신뢰할 수 없다. 앞선 원본 직접 seek 실험 결과는 동일 구간 모델 비교로 사용하지 않는다.

추출 영상에 yolo11n, 기존 팀 역할 모델, ByteTrack, cam3 89×60m, 기존 수동 reference-bg/shift를 사용해 새로 추론했다. 캐시 추적 결과를 라이브 추론인 것처럼 재생하지 않는다. 고정 구도 수동 보정 시험이며 자동 카메라 적응 성공을 입증하지 않는다.

메인 `/`의 상태·분석·JPEG API를 로컬 분석 snapshot에 연결했다. snapshot이 3초 이상 오래되면 선수·피드백·영상을 숨긴다. 재생 시험은 status.replay로 구분한다. 이번 재생은 JPEG 약5fps이며 방송용 연속 비디오 스트림은 아니다. SRT 네트워크 시험이나 아이폰 송출 시험을 대신하지 않는다.

## 실측

60초, 300분석 프레임에서 탐지 후보 중앙값36명, 위치 후보 중앙값18명(범위0–24명), 처리시간 중앙값172ms였다. 초기 모델 로딩은 별도다. 관중·중복을 포함할 수 있는 탐지 후보 수는 실제 선수 수가 아니다.

같은 프레임 자료에서 위치 속도 검사 전후를 재계산했다:

| 항목 | 검사 전 | 검사 후 |
|---|---:|---:|
| 연속 관측 속도12m/s 초과 | 117/5117 | 0/4931 |
| 최대 속도 | 75.67m/s | 11.94m/s |
| 평균 위치 후보 | 17.86 | 17.47 |
| 전술 알림 | 4 | 4 |

117개 비정상 위치 관측을 생략했으며 대체 좌표를 만들지 않았다. 임계값에 의해 값이 사라진 것이지 위치 정확도가 실측으로 입증된 것은 아니다. 알림은 박스 공격2, 수비선 변화 진단1, 라인 간격1이었다. 수비선 진단만1초 늦어졌으며 코칭 정답률 개선 근거는 없다.

이후 추가한 인원 검사는 한 팀 후보가11명을 넘으면 코칭 이력을 초기화하고 지표·알림을 보류한다. 위4개는 이 추가 검사 이전 결과다. 초과 후보를 임의로 다른 팀으로 바꾸거나11개만 골라 숨기지 않는다. 검사 전후 초과 프레임은 home37→33, away31→23으로 여전히 남는다.

기존 저장 추적의 1740–2916초도 별도로 재검사했다. 관측 중앙값18명, ID내 관측 공백4212회(중앙값0.6초,p95 6.4초), 속도12m/s초과1632회였다. 겹친 검정/형광 유니폼 선수 사이에서 상자가 이동하는 사례를 실제 영상으로 확인했다. 이는 화면 애니메이션만으로 해결할 수 없다.

## 표시 수정

- 내부 경기장 좌표는 중심 원점의 metre, 대시보드는 좌상단 원점의0–1좌표다. `0.5+x/length`, `0.5+y/width`로 변환하고 바깥 위치는 null로 둔다. 처음 연결 시험에서 이 원점 차이를 발견해 수정하고 모서리/중심 회귀 테스트를 추가했다.
- 같은ID·팀의 짧은 변화만200ms 표시 보간한다. 누락ID는 즉시 제거한다. 큰 이동,600ms넘는 공백,팀·세션 변경은 연결하지 않는다.
- 화면 보간은 원본 위치와 코칭 계산으로 돌아가지 않는다. 미관측 선수를22명 채워 넣지 않는다.

## 운영 및 한계

`FOOTBALL_LIVE_SNAPSHOT_DIR` 또는 서버 설정 `live_snapshot_dir`를 지정한다. `scripts/run_live_feedback.py --publish-dir DIR --observations NEW.jsonl --realtime`으로 연결한다. `work/live-dashboard-validation-20261113/run-replay.py`는 시험 구간을10회만 반복하도록 시작했다. 종료 뒤3초가 지나면 화면은 입력 중단 상태가 된다. 반복 중 매번 모델을 다시 로딩하므로 구간 사이 잠깐의 중단이 있다.

Chrome에서 공인 주소의 메인 화면을 열어 영상, 선수 점, 코칭 문구 표시를 확인했다. 같은PC에서의 접속이므로 셀룰러 도달성 검증은 아니다. 기존 분류 답과 녹화 원본은 수정하지 않았다. 웹 서버 재시작 전 검토 저장소를 백업했다.

FM처럼 일관된22명의 정체성·궤적은 아직 검증되지 않았다. 다음 우선순위는 겹침 장면의 ID혼동, 팀별 초과 인원, 원거리 발 위치 흔들림을 실제 정답으로 줄이는 것이다. 특히 자동 구도 적응과 현재 수동 보정 재생을 혼동해서는 안 된다.

원시 측정과 재현 스크립트는 `work/live-dashboard-validation-20261113/`에 보관한다. Git에는 영상·분류 답·모델을 넣지 않는다.
