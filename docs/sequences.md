# 검토 장면 저장

현재 기능은 사용자가 지정한 MP4 시간 구간을 저장하는 수동 검토 장면이다. 자동으로 골·실수·결정적 순간을 판정하지 않는다. 업로드한 MP4가 현재 입력으로 선택된 경우에만 사용할 수 있으며, 영상 종료 뒤에도 같은 입력이 선택되어 있으면 저장할 수 있다. SRT는 녹화·시간 동기화가 없어 이 기능을 지원하지 않는다.

```http
POST /api/v1/sequences
Content-Type: application/json

{"start_s": 10, "end_s": 20}
```

시작과 끝은 원본 영상의 초이며 구간은 0보다 크고 최대 20초이다. 요청이 성공하면 서버가 임의 식별자를 만든다. `GET /api/v1/sequences`로 목록을 보고 `GET /api/v1/sequences/{id}/video`로 동영상을 재생할 수 있다. 동영상은 H.264 MP4로 재인코딩하고, 너비 1920 이하로 축소하며 오디오는 제거한다. 구간과 시간은 인코딩·원본 시간 정보에 따라 근사치다. 원본 영상에 미니맵이나 자막이 이미 포함돼 있다면 이는 원본의 표시일 뿐 서버 분석 결과가 아니다.

업로드 MP4가 일정 프레임레이트(CFR)임을 사용자가 별도로 확인하고 `verified_constant_frame_rate: true`를 설정한 뒤 그 파일을 분석할 때에만, 최대 초당 한 프레임의 실제 분석 결과·원본 프레임 번호·픽셀 해시를 임시 메모리에 보관한다. CFR 확인 표시는 자동 검증이 아니다. 클립 구간의 분석 프레임을 선택해 원본을 다시 디코딩하고 픽셀 해시가 일치할 때만 실제 분석 프레임 이미지와 해당 결과를 클립에 저장한다. 분석 이미지는 `GET /api/v1/sequences/{id}/snapshot.jpg`로 제공한다. 해당 미니맵은 그 이미지 **한 장의 관측값**이며 동영상과 자동 재생 동기화되거나 전체 구간을 대표하지 않는다. 원본 시간·클립 내 오프셋은 CFR 확인과 FFmpeg 절단을 전제로 한 근삿값이다.

분류 검증 설정이 없으면 저장되는 팀은 `unknown`, 보정 검증이 없으면 좌표는 null이다. 두 설정이 모두 검증되었다는 사용자 표시가 없으면 폭·길이와 코칭은 비운다. 사용자의 검증 표시는 정확도 보증이 아니다. 시점이 없거나 원본의 디코딩 결과가 달라 해시 검증이 실패하면 이미지를 저장하지 않으며 선수·지표·코칭도 빈 값이다. 프레임 기록은 최대 7,200개이고 메모리에만 있으므로 입력 전환·재시작 시 초기화된다. 사용자가 저장한 클립 자체와 해당 스냅샷은 디스크에 남는다. SRT는 정확한 촬영 시각을 확인할 수 없어 지원하지 않는다.

결과는 프로젝트 `sequences/` 아래 서버 생성 ID로만 저장하고 Git에서 제외한다. 장면은 최대 50개, 파일당 최대 50 MiB, 전체 최대 1 GiB이다. 소스 전환과 장면 생성이 동시에 일어나면 충돌을 반환한다. 임의의 로컬 경로·URL을 요청으로 전달할 수 없다. 삭제·일괄 정리 기능은 없다. FFmpeg가 없거나 `libx264`를 지원하지 않으면 생성을 할 수 없으며 서버에 설치된 도구로 설정해야 한다. `FOOTBALL_FFMPEG` 환경 변수로 실행 파일의 절대 경로를 지정하거나 프로젝트의 `bin/ffmpeg.exe`를 사용할 수 있다. 개발 환경의 FFmpeg 9.0.2 별도 빌드도 자동 탐색한다. 해당 빌드에는 GPL 옵션이 포함되어 있으므로 배포 전에 해당 라이선스를 확인한다.

공개 데모 게이트웨이를 사용하면 이 장면 목록과 저장된 영상도 접근 가능한 모든 이용자에게 공개된다. 현재 게이트웨이는 인증과 암호화가 없으므로 실제 경기 영상을 쓰기 전 보안 연결과 접근 제어를 마련해야 한다. 별도의 보안 프록시에는 이 기능이 추가되지 않았다.
