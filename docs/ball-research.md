# 공 후보 탐지: 자료와 실험

## 근거와 범위

- [SAHI 논문](https://arxiv.org/abs/2202.06934)과 [공식 구현](https://github.com/obss/sahi)은 작은 물체의 입력 크기를 확보하기 위해 겹치는 구간을 추론하고 원본 좌표로 결과를 합치는 접근을 설명한다. 여기서는 별도의 SAHI 패키지나 코드를 사용하지 않고 동일한 일반 원리로 단순 타일 추론을 구현했다. 원본 및 타일 경계의 후보는 IoU .5로 중복 제거하고 총량을 제한한다. 큰 공·컨텍스트 손실, 설비 오탐, 타일 경계, 캡으로 인한 누락과 GPU 비용을 검증해야 한다.
- [축구 공의 시간 정보 활용 논문](https://arxiv.org/abs/1909.02406)은 연속 프레임 이용의 가능성을 다룬다. 이 프로젝트는 아직 시간 정보를 이용해 공을 연결하거나, 검출되지 않은 위치를 예측하지 않는다. [TrackNet](https://arxiv.org/abs/1907.03698)은 테니스 영상 대상으로, 축구에서의 품질을 바로 가정할 수 없다. 공 점유·패스·속도·골은 제공하지 않는다.
- [Martinjolif 자료](https://huggingface.co/datasets/martinjolif/football-player-detection)는 데이터 카드에서 CC BY 4.0을 표기하고 선수·공 박스를 포함한다. 원본 중계 영상의 개별 권리와 경기 단위 분할은 별도 확인이 필요하다. [SoccerNet](https://www.soccer-net.org/faq)의 방송 영상은 권리와 연구 목적 제한이 별도여서 공개 모델이나 코드 라이선스를 영상에 그대로 적용하지 않는다.

## 설정과 API

기본 공 탐지는 꺼져 있다. `ball_detection: true`를 설정하면 기본 사람 모델 또는 `ball_model_path`에 지정한 별도 모델에서 클래스 이름이 `ball` 또는 `sports ball`인 클래스가 정확히 하나인지 확인한다. 적합한 클래스가 없거나 여러 개면 `ball_detection_available`은 false이고 후보도 제공하지 않는다. 체크포인트의 출처와 라이선스는 사용자가 별도 확인해야 한다. 모델 가중치는 프로젝트에 포함하지 않는다.

`ball_tiled_detection: true`를 추가하면 512px를 시작점으로 가로·세로 20% 중첩 영역을 만든다. 전체 프레임을 빠짐없이 덮도록 하되 24개를 초과하면 영역 크기를 늘린다. 타일별 최대 100개, 전역 중복 제거 전 최대 300개, 최종 최대 100개로 연산량을 제한한다. 밀집 장면에서 후보가 누락될 수 있다. 전체 프레임 추론 모드가 기본이고 타일 모드는 명시적으로 켜야 한다. 분할은 일반적으로 처리시간을 늘리므로 실제 아이폰 SRT에서 지연과 드롭을 측정해야 한다.

`ball_candidates`는 정규화된 **영상 픽셀 박스**와 모델 점수의 배열이며 골이나 공으로 확정한 값이 아니다. 후보가 여러 개이거나 비어 있을 수 있다. 경기장 좌표·공의 궤적을 추정하거나 없는 후보를 보간하지 않는다. 기존 `/api/v1/status`, `/analysis` 필드와 기본값을 유지한다.

```json
{"ball_detection": true, "ball_tiled_detection": true, "ball_model_path": "C:/trusted/model.pt"}
```

## 한정된 실제 자료 재실행

기존 `work/night-independent/martin`의 9장(공 기준 박스 총 9개)을 confidence .15, 입력 640, IoU .5 일대일 대응으로 재시험했다. 동일한 선수 데이터 기반 출처의 이전 시험용 가중치를 사용했으며, 이 9장은 여러 후보의 비교에 반복 사용됐고 경기 단위 독립성·주석 완전성·야간 여부가 확인되지 않았다. 독립적인 최종 정확도가 아니다.

| 방식 | 예측 후보 | 기준 박스와 대응 |
| --- | ---: | ---: |
| COCO 기본 전체 | 0 | 0 |
| COCO 기본 타일 | 10 | 2 |
| 이전 공 실험 모델 전체 | 5 | 0 |
| 이전 공 실험 모델 타일 | 18 | 5 |

예측 중 기준 박스에 대응하지 않은 것들은 주석 누락 여부가 확정되지 않아 모두 오탐으로 단정할 수 없다. 현재 사용한 모델과 반복 시험 자료는 원본 권리·일반화가 미확인이라 운영 모델로 승격하지 않았다. 별도 UVY 영상 1280×720 연속 5프레임에서 예열 후 기존 COCO 모델 타일 호출은 약 15.5fps였다. 영상 디코딩, 선수 탐지·추적, 전송, 대시보드가 빠진 5프레임의 속도이며 공의 정확도나 실제 30fps 처리를 증명하지 않는다.

다음에는 아이폰 고정 시점의 서로 다른 경기·조명·해상도에서 공이 존재하는지와 정확한 위치를 사람이 프레임별 검수한 시험 세트, 공 없는 프레임, 가림 및 빠른 이동 장면이 필요하다. 학습·모델 선택에 쓰지 않은 경기로 정밀도와 재현율, 오탐/분, 지연 및 프레임 드롭을 측정한다. 이미지 경계의 예측을 필드 좌표·이벤트로 자동 변환하지 않는다.

`python -m scripts.evaluate_ball_dataset --images <JPG폴더> --labels <YOLO라벨폴더> --weights <모델> --device 0`은 전체·타일 결과와 IoU .5 일대일 대응 수를 출력한다. JPG마다 같은 이름 TXT가 있어야 한다. 라벨의 공 클래스 ID 기본값은 0이며 다른 자료에는 `--label-class`를 지정한다. 이 도구는 이미지·주석의 권리, 경기 단위 독립성 및 정확도를 대신 검증하지 않는다.
