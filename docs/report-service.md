# 영상 분석 리포트 서비스 운영 안내

검수 서버(`app.review_public`)에 붙어 있는 영상 리포트 서비스의 구성, 운영 방법, 한계를 정리한 문서입니다. 화면 주소는 `/report`입니다.

## 1. 무엇을 하는 서비스인가

녹화 영상을 올리면 다음 순서로 처리해서 한 팀의 영상 분석 리포트(영상, 문서, 장면 데이터)를 만듭니다.

1. **선수 탐지**: 조각(60초)마다 사람을 찾고 색 특징을 저장합니다.
2. **선수 추적과 팀 분류**: 같은 선수를 이어 붙이고 팀(A 밝은 옷, B 어두운 옷)과 역할을 나눕니다.
3. **리뷰 영상 제작**: 선수 위치를 경기장 좌표(미터)로 바꿔 **하프 전체**에서 코칭할 장면(침투, 상대 침투 허용, 고립된 공격수, 수비 라인 하락, 입력한 득점)을 찾습니다. 장면마다 전체 화면, 핵심 선수 확대, 전술 보드, 이어지는 공격(득점이 뒤따르면 골까지)의 풀화면 컷으로 보여 주고, 글머리 3개 카드로 정리합니다. 결과는 `review.mp4`, `review.md`(글머리만), `events.json`입니다.

**한계**: 공의 흐름은 판정하지 않습니다(패스, 슈팅, 득점 판정 없음). 득점 장면 리포트는 사용자가 득점 시각을 입력해야 만들어집니다. 선수 위치는 자동 측정값이라 오차가 있고, 팀당 평균 9~10명 정도만 보입니다.

## 2. 화면 사용법

| 영역 | 설명 |
| --- | --- |
| 상단 상태 | 작업기 동작 여부, 대기와 진행 작업 수, 남은 저장공간(20GB 미만이면 빨간색) |
| 새 리포트 | 제목, 영상, 카메라, 대상 팀, 공격 방향, 분석 구간, 득점 시각(선택), 접속 토큰 입력 후 업로드 |
| 작업과 보관함 | 진행률과 남은 시간, 열기, 취소, 다시 시도, 삭제 |
| 상세 | 영상 재생, 내려받기, 문서(잘한 점, 아쉬운 점, 조언), 단계별 처리 로그(토큰 필요) |

시각은 `분:초` 또는 초로 입력하며, 영상 파일 안의 시각입니다. **공격 방향**은 대상 팀이 화면 기준 어느 쪽으로 공격했는지입니다(경기 중 바뀌면 구간을 나누어 올리세요).

## 3. 작업 상태

`업로드 중 → 대기 중 → 처리 중 → 완료` 순서로 가며, `실패`와 `취소됨`이 될 수 있습니다.

- 작업은 **한 번에 하나**씩 처리됩니다. 처리 시간은 영상 길이의 1.5~2배입니다.
- **서버를 다시 시작하면** 처리 중이던 작업은 대기열로 돌아가 처음부터 다시 처리하고, 업로드 중이던 작업은 실패로 표시됩니다.
- 완료, 실패, 취소된 작업은 최근 40개만 보관합니다(`FOOTBALL_REPORT_KEEP`로 변경).
- 작업 데이터는 `<검수 저장소>\reports\<작업 번호>\`에 있고, 삭제하면 업로드 원본과 결과가 함께 지워집니다.

## 4. 설정

서버를 시작할 때 환경 변수로 설정합니다. `scripts/run_review_server.ps1`이 설정 파일(JSON)에서 읽어서 대신 해 줍니다.

| 환경 변수 | 뜻 |
| --- | --- |
| `FOOTBALL_REPORT_TOKEN` | 접속 토큰(40자 이상 권장). **없으면 업로드와 작업 변경이 모두 꺼집니다.** |
| `FOOTBALL_REPORT_CAMERAS` | 카메라 설정 JSON(아래 참고) |
| `FOOTBALL_REPORT_DETECTOR` | 사람 탐지 모델(yolo) 파일 |
| `FOOTBALL_REPORT_CLASSIFIER` | 팀과 역할 분류 모델 파일 |
| `FOOTBALL_REPORT_FFMPEG` | ffmpeg 실행 파일 |
| `FOOTBALL_REPORT_CALIBRATIONS` | 검수 저장소의 `calibration\calibrations.json` |
| `FOOTBALL_REPORT_MAX_MB` | 업로드 최대 크기(기본 4096) |
| `FOOTBALL_REPORT_KEEP` | 보관할 완료 작업 수(기본 40) |

### 카메라 설정 (`cameras.json`)

```json
{
  "cam1": {"label": "운동장 서쪽", "bg": [1.000657, 0.000035, -0.67, -0.47], "shift_schedule": "0:0.0,-0.2", "pitch_length": 89, "pitch_width": 62},
  "cam3": {"label": "운동장 동쪽", "bg": [1.003087, -0.001614, -7.41, 5.61], "shift_schedule": "0:-1.8,6.8", "pitch_length": 89, "pitch_width": 62}
}
```

새 카메라 위치를 쓰려면 먼저 검수 화면(`/train`)의 미니맵 보정으로 경기장 기준점을 저장하고(보정 오차가 5m를 넘으면 거절됩니다), 그 카메라 이름으로 위 설정에 추가해야 합니다. 카메라 이름은 소문자, 숫자, `-`, `_`만 쓸 수 있습니다.

## 5. 운영

```powershell
# 시작(이전 서버를 끄고 저장소를 백업한 뒤 시작)
.\scripts\run_review_server.ps1 -ConfigFile C:\경로\server.json
# 상태 확인
.\scripts\run_review_server.ps1 -ConfigFile C:\경로\server.json -Status
# 중지
.\scripts\run_review_server.ps1 -ConfigFile C:\경로\server.json -Stop
```

- 시작할 때마다 저장소 전체를 백업합니다(`-NoBackup`으로 생략 가능). 백업 폴더는 수동으로 정리하세요.
- 컴퓨터가 갑자기 꺼졌을 때는 같은 명령으로 다시 시작하면 됩니다. 대기열은 위 3번대로 복구됩니다.
- **무거운 작업(탐지, 영상 제작)은 CPU와 GPU를 오래 씁니다.** 같은 컴퓨터에서 게임이나 다른 무거운 작업을 함께 돌리지 마세요(전원 문제로 컴퓨터가 꺼진 적이 있습니다).

## 6. 보안

- 이 서버는 암호화되지 않은 공개 HTTP입니다. 토큰이 **네트워크에서 그대로 보일 수 있으므로** 외부에서 쓸 때는 같은 토큰을 다른 곳에서 쓰지 마시고, 가능하면 HTTPS 프록시나 VPN 뒤에 두세요.
- 변경 작업(업로드, 취소, 다시 시도, 삭제, 로그 보기)은 토큰이 필요합니다. 목록과 완료된 결과는 토큰 없이 볼 수 있습니다.
- 업로드 파일은 영상 확장자만 받고, 파일 이름을 경로로 쓰지 않으며, 업로드 원본은 내려받을 수 없습니다. 로그에서는 컴퓨터 경로를 지워서 보여 줍니다.

## 7. 문제 해결

| 증상 | 확인 |
| --- | --- |
| 화면에 "업로드 꺼짐" | 서버를 시작할 때 `FOOTBALL_REPORT_TOKEN`이 설정되지 않았습니다. |
| "접속 토큰이 맞지 않습니다" | 토큰 파일의 값과 입력한 값이 다릅니다(앞뒤 공백, 줄바꿈 주의). |
| 작업이 `실패`: "영상 파일을 읽을 수 없습니다" | 영상이 손상되었거나 다 올라가지 않았습니다. 다시 올려 주세요. |
| 작업이 `실패`: "이 카메라의 경기장 보정…" | 카메라 설정이나 저장소의 보정이 없거나 오차가 큽니다. |
| 리포트에 득점 장면이 빠짐 | 그 시각 전 25초 동안 팀 선수가 6명 미만으로 보여 위치 분석을 만들 수 없는 경우입니다(로그에 기록됨). |
| 영상 화면과 선수 표시가 어긋남 | 녹화 영상의 프레임 간격이 일정하지 않은 경우를 처리하도록 ffmpeg으로 프레임을 잘라 맞춥니다. ffmpeg 경로를 확인하세요. |

## 8. 개발자용 API

모두 `POST`이며 요청 출처(`Origin`)가 서버의 공개 주소와 같아야 합니다. 변경 API는 `X-Report-Token` 헤더가 필요합니다.

- `/api/v1/report/list`: 작업 목록, 카메라 목록, 상태 점검
- `/api/v1/report/upload?camera=&team=&direction=&start=&end=&half_name=&title=&goals=&name=`: 본문은 영상 바이트
- `/api/v1/report/cancel`, `/retry`, `/delete`: `{"job": "작업 번호"}`
- `/api/v1/report/log`: `{"job": "작업 번호", "step": "detect|track|report"}`
- `GET /report-files/<작업 번호>/<review.mp4|review.md|events.json>(이전 방식의 report.mp4, report.md, scenes.json도 열 수 있음)`: 결과 파일(영상은 구간 이동 가능)
