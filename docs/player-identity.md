# 선수 확인 (누가 누구인지)

추적기가 만든 짧은 추적 조각마다 "이 선수가 누구인가"를 사람이 답하고, 그 답을 이어 가는 기능의 사용 방법과 한계, 그리고 카메라를 더 쓸 때의 기대 효과를 정리한 문서입니다.

## 1. 구성

| 파일 | 역할 |
| --- | --- |
| `scripts/prepare_player_review.py` | 경기 한 구간의 추적 조각마다 사진 3장, 시간, 위치, 추정 포지션 자리를 만들고, "같은 사람일 수 있는" 쌍을 찾습니다 |
| `app/player_identity.py` | 선수 명단과 사람의 답(추적 조각 → 선수, 두 조각이 같은 사람인지)을 파일로 저장합니다 |
| `app/position_slots.py` | 팀의 위치 모양에서 골키퍼, 수비, 중원, 공격 줄과 "왼쪽 풀백" 같은 자리를 추정합니다 |
| `web/players.html`, `web/players.js` | 서버의 `/players` 화면 |

### 준비 명령
```bash
python scripts/prepare_player_review.py <서버 저장소 폴더> h1 <영상> <ffmpeg> <calibrations.json> "전반|<tracks.json>|cam1|-1|64|1.000657,0.000035,-0.67,-0.47|0:0.0,-0.2|"
```
- 길이 40줄(8초) 이상인 추적 조각만 다룹니다. 전반은 449개였습니다.
- 사진은 영상의 정확한 시각에서 잘라 만든 것이고, 220픽셀 높이로 키운 것입니다(원본은 선수 키 약 30픽셀이라 흐립니다).

### 화면에서 하는 일
1. **선수 명단**: 팀, 번호, 이름, 포지션을 한 번 적습니다(전후반 공통). 같은 팀에서 번호가 겹치면 거부합니다.
2. **같은 사람인가요?**: 추적기가 놓친 뒤 가까운 곳에서 다시 잡은 것으로 보이는 쌍을 보고 "같은 사람"이나 "다른 사람"을 누릅니다. 같은 사람으로 답하면 두 조각이 하나의 묶음이 되어, 한 조각에만 이름을 골라도 묶음 전체가 그 선수가 됩니다.
3. **추적 조각마다 선수 고르기**: 사진 3장을 보고 명단에서 고릅니다. 팀이 다른 선수는 고를 수 없습니다.
- 이어진 조각들의 답이 서로 다르면 "충돌"로 표시하고 어느 쪽도 추측하지 않습니다.
- 답은 `<저장소>/players/assign/<구간>.json`, 이음 답은 `<저장소>/players/links/<구간>.json`, 명단은 `<저장소>/players/roster.json`에 저장됩니다.

### 포지션 자리 추정의 규칙
- 팀 전체를 깊이 순으로 세 줄(수비, 중원, 공격)로 나누고, 각 줄 안에서 팀 기준 왼쪽에서 오른쪽 순서로 자리를 붙입니다. 카메라가 +y 쪽에 있으므로 오른쪽으로 공격하는 팀의 오른쪽은 화면 아래쪽입니다.
- 가장 뒤의 선수가 그다음 선수보다 8미터 넘게 뒤에 있고 팀에서 8명 이상이 잡힐 때만 골키퍼로 부릅니다.
- 8명 미만이 잡히면 줄이 불안정해서 "수비, 중원, 공격"까지만 말합니다.
- 이 자리는 그 순간의 팀 모양이지 선수의 고정 포지션이 아닙니다. 선수끼리 자리를 바꾸면 자리 이름도 바뀝니다.

## 2. 우리가 분류해야 하는 것과 시스템이 인식할 수 있는 것

| 항목 | 지금 시스템이 하는 것 | 사람이 해야 하는 것 |
| --- | --- | --- |
| 사람인지, 어느 팀인지 | 옷 색과 학습한 모델로 인식(팀 구분 약 85%) | 틀린 곳을 `/train`에서 고치기 |
| 심판, 골키퍼, 관중 | 일부만 구분(골키퍼는 위치로만 추정) | 라벨 |
| 한 사람을 따라가기 | 몇 초에서 몇 분 동안 이어서 따라감 | 끊긴 곳이 같은 사람인지 답하기 |
| 선수 이름, 번호 | 읽지 못함(선수 키 약 30픽셀) | 명단 입력과 추적 조각마다 고르기 |
| 포지션 | 그 순간 팀 모양에서 자리 추정 | 선수의 실제 포지션 입력, 추정이 맞는지 확인 |
| 등번호 | 읽지 못함 | 번호 입력, 번호가 보이는 사진을 고르기 |
| 선수의 일관된 이력(누가 몇 분을 뛰었나) | 사람이 준 답이 있을 때만 합산 가능 | 위 답 |

피드백으로 들어온 "포지션과 등번호까지 구별하면 사람을 더 정확히 인식한다"는 의견에 대해서는 이렇게 정리됩니다. 포지션 자리는 같은 팀 안에서 후보를 줄이는 데 도움이 되지만(예: 왼쪽 풀백 자리에 있던 조각은 왼쪽 풀백 후보), 선수가 자리를 바꾸면 틀립니다. 등번호는 직접 증거로 가장 강하지만 지금 해상도에서는 읽을 수 없어서, 사람이 번호를 입력하는 방식으로만 쓸 수 있습니다.

## 3. 경기장을 반쪽씩 찍는 방법, 반대편 카메라

이 영상에서 추적된 선수 상자의 키(픽셀)를 위치별로 쟀습니다(전반 약 13만 줄, 후반 약 11만 줄).

| 위치 | 상자 높이 중간값 |
| --- | --- |
| 카메라에 가까운 쪽(y > 12m) | 47~48픽셀 |
| 가운데 | 29~31픽셀 |
| 먼 쪽(y < -12m) | 21~22픽셀 |

- 먼 쪽 선수는 가까운 쪽 선수의 절반 크기입니다. 등번호와 외형 구분에는 키 150픽셀 정도가 필요하다는 점에서, 지금은 가장 가까운 쪽 선수도 3분의 1 수준입니다.
- **반쪽씩 찍기**(카메라마다 경기장 절반만 줌으로 담기): 같은 해상도에서 화면 폭이 절반이면 선수가 약 2배 크게 찍힙니다. 가까운 쪽 선수는 약 95픽셀, 가운데는 약 60픽셀, 먼 쪽은 약 44픽셀로 계산됩니다(위 측정값의 단순 2배 추정이고, 실측하지 않았습니다). 같은 장면을 4K로 찍으면 다시 2배가 되어 가까운 쪽 선수가 약 190픽셀이므로 등번호를 읽을 수 있는 범위에 들어옵니다.
- **반대편 카메라**: 먼 쪽 선수가 가까운 쪽 선수가 되어 두 카메라 중 하나는 모든 선수를 "가까운 쪽 크기"로 보게 됩니다(가운데 선수는 어느 쪽에서도 중간). 선수가 서로 가려지는 문제도 줄어듭니다.
- 둘을 합치면(양쪽에서 반쪽씩, 총 4대) 모든 선수가 가까운 쪽 크기의 2배로 보입니다. 장비와 사람이 가장 많이 필요합니다.
- **필요한 것**: 카메라마다 경기장 보정(모서리와 선 위의 점 클릭), 카메라 사이의 시간 맞추기(시작할 때 박수나 호루라기 소리를 기준으로 맞출 수 있음), 두 카메라가 겹치는 구간(중앙선 부근)에서 같은 사람을 이어 주는 합치기 코드(아직 없음), 카메라 수만큼 늘어나는 처리량(지금 실시간이 겨우 되는 수준이라 GPU가 더 필요).
- **기대 효과(추정)**: 선수 검출 수가 늘고(작은 선수를 더 잘 찾음), 팀 구분이 좋아지고, 가까운 쪽 선수의 등번호를 읽을 가능성이 생깁니다. 정확히 얼마나 좋아지는지는 실제로 찍어서 재야 알 수 있습니다.

## 4. 선수 이어 달기 (`/players` 첫 칸)

한 선수의 조각을 이어서 이름을 붙이는 화면입니다. 22명 전체가 아니라 관심 있는 선수부터 해도 됩니다.

1. 선수를 고르면(처음에는 팀 B 명단만 나옵니다) 그 선수의 포지션 줄(수비수, 미드필더, 공격수, 골키퍼)에 맞는 조각이 긴 것부터 나옵니다. 하나를 골라 "이 선수가 맞음"을 누르면 시작입니다.
2. 그 뒤에는 이미 정한 조각 **앞뒤 90초 안**에서, 끝난 자리와 시작한 자리가 가까운 조각만 후보로 나옵니다(허용 거리는 4m + 초당 5m, 최대 40m 기준으로 순위를 매깁니다).
3. 후보 카드의 지도에서 주황 점은 앞 조각이 끝난 자리, 하늘색 점은 이 조각이 시작한 자리입니다(팀이 공격하는 방향이 오른쪽). 사진은 앞 조각의 끝 모습과 이 조각의 앞, 가운데, 뒤 모습입니다.
4. "이 선수가 맞음"을 누르면 그 조각이 선수의 조각이 되고 후보가 새로 계산됩니다. "아님"을 누르면 그 선수에게는 다시 나오지 않습니다(`players/rejects/<구간>.json`).
5. 위쪽에 정한 조각의 시간과 합계가 나오고, 조각 옆 ×로 뺄 수 있습니다.

후보에서 제외되는 것: 이미 다른 선수로 정해진 조각(이어진 조각 포함), 시간이 선수의 조각과 1초 넘게 겹치는 조각, 이어진 조각끼리 답이 충돌하는 조각, 다른 팀 조각.
순위: 시간과 거리가 가까울수록 앞에, 포지션 줄이 맞으면 앞으로, 다르면 뒤로 보냅니다. 순위는 도움을 주는 것일 뿐 판정이 아닙니다. 마지막 확인은 사람이 합니다.

## 5. 조각이 끊기는 원인 측정 (2026-11-13)

팀 B 조각은 전반 204개, 후반 178개입니다. 줄일 수 있는지 라벨 없이 측정했습니다.
- 한 순간에 추적되는 선수는 팀 A 약 11명, 팀 B 약 10명으로 거의 전원입니다(20개 화면 표본). 검출 수가 모자란 것이 아닙니다.
- `scripts/auto_link_tracks.py`로 "5초 안에, 달릴 수 있는 거리 안에서, 서로가 유일한 후보"인 쌍만 이어 보니 전반 12쌍, 후반 15쌍(조각 3~6% 감소)이었습니다. 짧은 조각까지 넣어도 비슷했습니다. 다음 조각은 대부분 20~30초 뒤에 나와서 거리와 시간만으로는 확정할 수 없습니다.
- 같은 사람을 겹쳐서 따라간 중복 조각(5프레임 이상 겹치고 상자 겹침 평균 0.5 초과)과 2초 안의 인계는 전반 5쌍, 후반 8쌍뿐이었습니다. 끝난 조각의 주변에 다른 조각이 보이는 경우가 약 3분의 1이라는 처음 측정은, 상자가 겹친 옆 선수를 같은 사람으로 센 과대 추정이었습니다.
- 사라진 조각의 끝 자리에는 1초 뒤에도 사람 검출이 대부분 있었습니다(40개 표본 중 31~34개, 근처의 다른 선수일 수 있음). 추적기가 놓친 선수를 오래 기다리지 못하는 것이 유력한 원인입니다. 확인하려면 추적을 다시 돌려야 합니다.
- 그래서 자동 이음은 저장소에 반영하지 않았고, 이름 붙이기는 사람의 답과 등번호로 계속합니다.
- 추적기 대기 시간을 늘린 재추적 실험(전반, 저장된 검출로 약 30초 소요, `scripts/track_from_cache.py`의 `--track-buffer`와 `--stitch-gap`): 사람 추적 수가 기준 575개에서 이음 간격 75프레임으로 461개, 대기 150프레임과 이음 150프레임으로 443개(약 23% 감소)가 되었습니다. 대신 한 조각 안의 옷 색 일치도가 0.783에서 0.743으로 낮아져, 다른 사람을 잘못 이은 조각이 늘었을 가능성이 있습니다. 정답이 없어 정확도는 재지 못했고, 사람이 같은 사람으로 답한 쌍(대부분 간격 0.2~3.4초)은 어느 설정에서도 달라지지 않았습니다. 그래서 기본 설정은 바꾸지 않았습니다.
- 분명한 쌍이 이어지지 않던 원인(후반 17190번과 17788번으로 확인): `track_from_cache.py`가 추적을 이어 붙이기 전에 새 조각의 탄생 검출을 최대 3프레임 앞으로 되돌려 넣는데(`--backfill`), 그러면 새 조각이 앞 조각의 끝과 1~2프레임 겹칩니다. 이음 규칙은 겹친 조각을 절대 잇지 않아서, 바로 붙어 있고 상자가 77% 겹치는 쌍도 이어지지 않았습니다. `--stitch-overlap 3`으로 3프레임까지 겹침을 허용하면 전반과 후반에서 사람 추적이 각각 13개 줄고, 사람이 "같은 사람"이라 답한 쌍 중 후반 14개 가운데 5개, 전반 5개 가운데 1개가 하나로 합쳐졌습니다. 다만 전반에서 사람이 "다른 사람"이라 답한 19쌍 중 2쌍이 잘못 합쳐졌습니다(후반은 6쌍 중 0). 그래서 기본값은 0(끔)으로 두었습니다.
- 반영(2026-11-13): 후반만 `--stitch-overlap 3`으로 다시 추적한 결과(`work/tracks-ov3-20261113/h2_ov3.json`)로 선수 확인 자료를 다시 만들었습니다(후반 조각 368개에서 358개). 전반은 잘못 합쳐진 쌍이 있어 기존 추적을 그대로 둡니다. 답은 `scripts/migrate_player_answers.py`로 새 조각 번호에 옮겼고(충돌과 유실 없음), 옮기기 전 상태는 `work/players-backup-20261113-before-ov3`에 복사해 두었습니다.
