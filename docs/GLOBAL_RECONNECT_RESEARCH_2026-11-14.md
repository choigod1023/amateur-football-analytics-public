# 여러 재연결 후보를 함께 판단하는 실험

현재 코드는 각 새 ID에서 1위 후보를 고르고, 같은 기존 ID로 몰린 제안은 모두 버린다. 새 실험은 한 창 안의 후보를 함께 최적화해 한 기존 ID를 두 사람에게 연결하지 않는다. 미연결을 정식 선택지로 두며 22명을 채우거나 좌표를 생성하지 않는다. 운영에 연결하지 않은 실험 모듈이다.

## 논문에서 가져온 범위

- [Zhang, Li, Nevatia, CVPR 2008](https://www.cvlibs.net/projects/autonomous_vision_survey/literature/Zhang2008CVPR.pdf)는 궤적의 배타성을 갖는 비용 흐름 최적화를 제안했다. 여기서는 전체 영상 네트워크 흐름을 재현하지 않고, 제한된 후보 창에서 이분 그래프 할당을 구현했다. 논문의 성능을 이 코드의 성능으로 인용하지 않는다.
- [OC-SORT, CVPR 2023](https://arxiv.org/abs/2203.14360)는 가림 동안 선형 예측 오차가 누적될 수 있음을 설명하고 관측 기반 갱신을 제안한다. 기존 temporal_reconnect의 앞 5장·뒤 3장 관측과 양방향 잔차를 유지한다. 이번 변경은 OC-SORT 구현 또는 재학습이 아니다.

## 구현과 경계

`app/global_reconnect.py`는 순수 Python Hungarian 할당을 사용한다. 후보 최대 512개, 각 집합 최대 64개로 제한하고 초과하면 명시적으로 오류를 낸다. 선수 수 제한과는 다르다. 한 행마다 미연결 열을 추가한다. 점수는 확률이 아닌 순위 점수다. 미연결 기준 0.5, 승인 하한 0.9, 전역 대안과 차이 0.15는 검증 전 정책값이다.

선택된 연결을 하나씩 금지하고 다시 풀어 전체 목적함수 감소량을 측정한다. 작은 차이는 미연결로 남기며, 거절 후 다른 연결을 강제로 채우지 않는다. 동일 원본 ID의 파편들은 호출 전에 canonical ID로 통합해야 한다. 여러 카메라/영상의 ID를 한 창에 섞으면 안 된다.

입력은 실제 마지막 관측 시각, 새 관측 시작 시각, 점수 계산에 사용한 마지막 프레임 시각을 요구한다. 미래 프레임, 역전된 시간, 2.5초 초과 공백, 0.6초 초과 확인 지연은 거절한다. 이미 공개한 ID를 나중에 바꾸는 기능은 없다. 창에 들어온 경쟁 후보가 누락되면 전역 여유값을 과대평가하므로, 운영 연결 전 전체 후보 기록이 반드시 필요하다.

## 실행 결과

회귀 테스트 10개 통과. 이 안에 작은 비용 행렬 80개의 전수 열거 결과와 최적해 비교가 포함된다. 충돌 제안, 교차 시 유사 외형의 모호함, 동점, 미연결, 미래 정보, 시간 중첩, NaN, 중복 입력, 세 번째 관측의 확인 지연, raw ID 재등장 때 alias 중복 해제를 검증했다.

기존 원본 이미지와 사람 답의 SHA256을 확인하고 4개 학습 쌍을 다시 계산했다. 기존 방식과 새 방식 모두 실제 재연결 2개(d0108, d0109)를 승인했다. d0105는 원래 raw ID가 동일해 재연결 대상이 아니다. 다른 사람 답 d0110은 기존 운동 잔차 제한에서 탈락했다. **새 개선 효과는 0개이며, 이 4개는 학습에 쓴 자료이므로 일반화 정확도를 뜻하지 않는다.** 이 자료에는 같은 시점의 여러 후보 간 충돌 사례가 없어, 전역 할당의 실제 영상 우위를 검증하지 못했다.

학습에 쓰지 않은 eval-305·306의 예전 기록에는 거절 후보와 관측 종점 시간이 없어 로그만으로 재실행할 수 없었다. 따라서 별도 `GlobalTemporalLinker`와 `evaluate_global_temporal_video.py`를 만들고 원영상에서 탐지·추적을 다시 실행했다. 같은 상자, 같은 temporal 모델, 같은 0.4초 확인 지연을 두 방식에 적용했다. 각 영상의 0–30초, 300–330초, 600–630초를 5fps로 평가했고 정답은 채점에만 썼다.

| 별도 경기 | local IDSW | global IDSW | local/global 승인 | local/global 정연결·오연결·미확정 |
|---|---:|---:|---:|---|
| 305 | 1641 | 1641 | 9 / 9 | 4·1·4 / 4·1·4 |
| 306 | 1622 | 1622 | 6 / 6 | 4·1·1 / 4·1·1 |

합계 900프레임에서 **IDSW 3263→3263, 기록상 오연결 2→2로 개선되지 않았다.** 양 방식의 GT 매칭 5878, 미매칭 GT 12234, 미매칭 탐지 5287도 동일했다. 미매칭 탐지 전부를 오탐으로 부를 수 없다. 더 엄격한 앞뒤 경계 감사에서는 두 방식 모두 정연결 5·오연결 2·미확정 8이었다. 단일 시점 ID 판정과 경계 감사의 차이도 남아 있다.

재생한 후보 66개 중 경쟁이 존재한 창은 8개뿐이었다(305 3개, 306 5개). 최대 창 크기는 4개이고 상한 초과는 없었다. 결과가 같은 이유는 새로운 할당을 사용할 경쟁 후보가 적고, 실제 오연결 후보의 점수를 개선하는 변경이 아니기 때문이다. 많은 ID 변경은 후보 생성 이전의 미탐·단절에서 발생한다. 다음 단계는 원영상의 미탐과 운동 잔차에서 탈락한 후보를 검토하고, 더 많은 검증된 같은 사람/다른 사람 다중 프레임 쌍으로 점수 모델을 개선하는 것이다. 제한을 무조건 풀면 오연결이 늘 수 있다.

450프레임 평가 전체 실행은 각각 27.26초·19.76초였으며 영상 해독·탐지·두 방식 비교를 모두 포함한다. 저장된 후보만 다시 푼 마이크로 측정은 창당 평균 0.0026ms·0.0021ms였다. 이는 GPU 파이프라인 또는 스트리밍 지연을 뜻하지 않으며, 이 작은 그래프 크기의 CPU 할당 비용만 보여준다. IDSW는 기존 greedy IoU≥0.5 진단 방식으로 계산했고 공식 HOTA/IDF1이 아니다. 운영, 미니맵, 코칭 개선을 주장하지 않는다.

## 재현

프로젝트 가상환경 Python으로 실행한다.

```powershell
python -m unittest discover -s tests -p 'test_global*py'
python scripts/evaluate_global_reconnect.py ../../work ../../work/paper-improvements-20261114/reconnect
python scripts/evaluate_global_temporal_video.py VIDEO TRACK_JSON TEMPORAL_MODEL ENDPOINT_MODEL YOLO_WEIGHTS NEW_OUTPUT --group aihub-match-305
```

결과는 work/paper-improvements-20261114/reconnect/comparison.json 및 eval-305/306 하위 비교·후보·경계 감사 파일에 있다. 별도 영상 평가 출력의 기존 호환 키 endpoint는 baseline_local_temporal, temporal은 global_temporal을 뜻하며 mode_names에 명시한다. ENDPOINT_MODEL은 기존 학습/평가 분리 검사에만 쓰며 두 비교 방식은 TEMPORAL_MODEL을 사용한다. 영상 305는 work/aihub-coaching-eval/video-02.mp4, 306은 video-04.mp4이고 정답은 work/aihub-role-study/final-305-track.json 및 final-306-track.json이다. 인간 답과 원본 이미지는 읽기만 한다. 운영 경로와 기존 모델 가중치는 바꾸지 않았다.

후보와 canonical/raw ID, 정확한 종점 시각을 이번 재생에서 저장했다. 같은 가림 장면의 정답 검증을 확대한 뒤 특징 개선을 비교해야 한다. 오연결 감소가 확인되기 전 운영 자동 재연결에 넣지 않는다.
