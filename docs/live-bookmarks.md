# 라이브 화면 북마크

라이브 입력을 분석 중일 때 사용자가 `현재 장면 표시`를 누르면 최근 처리된 영상 프레임 한 장과 그 프레임에서 계산된 인물 수·지표·피드백을 서버 메모리에 저장한다. `timestamp`는 서버가 디코딩한 시각이지 촬영 시각이나 경기 시계가 아니다. 북마크 생성은 최근 1초 이내의 프레임이 있을 때만 허용하며 최대 20개이다. 초과하면 기존 것을 지우지 않고 생성 요청을 거부한다. 입력을 전환해도 만든 북마크는 유지되지만 프로세스 재시작 시 사라진다.

**동영상 녹화나 전후 구간 다시보기는 아니다.** 현재 공·경기상황의 독립 검증이 없어 결정적 찬스를 자동 판정하거나 임의로 코칭하지 않는다. 기존 지표와 피드백이 보류된 프레임은 빈 결과를 유지한다. 영상 프레임과 분석은 같은 처리 반복에서 가져오며 미리보기 테두리는 제외된 원본 분석 프레임이다.

`GET /api/v1/live-bookmarks`, `POST /api/v1/live-bookmarks`, `GET /api/v1/live-bookmarks/{id}/frame.jpg`는 로컬 서버용이다. 기본 공개 데모·보안 프록시의 API 허용 목록에는 추가하지 않았다. 웹 페이지에 다른 Origin에서 작성 요청이 오면 거부한다. 인증된 원격 북마크에는 별도 접근 제어와 저장 정책이 필요하다.

실제 로컬 SRT→MediaMTX→RTSP 입력으로 별도 127.0.0.1 포트에서 테스트할 때 한 시점의 실제 JPEG 프레임과 인물 11명, 빈 피드백을 북마크로 반환했다. 통신 흐름 검증이며 장면의 전술 의미·실제 아이폰·원격 네트워크·장시간 안정성은 검증하지 않았다. 추후 플레이리스트의 실제 전후 영상을 복구하려면 별도 녹화·보존 한도·동기화·접근 제어가 필요하고, 자동 찬스 후보는 공·골대·선수 및 경기 상황의 정확도와 거짓 후보율 평가가 선행돼야 한다.
