# 겹침과 원거리 위치 흔들림 개선 검증

## 구현 범위

`scripts/run_live_feedback.py --motion-guard`에서 선택적으로 사용한다. 운영 기본값은 변경하지 않았다.

`IdentityGuard`는 같은 tracker ID에 색상·상자 변화가 동시에 크게 나타나면 새 구간ID를 부여한다. 다른 ID끼리 동일인을 복원하는 재식별 모델은 아니다. 겹친 상자로 외형 특징을 갱신하지 않는다. 부분 상자→전신 상자로 바뀔 때에는 포함률과 발 위치를 함께 확인해 자동 분리를 보류한다. 내부구간ID는 실제 선수 신원이 아니다.

`FootStabilizer`는 작은 원거리 상자의 관측 발 위치만 시간상수0.18초로 안정화한다. 수정은 최대3px·상자높이15%로 제한하며 metre변환 뒤0.8m를 넘으면 원본을 사용한다. 겹침,큰 이동,상자크기 변화,0.6초보다 긴 공백에서는 원본으로 돌아간다. 없는 선수를 생성하지 않는다.

추가 `DisplayPositionGuard`는 필터가 원본으로 돌아갈 때 새 순간 이동이 생기지 않도록 검사한다. 안전한 원본으로도 연결할 수 없으면 해당 표시 관측을 생략한다. 표시 필터가 코칭이나 경기 지표에 들어가지 않도록 원본 관측과 분리했다. API에 raw_players와 position_basis를 추가했고 기존 필드는 유지했다.

## 사용자 답과 비교

기존 d0105 같은사람, d0106·d0107 다른사람 답을 사용했다. 단독 상자뿐 아니라 해당 시각의 주변 저장 추적 상자를 모두 넣어도 동일인1건 유지·다른사람2건 분리 결과를 얻었다. 이3건은 개발에 참고했으므로 독립 정확도가 아니다. 기존 정답을 재작성하지 않았다.

새60초 영상에서 초안은5곳을 분리했으나 확대 검토 결과 부분/전신 상자 변화로 의심됐다. 포함률0.818–1.0,발변화0.18–0.49상자높이였고, 사람 답이 다른 두 사례는발변화1.65·1.99였다. 포함률과 발위치 검사를 추가한 최종본은5곳을 검토 후보로만 기록하고 ID를 분리하지 않는다. 5개를 실제 ID오류 수정 성과로 세지 않는다.

## 실제 영상 새 추론

촬영 영상1950–2010초,300분석 프레임을 동일 yolo11n·기존 팀모델·ByteTrack·cam3수동 보정으로 전후 각각 새로 분석했다. 마지막 경계수정까지 포함해 최종GPU 실행을 다시 끝냈다. 자료 위치는 `work/motion-validation-20261113/verified/`다.

| 항목 | 기존 | 최종 수정 |

| 위치 표시 중앙값 |18명|18명|

| 코칭 |박스공격1·수비선진단1|박스공격1·수비선진단1|

표시 가속도 p95가32.9% 줄었지만 실제 움직임도 포함된 지표이므로 metre정확도32.9% 향상이라고 해석할 수 없다. 위치 정답은 없다. 표시 관측2개를 추가로 생략한 대가가 있으며 누락 없는FM식22명추적은 달성하지 못했다. 실제 적용한 표시 변경량은 중앙값0.104m,최대0.786m였다.

원본 관측을 쓰는 코칭은 종류와 발생시각이 같았다. 이번 변경으로 코칭의 정답률이 좋아졌다는 근거는 없다. 수비선 알림은 같은 선수의 후퇴를 확인했다는 주장이 아니라 관측 구성 변화 진단이다.

## 검증과 결과물

전체Python테스트448개통과·1개건너뜀 이후 표시생략으로 인원초과검사가 우회되지 않도록 회귀테스트1개를 추가했다. 기존 저장JSON1187개SHA256비교에서 변경0개였다. 운영 재시작·배포·모델 가중치 교체는 하지 않았다.

`comparison.mp4`는 실제영상과 전후미니맵,알림종류를 나란히 보여주는60초비교영상이다. 이는5fps평가영상이며 연속SRT송출검증은 아니다. `comparison.json`과 전후관측JSONL을 같은 폴더에 보관했다. `scripts/compare_motion_replay.py`, `scripts/render_motion_comparison.py`로 재현한다.

미해결: 완전히 가려진 선수 재식별,같은유니폼간ID변경,부분탐지 자체의 복구,물리적위치 정답평가. 현재검토후보5건을 새 정답으로 취급하지 않는다.
