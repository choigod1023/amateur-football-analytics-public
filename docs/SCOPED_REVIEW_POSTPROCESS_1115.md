# 사용자 답을 장면 후처리에 연결

다음 순서: 답 연결 → 같은 장면의 합치기/중복 제거 검사 → 교차 전후 동일인 검증 → 답을 쓰지 않은 장면의 ID switch와 오연결 비교 → 영상 프리뷰 → 개선 확인 시 운영 후보. 이번 변경은 첫 두 단계의 제한된 구현이다.

## 구현
app/reviewed_scene.py와 scripts/apply_reviewed_scene.py가 원본 영상·관측 trace SHA256을 확인하고 답의 시간 범위만 추출한다. 사용자가 서로 다른 사람이라고 답한 쌍은 stitch_tracks의 합치기 금지와 drop_duplicates의 제거 예외에 전달한다. 다른 안전한 연결로 대표 ID가 바뀌어도 membership으로 예외를 변환한다. 원본 답을 덮어쓰지 않으며 출력은 새 파일에만 쓴다. 다른 촬영이나 다른 시각에 raw ID를 전역 적용하지 않는다. 주어진 기간의 모든 인물을 비교하되 팀·신원을 임의로 정답화하지 않는다.

## 실행 결과
실제 11.6~13.0초 장면 전체를 처리한 전후 결과 모두 29트랙/합침0/중복 제거2. 두 제거는 사용자 확인 쌍이 아니며 자동 판정의 정답 여부는 검증하지 않았다. ID29의5개와 ID31의7개 관측은 전후 모두 보존됐다. 정확도 개선이 확인된 결과는 아니다. 기존 알고리즘이 해당 쌍을 지우지 않으므로 답 연결만으로 새로운 성능 이득이 생기지는 않았다.

회귀 테스트는 강하게 겹친 서로 다른 인물 보호, 원본 불일치 거부, 시간 범위 제한, 대표 ID 변경 후 예외 보존을 포함한다. 합성 반례는 규칙 동작 검증이며 실제 정확도 수치에 넣지 않는다.

## 남은 판단
이번 답은 ‘두 명’이라는 정답이고 ‘겹침 전후 각 ID의 동일인 유지’ 정답은 아니다. 이동 외삽만으로 ID를 교환하면 유지되던 ID까지 틀릴 수 있다는 이전 감사 결과가 있어 자동 ID 교환은 넣지 않았다. 추가 촬영 없이 해결해야 하는 다음 항목은 교차 전후 동일인 평가 자료 확보와 후보별 비교다. 두 카메라 실험은 별도 실제 동시 영상이 필요하다.

결과: work/scoped-review-postprocess-20261115/reviewed-result.json. 운영 파이프라인 자동 적용이나 모델 재학습은 수행하지 않았다. CLI를 통해 검증된 장면 후처리 연결이며 live ID 스위치 해결을 뜻하지 않는다.
