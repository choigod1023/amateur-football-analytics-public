# 사람 확인 답 반영

d0105는 같은 사람, d0106·d0107은 다른 사람이라는 저장 답을 fingerprint로 검증했다. 과거 분석에서 d0105의 겹침을 ID 전환으로 의심했지만, 사람 답을 우선하여 이 지점은 분리하지 않았다. 위치 흔들림과 ID 혼동은 구별해야 한다.

원본 추적 파일 SHA-256과 질문 생성 당시 기록, 두 사진의 상자 좌표가 일치함을 확인한 뒤 별도 결과 파일에만 적용했다. d0106의10817과 d0107의585를 각각 확인된 경계에서 분리했다. 이 숫자는 이 저장 영상의 ID이므로 라이브의 같은 숫자 ID에 재사용하지 않는다.

팀 답은 직접 저장된3개를 해당 프레임에 반영했다. d0105의 B팀 답은 같은 사람이라고 확인한 반대쪽 사진에도 적용해4개 프레임의 팀 근거를 확보했다. 원본 답을 만들어 저장하거나, 다른 사람인 반대쪽 사진으로 팀 답을 복사하지 않았다. 전체 트랙으로 자동 확장하지도 않았다.

후반1740–2916초를 동일 보정과 LiveAnalyzer로 재계산했다. 두 경계의 잘못된 동일ID 연결은2→0, 추적 조각 수는587→589다. 이것은 검토한 지점의 수정 성과이며 독립 평가 정확도가 아니다. 코칭은 전후 모두44개(수비선10,상대침투4,고립4,침투5,박스공격14,라인간격7)였다. 전역 ID 정확도나 코칭 정답률 향상은 입증하지 못했다.

기존 분류·질문·답 JSON 해시를 비교해 변경이 없음을 확인했다. 새 결과는 `work/reviewed-breaks-eval-20261113-v2/tracks.json`, 비교는 같은 폴더의 `comparison.json`이다. 모델 가중치 학습·운영 적용·서버 재시작은 하지 않았다.

재현: 프로젝트 Python으로 `scripts/evaluate_reviewed_breaks.py ../../work NEW_OUTPUT_DIRECTORY` 실행. 출력 폴더가 존재하면 거부한다. 관련 회귀 테스트7개 통과.
