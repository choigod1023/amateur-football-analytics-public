# 정답 상자로 탐지·추적 병목 분리 (2026-11-15)

탐지 재학습만으로 해결되지 않는 추적 병목을 확인했다. 완벽한 상자 입력을 가정해도 BYTETracker 5Hz에서는 정답 관측의 50.8%만 현재 추적 결과로 나온다. 15Hz는 77.4%로 늘지만, 연속 관측에서 ID가 바뀌는 비율이 29.7%로 여전히 높다. 운영 변경이나 개선 완료를 주장하지 않는다.

## 고정 조건과 정답 점검

AI Hub 305/306 영상 각각 0–30, 300–330, 600–630초, 30Hz 원본에서 5Hz로 450프레임씩 채점했다. 15Hz 조건은 실제 존재하는 추가 정답 프레임으로 업데이트하고 같은 5Hz 프레임에서 채점했다. 보간 정답은 없다. 총 900 평가 프레임, 18,112명-프레임이다. 기존 raw 추적 baseline의 영상·라벨 SHA256, 구간, 평가 FPS를 검증했다.

정답 상자의 신뢰도를 1로 고정하고 class=0으로 넣었다. 정답 ID·팀은 추적 입력에 포함하지 않았고 채점에만 사용했다. BYTETracker 설정은 기존 high/new=.12, low=.06, match=.98, fuse_score=True를 유지했다. 15Hz에서는 buffer를 50에서 150으로 바꿔 보존 시간을 유지했다. 각 구간마다 추적 상태를 초기화했다.

라벨의 playerInfo/player_sid는 인물 명단을 가진 지속 ID 구조다. 필요한 프레임의 중복 ID·누락 프레임을 검사했다. 305의 프레임 0, 30, 9000에 실제 영상 위 정답 상자를 그려 인물과 위치가 맞는지 확인했고, 0→30의 동일 ID 이동을 확인했다. 이는 모든 ID의 전체 구간 정확도를 보증하지 않는다. 306 전체 정체성의 수동 검수는 하지 않았다.

실제 현재 입력은 Ultralytics 결과 row[7]의 detection index를 검증한 뒤 해당 프레임 입력과 연결했다. 정답 ID로 연결을 선택하지 않았다. 예측 상자와 관측 상자의 차이만으로 5Hz 미출력 전체를 설명할 수 없다. index 기반 비교는 상자 IoU 오차를 제거한 연결 진단이며, 실제 탐지기 정확도 수치가 아니다.

기존 방식의 IDSW 합은 baseline 3,271, oracle5 5,101, oracle15 5,410이다. 관측 수가 크게 달라 단순 합의 감소율을 개선율로 쓰면 안 된다. 표의 연속 ID 변경 분모는 앞뒤 평가 프레임 모두 출력된 동일 GT 인물이다. 이 분모도 조건별 생존 대상이 달라 완전히 동등한 조건부 정확도 비교는 아니다.

추가 조건은 한 번만 실행한 BoTSORT + sparseOptFlow, ReID 없음이다. BYTE15보다 미출력이 987건 늘었다. ID 변경 비율 소폭 감소만으로 채택하지 않았다. 카메라 보정 알고리즘과 Kalman 상태 표현이 함께 달라졌으므로 GMC 단독 인과 효과도 아니다. 동일 자료로 다음 개발 방향을 찾은 진단이며 새로운 독립 검증이 아니다.

## 시간과 한계

두 영상 합 BYTE5 1.91초/900 업데이트, BYTE15 6.31초/2700 업데이트: 탐지와 영상 디코딩 제외, 추적·채점만 측정했다. BoTSORT15는 45.96초/2700 업데이트: 영상 디코딩·GMC·채점 포함, 탐지 제외다. 이 시간으로 실서비스 처리율을 주장하지 않는다.

평가는 기존 greedy IoU>=0.5 진단이며 공식 HOTA/IDF1이 아니다. 미매칭 탐지를 오탐으로 단정하지 않는다. 동일 GT 상자가 여러 번 겹치는 등 라벨 문제 가능성은 남는다. 영상은 주간 중계 구도이며 사용자의 야간 고정 카메라 성능으로 일반화하지 않는다.

## 미출력 원인의 실행 확인

동일 GT 입력을 다시 실행해 각 평가 프레임의 `tracker.tracked_stracks` 중 `is_activated=False`를 집계했다. BYTE5 미출력 8,920건과 미확정 트랙 8,920건, BYTE15 미출력 4,091건과 미확정 트랙 4,091건이 각각 정확히 일치했다. 즉 상자 입력 누락이 아니라 새 트랙의 다음 관측 확인을 기다리는 상태에서 현재 결과에서 제외된다. 왜 기존 ID 연결에 실패해 새 트랙이 되었는지는 겹침·기하 gating·카메라 이동을 추가 분해해야 한다. 모든 미확정 트랙을 즉시 노출하면 해결된다는 뜻은 아니며 실제 탐지의 오탐을 함께 검증해야 한다.

## 다음 개선 대상

1. 탐지 단계와 별개로 업데이트 주기를 확보하고 이동·급격한 구도 변화에서 새 트랙이 확인되지 못해 탈락하는 원인을 추적한다.
2. 현재 측정 상자와 필터 예측 상자를 분리해 평가한다. 위치가 틀린 예측을 미니맵에 유지하는 방식은 채택하지 않는다.
3. 고신뢰 현재 관측의 초기화·확인 정책을 고정하고 실제 탐지 입력에서 미출력과 오탐/오연결을 함께 검증한다. 정답 상자 실험 성공을 배포 근거로 쓰지 않는다.
4. 검증된 짧은 구간에서 정체성 수동 정답을 추가하고 HOTA/IDF1 및 중복·오연결을 별도 측정한다. 이미 받은 사용자 답은 변경하지 않았다.
