# 선수 탐지 누락과 ByteTrack 저신뢰 연계 시험

기존 파노라마 타일 경로는 YOLO의 `confidence=0.35`로 박스를 잘라 ByteTrack에 넘긴다. 설치된 ByteTrack 기본값은 high 0.25, low 0.1이다. 따라서 기존 입력에는 0.1~0.35 박스가 없어 낮은 점수의 탐지를 기존 궤적에 다시 연결하는 2차 단계가 사실상 작동하지 못한다. [ByteTrack 원 논문 구현과 설명](https://github.com/FoundationVision/ByteTrack)은 이 단계를 낮은 점수 때문에 짧게 사라진 대상의 연결에 활용한다. 타일 추적에서만 선택적 `bytetrack_low_score_recovery: true`를 설정하면 검출 최저 점수를 0.1로 낮추되, 높은 점수 연계와 새 트랙 생성 기준은 기존 confidence로 둔다. 기본값은 꺼져 있다. 동영상 전체 추적 경로는 변경하지 않는다. 이 프로젝트의 실제 추적기 구현은 설치된 Ultralytics에 의존하며 그 라이선스를 별도 준수해야 한다. 공식 ByteTrack/BoT-SORT 코드를 가져오지 않았다.

## 다른 경기만 사용한 학습과 현재 영상 평가

이전 영상 전용 가중치는 이번 목표인 독립 경기 평가에 쓸 수 없어 범용 YOLO11n 사전학습 가중치부터 CPU 3에폭을 학습했다. 훈련은 AI Hub 경기 310·781·113·131·103·151·10·106·1의 정답 상자가 있는 51프레임, 개발 검증은 별도 AI Hub 318의 6프레임이다. 목표 영상인 SoccerTrack 20200220과 그 라벨은 이번 모델의 학습과 개발 검증에 넣지 않았다. 선수·심판 등 사람 상자를 한 클래스로 학습했으며 역할·팀 모델은 아니다. 프레임 수가 적고 같은 경기에서 추출한 프레임끼리 상관돼 성능 보장은 없다. 원본·라벨·가중치는 로컬의 `work/byte-tracker-new-training`에만 둔다. 사용권은 데이터와 가중치 각각 확인해야 한다.

개발 경기 318에서 IoU 0.5 매칭 F1을 기준으로 탐지 문턱값 0.95를 선택한 후 목표 영상의 60~90초 구간에 적용했다. 이 경기 영상은 과거 프로젝트 탐색에 사용됐으므로 최종 블라인드 시험은 아니다. 각 구간 50개 연속 프레임의 정답은 1,100개, 인접 프레임은 같은 선수의 반복이다. 예측 중 매칭되지 않은 박스에는 누락된 주석·심판·매칭 실패도 포함될 수 있어 모두 오탐으로 단정하지 않는다.

| 시작 프레임 | 방식 | 정답 기준 매칭 | 예측 기준 매칭 | 재등장 ID 변경/재등장 |
|---|---|---:|---:|---:|
| 100 | 범용 YOLO, 기존 0.35 | 180/1100 (16.36%) | 180/555 (32.43%) | 2/22 |
| 100 | 9경기 모델 0.95 | 545/1100 (49.55%) | 545/1106 (49.28%) | 2/45 |
| 100 | 9경기 모델 0.95 + 저신뢰 연계 | 624/1100 (56.73%) | 624/1268 (49.21%) | 4/31 |
| 350 | 범용 YOLO, 기존 0.35 | 540/1100 (49.09%) | 540/961 (56.19%) | 4/38 |
| 350 | 9경기 모델 0.95 | 562/1100 (51.09%) | 562/1137 (49.43%) | 3/50 |
| 350 | 9경기 모델 0.95 + 저신뢰 연계 | 663/1100 (60.27%) | 663/1380 (48.04%) | 2/40 |

여기서 재등장 ID 변경은 정답 선수와 IoU 매칭이 한 번 이상 끊긴 뒤 다시 매칭됐을 때 이전 추적 ID가 달라진 횟수다. 인접 처리 프레임의 ID 변경은 별도로 센다. 모두 표준 IDF1/HOTA가 아니고 추적이 실제로 사라진 이유를 구분하지 못한다. 저신뢰 연계로 매칭이 늘었지만 일부 구간에서 미매칭과 ID 오류도 늘었다. 실제 미니맵의 선수 유지와 팀 분류 개선을 보장하지 않는다.

25fps 원본에서 3프레임마다 한 장을 처리한 30개 프레임의 모의 드롭 시험에서는 범용 0.35의 정답 매칭이 97/660→135/660, 예측 기준 97/247→135/294였다. 9경기 모델 0.95는 332/660→369/660, 예측 기준 332/641→369/709였다. 9경기 모델의 재등장 ID 변경은 11/40→11/31이었다. 이는 파일 프레임을 일정 간격으로 건너뛴 실험이며 SRT 패킷 손실·지연 변화·실제 아이폰 송출을 재현한 것은 아니다.

과잉 탐지도 확인했다. 타깃 한 프레임을 여러 타일로 검출했을 때 9경기 모델은 conf≥0.1 상자 627개를 내고 그중 63개가 0.8 이상이었다(범용 모델은 각각 26개, 1개). conf=0.35에서 50프레임 정답 1,100개에 대한 트랙이 10,467개 나와 그대로 적용할 수 없었다. AI Hub 훈련의 프레임 수와 광각 도메인 차이 등이 가능성이지만 원인은 확정되지 않았다. 이 모델과 옵션은 실험으로만 남기며 자동 배포하지 않는다.

한 경기 적응 가중치를 이어서 3에폭 더 학습한 별도 실험은 현재 타깃의 두 구간에서 confidence 0.35 이상 트랙이 0개였다. 해당 가중치는 현재 경기에서 학습됐으므로 독립 평가에도 부적합하며 사용하지 않는다. 한 타깃 프레임의 전체 타일 confidence 최대값은 기존 전용 모델 0.879, 추가 학습 모델 0.170이었다. 개발 경기 이미지에서는 같은 가중치가 mAP50 0.408을 보여 개발 점수만으로 현장 사용을 판단할 수 없음을 보여준다.

후속으로 경기 단위로 서로 다른 광각·주야간 샘플과 역할 정답을 확보해 MOT 표준 HOTA/IDF1, 누락/재등장 ID 교체, 팀 오분류 및 실제 SRT 지연을 함께 평가한다. [BoT-SORT](https://github.com/NirAharon/BoT-SORT)는 운동과 외형 정보를 함께 쓰는 공개 대안이며 [스포츠 궤적 재연결 연구](https://openaccess.thecvf.com/content/ACCV2024W/MLCSA2024/html/Sun_GTA_Global_Tracklet_Association_for_Multi-Object_Tracking_in_Sports_ACCVW_2024_paper.html)는 앞뒤 tracklet을 연결한다. 어느 방법도 현장 이전을 검증하기 전 운영 정확도로 추정하지 않는다.

재현은 준비된 로컬 `independent-dataset`과 원본 범용 `yolo11n.pt`를 인자로 `python scripts/train_other_games.py --dataset <폴더> --pretrained <원본.pt> --project <별도_실험_폴더>`를 실행한다. 파일명·개수와 YAML 경로를 확인하지만, 이름만으로 영상 내용의 출처나 가중치의 학습 이력을 증명하지는 못한다. 학습·검증 원본의 실제 출처 및 모델 해시를 별도 기록해야 한다. 기존 설정을 수정하거나 모델을 자동 전환하지 않는다.
