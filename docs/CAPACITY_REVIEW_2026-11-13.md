# 12명 초과: 실제 영상 원인과 운영 적용 판정

## 범위와 정답 보존

현재 운영의 60초 재생 파일 `work/live-dashboard-validation-20261113/replay-1950-2010.mp4` 및 완료된 run73/74를 사용했다. 원본 경기 1950~2010초이며 새 학습/평가 영상으로 간주하지 않는다. 기존 사람 답은 학습된 역할·팀 모델과 별도 홀드아웃 평가에 활용했다. 현재 60초 구간의 사람별 정답은 찾지 못했으므로 과거 다른 시각의 답을 현재 ID의 정답으로 복사하지 않았다.

## 실제 원인

- 같은 60초에서 팀별 11명 초과는 54프레임이다. 강한 상자 포함(작은 상자의 80% 초과)은 그중 51.8초와 53초 두 프레임뿐이다. 나머지를 단순 중복으로 삭제하면 실제 겹친 선수를 잃을 위험이 있다.
- 32.6초 ID430은 문맥 크롭에 여러 선수가 보이지만 실제 상자 경계는 가운데 인물에 해당한다. 중복 확정이 아니라 팀 분류 확인 대상이다. 문맥 크롭을 실제 탐지 상자로 오해하지 않도록 경계를 다시 그려 확인했다.
- 51.8초 ID998은 여러 사람을 둘러싼 큰 상자, ID748은 하체 옆 잔디 쪽 작은 상자였다. 동일 모델·타일·확률 설정으로 두 프레임을 다시 추론했다. ID998의 추적 상자와 현재 검출 상자의 최대 IoU는 0.252/0.224였다. 큰 상자는 현재 검출 모양 자체가 아니라 추적 상태에서 변형된 것이다. 동시에 하체·잔디 영역의 실제 검출 오탐도 있었다. 분류·발 좌표에 추정 상자를 사용하는 문제와 검출 오류가 겹친다.
- 기존 TeamVotes는 확률·마진을 보지 않고 argmax를 계속 누적하며 동률을 보류하지 않는다. 가림·ID 혼동 뒤에도 과거 팀 표가 남는다.

## 수정 후보와 결과

`--guard-team-votes`는 최근 15개 관측, 확률 0.5/마진 0.1, 최소 3표/2분의 3 동의를 시험한다. 현재 불확실하거나 겹친 상자는 과거 팀으로 확정하지 않는다. 기본값은 꺼져 있다.

run73의 기존 분류·위치 후보 5,241개에서 초과는 54→0프레임이지만, **1,011개(19.3%)를 보류하고 153개는 팀이 달라졌다.** 선수들을 제외한 결과이므로 성공으로 판정하지 않았다. 재학습 후보 모델도 1,003개 보류로 비슷했다.

기존 홀드아웃 136개에서 기존 모델과 재학습 모델 모두 125개 정답이다. 확신 기준 적용 시 기존 모델은 132개 수락 중 122개 정답으로, 오답 1개와 정답 3개를 함께 제외한다. 독립 경기 성능이나 시간적 추적 정답을 입증하지 못한다.

같은 저장 좌표에 분류 후보를 넣은 코칭 비교도 실행했다. 기존은 3초 박스 침투/25초 수비선 관측 변동, 후보는 30초/38초에 같은 종류의 알림이 나왔다. 생성 건수는 모두 2건이다. 검출을 새로 수행한 비교가 아니며 미분류로 선수 배치가 바뀐 결과일 수 있어 코칭 개선으로 인정하지 않았다.

`--observed-detection-boxes`는 트래커가 반환한 현재 검출 인덱스로 분류·위치용 상자만 실제 검출 상자로 교체한다. 트래커 상태와 ID는 바꾸지 않는다. 인덱스 중복·범위·유한값을 검증하고 원본 추적 상자와 교체한 상자를 기록한다. 과거 상자 기준 사람 재연결 답은 다시 검증해야 하므로 `--reviewed-links-store`와 함께 실행할 수 없다. 기존 답은 삭제하지 않는다. 이 옵션도 기본값은 꺼져 있다.

첫 상자 교체 구현으로 동일 60초 GPU 추론을 다시 수행했다. 원래 BYTETracker 출력은 **300프레임 모두 일치**했다. 그러나 교체한 상자가 후속 IdentityGuard에도 들어가 별도 세그먼트 ID가 달라지는 결합이 있었다. 인원 초과는 54→48, 동일 ID 팀 변경은 11→13, 위치 거부는 117→149, 표시 대상 고유 ID는 56→74로 변했다. 알림은 2→3건이지만 개선으로 인정하지 않았다. 이 구현은 그대로 운영에 적용하지 않는다. 실행 당시 운영 분석과 테스트가 함께 실행되어 처리시간은 공정한 속도 비교가 아니다. 원시 로그는 `work/capacity-observed-boxes-20261113`에 있다.

후속 수정에서는 원래 상자로 IdentityGuard와 재연결을 먼저 수행하고, 마지막에 분류·위치용 상자만 바꾸었다. `--observation-box-mode shape-outliers`로 폭/높이 차이가 2배를 초과하는 관측만 바꾸어 60초를 다시 분석했다. 42개 관측 상자가 교체됐고, 원래 추적 결과와 IdentityGuard 사건은 각각 300프레임 모두 일치했다.

| 동일 60초 새 추론 | 운영 기준 | 후속 상자 수정 |
|---|---:|---:|
| 팀별 인원 초과 프레임 | 54 | 54 |
| 같은 ID 팀 변경 | 11 | 11 |
| 분류·위치 대상 고유 ID | 56 | 56 |
| 위치 거부 | 117 | 118 |
| 생성 코칭/진단 알림 | 2 | 2 |

미니맵 표시의 사라짐은 277→277, 재등장은 243→241이었다. 단, 후보는 과거 상자에 의존하는 사람 재연결 alias를 제외했으므로 이 두 번 차이를 개선으로 인정하면 안 된다. 이 수정은 과도한 상자 변형을 제한하지만 현재의 팀별 인원 초과와 코칭 단절은 해결하지 못했다. 후속 결과는 `work/capacity-shape-boxes-20261113/comparison.json`이다. 현재 검출 역시 오탐일 수 있으며 시간 투표에 이미 쌓인 잘못된 소속까지 자동으로 바로잡지는 못한다.

## 사람이 확인할 항목

공개 `/train`에 새 질문만 추가했고 자동 답은 저장하지 않았다.

| 장면 | 경기 시각 | 확인 대상 |
|---|---|---|
| 130 | 33:02.6 | ID430의 역할·팀 |
| 131 | 33:18.4 | ID259의 역할·팀 |
| 132 | 33:18.4 | 원거리 ID909의 역할·팀 |
| 133 | 33:21.8 | ID998·748 상자가 사람에 해당하는지, 중복·잘못된 상자인지 |

중앙 장면과 기존 확대 기능은 공개 API에서 확인했다. 앞뒤 확대 이미지 15장은 `work/capacity-review-published-20261113`에 준비했지만 현재 공개 훈련 페이지에는 중앙 장면만 표시된다. 답한 뒤 이 장면은 학습·디버깅 자료이며 독립 평가에서 제외해야 한다. 원래 답 JSON 910개 SHA-256을 전후 비교했고 변경은 0개였다.

## 적용 판정

분류 후보는 현재 운영 적용 기준을 통과하지 못했다. 인원 초과 감소만으로 실제 선수 보존·팀 정확도·코칭 정확도를 대신할 수 없다. 따라서 모델/운영 설정/프로세스는 교체하지 않았고, 질문 추가만 운영 페이지에 반영했다. 사람 답이 필요한 부분을 숨기거나 임의로 확정하지 않았다.

재현 도구: `scripts/audit_team_vote_confidence.py`, `scripts/compare_capacity_coaching.py`, `scripts/prepare_capacity_review.py`. 실험 출력과 영상·개인 답은 Git에 넣지 않는다.

검증은 전체 Python 테스트 543개 통과·1개 건너뜀, 마지막 순서 분리/형상 제한 수정 뒤 관련 회귀 테스트 36개 통과다. 질문 페이지 HTTP 200과 공개 API의 4장면·5대상 노출을 확인했다. 최종 확인 당시 새 질문의 저장 답은 모두 0개였으며 사람의 판단을 기다린다. 중복·그림자 답은 현재 4종 역할 모델의 팀 정답으로 강제 변환하지 않고 탐지/추적 오류 평가에 사용해야 한다.
