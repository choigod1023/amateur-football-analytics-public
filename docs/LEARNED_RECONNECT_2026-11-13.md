# 사람 답변을 학습한 재연결 검증 — 2026-11-13

## 결론과 운영 결정

사용자가 확인한 장면 ID를 외우는 방식과 별도로, 원본 인물 크롭의 특징을 학습하는 재연결 모델을 구현했다. 학습하지 않은 다른 경기에서 9건을 자동 연결했고 8건은 정답, 1건은 다른 선수였다. ID 변경은 1635→1626으로 9건(0.55%) 감소했다. 개선 폭이 작고 오연결이 남아 **운영 모델로 승격하지 않았다.** 기존 수동 확인 기반 재연결과 운영 서버는 변경하거나 재시작하지 않았다. 이번 모델은 탐지기 자체를 재학습한 것이 아니다.

## 학습 자료와 방법

- 사용자 답변 d0105–d0110 중 장면 경계와 원본 크롭을 검증할 수 있는 6쌍: 같은 선수 3쌍, 다른 선수 3쌍.
- 이전 전체 트랙 단위 답변 39건은 내부 ID 전환 때문에 끝점의 인물이 답변과 일치한다고 보장할 수 없어 이번 학습에서 제외했다. 답변을 삭제하거나 수정하지 않았다.
- 전반·후반·잘라낸 클립 모두 `own-match-20261111` 하나의 경기 그룹으로 묶었다.
- 확대 사진의 노란 표시가 아닌 원본 프레임 크롭을 사용했다. 답변 SHA256, 현재 질문 fingerprint, 원본 프레임 SHA256을 재확인했다.
- 상·하의 HSV 색 분포 차이 6개, 키 비율 변화, 경과 시간으로 정규화한 이동 거리, 시간 간격을 입력으로 정규화된 로지스틱 분류기를 학습했다. 선수 ID·장면 ID는 입력하지 않는다.
- 연결 점수 0.90 이상, 차순위와 차이 0.15 이상, 최대 공백 2.5초를 평가 전에 고정했다. 점수는 보정된 동일인 확률이 아니다.
- 이미 관측한 트랙의 마지막 관측과 새 트랙만 비교한다. 동시에 나타난 선수·경쟁하는 연결은 보류하며, 새 탐지 상자나 화면 밖 좌표를 만들지 않는다.

## 분리 평가

AI Hub 다른 경기 `aihub-match-337`의 0–30초, 300–330초, 600–630초를 고정해 총 90초, 5fps 450프레임을 평가했다. 해당 경기는 과거 역할 분류 평가에 사용했지만 이번 재연결 학습과 임계값 결정에는 사용하지 않았다. 정답은 채점에만 사용했다. 평가 결과를 보고 임계값을 조정하지 않았다.

YOLO11n, 전체 화면 imgsz=1280, conf=0.1, ByteTrack으로 얻은 동일한 탐지·추적 결과에 세 방법을 적용했다. 인위적으로 탐지를 삭제하는 시뮬레이션은 사용하지 않았다.

| 진단 지표 | 기존 ByteTrack | 거리 기반 재연결 | 답변 학습 재연결 |
|---|---:|---:|---:|
| ID 변경 | 1635 | 1582 | 1626 |
| 새 연결 | 0 | 109 | 9 |
| 맞는 연결 | 0 | 32 | 8 |
| 다른 선수 연결 | 0 | 67 | 1 |
| 정답 대응 불가 연결 | 0 | 10 | 0 |
| 탐지 누락 뒤 같은 ID로 복귀 | 169 | 198 | 174 |
| 탐지 누락 뒤 다른 ID로 복귀 | 1189 | 1160 | 1184 |
| 정답과 대응한 관측 | 2988 | 2988 | 2988 |
| 놓친 정답 관측 | 6599 | 6599 | 6599 |
| 정답에 대응하지 못한 탐지 | 898 | 898 | 898 |

횟수는 선수 수가 아닌 시간에 따른 관측/전환 수다. IoU≥0.5 탐욕 대응 진단이며 공식 HOTA·IDF1이 아니다. 미대응 탐지에는 정답에 없는 사람이 포함될 수 있으므로 898건을 전부 오탐이라고 부를 수 없다. 재연결기는 상자를 추가하지 않아 탐지 수가 같으며, **탐지 오탐 감소는 입증하지 못했다.** 주간 다른 경기 하나로 야간 경기 일반화도 입증하지 못한다.

잘못된 연결은 617.6초의 정답 ID 25와 619.0초의 ID 24였다. 실제 크롭을 확인하면 두 선수 모두 비슷한 밝은 유니폼을 입었다. 색상과 단일 끝점만으로 개인을 구별하기 어렵다는 실패 사례다. 거리 방식은 ID 변경을 더 줄였지만 다른 선수 연결이 67건이므로 운영에 부적합하다. ID 변경 수만 낮추는 것을 성공으로 취급하지 않는다.

## 재현과 증거 위치

작업 루트의 `work/learned-reconnect-20261113/`에 원본 자료와 산출물을 보관한다. 데이터·답변·영상·모델은 Git에 넣지 않는다.

- `train-pairs.json`: 학습 6쌍과 답변/프레임 해시
- `model.json`: 평가 전에 고정한 모델
- `model-revalidated.json`: 현재 답변/질문을 재검증해 재학습한 결과, model.json과 바이트 단위 동일
- `heldout-final/comparison.json`, `events.json`, `trace.json`: 실제 실행 비교 및 연결별 증거
- `wrong-join.jpg`: 잘못 연결한 두 정답 인물의 실제 크롭
- `published/publication.json`, `page-check.json`: 질문 게시·응답 확인
- 최초 실행은 NumPy 점수 JSON 직렬화 오류로 산출물 저장 중 실패했다. float 변환과 회귀 테스트를 추가한 뒤 `heldout-final`에 전체 재실행했다. 처음 계산한 수치와 동일했다.

프로젝트 가상환경 Python으로 실행한다. OUTPUT과 MODEL은 기존 파일이 없는 새 경로를 지정한다.

```powershell
python scripts/train_reconnect_scorer.py TRAIN_MANIFEST MODEL
python scripts/evaluate_learned_reconnect.py VIDEO TRACK_JSON MODEL YOLO_WEIGHTS OUTPUT --group aihub-match-337
python -m pytest -q
```

평가기는 학습 경기 그룹과 같은 `--group`을 거부한다. 그룹명은 파일 이름이 아니라 실제 경기 단위로 관리해야 한다. 전체 테스트 472개 통과·1개 건너뜀 이후 직렬화 회귀 테스트를 추가했고, 해당 모듈 5개 테스트를 재실행해 모두 통과했다.
