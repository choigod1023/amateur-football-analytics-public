# 알림과 전술 조언의 타당성 검증: 수집, 학습, 검증 계획 (2026-11-17 제안)

목적: 코치용 알림 화면과 전술 조언이 "실제로 맞고 쓸모 있는지"를 확인하려면 어떤 자료를 모으고 무엇을 학습하고 어떻게 검증해야 하는지 정리합니다. 근거: 이 프로젝트의 판정 기록(`live-feedback.md`, `live-service-audit.md`)과 웹 조사(아래 출처). 웹 출처의 수치는 2차 요약이며 원문은 확인하지 못했습니다.

## 검증해야 할 세 가지 질문
1. 측정이 맞는가: 선수 위치(검출, 팀 분류, 경기장 좌표)가 실제와 맞는가. 현재는 사람이 확인한 상자 116개 등으로 검출만 점검했고, 미터 단위 위치 오차는 재지 않았습니다.
2. 알림이 정의대로인가: "이 순간이 박스 침투가 맞는가". 사용자님 판정(ok, wrong, useless)으로 측정 중이며 후반은 전부, 전반은 14/61만 판정됐습니다.
3. 조언이 타당하고 쓸모 있는가: 그 상황이 실제 결과(슛, 실점)와 관련이 있는가, 코치가 동의하고 행동하는가. **현재 가장 비어 있는 부분**입니다.

## 조사로 알게 된 것
- 알림이나 전술 조언을 코치 합의도로 검증한 공개 연구는 찾지 못했습니다(검색 한계 있음). 코치 20명이 경기 통계 변수를 검증한 연구는 있습니다([Frontiers 2019](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2019.01339/epub)). 코치 앞 운영 타당성은 열린 문제라고 스스로 밝힌 논문도 있습니다([arXiv 2601.00421](https://arxiv.org/html/2601.00421v1)). 따라서 우리가 직접 코치 검토를 해야 합니다.
- 수비 성공과 가장 관련 있는 값은 공 근처 수비수의 조밀함과 수비 라인의 상대 높이, 공간 점수였고, 팀 전체의 조밀함은 거의 차이가 없었습니다(분데스리가 153경기 [Forcher 외 2024](https://cir.nii.ac.jp/crid/1360861403644016128), 라리가 2,413 수비 장면 [arXiv 2511.06191](https://arxiv.org/pdf/2511.06191), 프리프린트). 해석: 우리 `gap_wide`(팀 전체 줄 간격)는 문헌 근거가 약하고, `line_drop`(라인 높이 변화)은 근거가 더 가깝습니다. 공 근처 값은 공 정보가 있어야 만들 수 있어, 공 추적이 조언의 타당성 쪽에서는 우선순위가 올라갈 수 있습니다.
- 위 연구의 결과 지표는 "수비 성공"이며 슛 허용이나 xT가 아닙니다. 프로 경기이고 우리는 아마추어 11대11이라 그대로 옮길 수 없습니다.

## 학습할 것 (검출 모델 말고)
- 지금은 학습보다 **기준값 확정**이 먼저입니다. 알림 판정이 종류별 20개 이상 쌓이기 전에는 규칙을 학습으로 대체하지 않습니다.
- 판정이 200개 이상 모이면 "이 알림은 ok일 확률" 소형 모델(입력: 간격, 변화량, 보인 선수 수, 직전 알림 간격, 경기 단계)로 약한 알림을 거르는 방법을 시험할 수 있습니다. 현재 61개는 부족합니다.
- 공개 추적 자료로는 임계값(예: 박스 안 3명, 14m 하락)이 프로 기준에서 결과와 연결되는 지점을 찾아 아마추어 값과 비교하는 정도로 씁니다.

## 검증 단계와 통과 기준 (제안, 근거 없는 임의 기준이므로 조정 가능)
1. 위치: 미터 오차를 재서 알림 기준 값의 절반 이하일 것.
2. 규칙 타당성(공개 자료): 알림 뒤 슛이나 박스 진입 비율이 기준 비율의 1.5배 이상이거나 방향이 문헌과 일치. 미달인 종류는 회색 또는 끔.
3. 사용자님 판정: 종류별 20개 이상에서 맞음 80% 이상. 미달은 "참고용" 표시를 유지하거나 끔.
4. 코치 검토: 코치 2명 이상, 종류별 "말해 줄 가치 있음" 60% 이상, 두 코치의 일치율 확인.
5. 현장: 실제 송출에서 지연과 복구 확인(`live-operations-research.md` 9절).
6. 경기 후 추적: 코치가 알림에 반응한 기록과 결과를 여러 경기에서 누적.

## 우선순위 (제안)
1. 공개 추적 자료로 규칙 타당성 시험(사용자님 일 없음, GPU 불필요, 이용 조건 확인 후).
2. 전반 알림 판정 20개(`gap_wide`, `line_drop` 우선)와 선택 태그 추가.
3. 코치 검토 세션 준비(카드 30개 구성).
4. 다른 경기 영상 촬영.

## 자동 처리와 불확실할 때만 사람 확인 방식의 선행 사례 (2026-11-17 웹 조사)
요약: 방식 자체는 흔하지만(대부분 업체 글), 우리 상황(야간 휴대폰 영상, 작은 선수)의 정밀도를 보고한 자료와 검증된 전술 알림 탐지 오픈소스는 찾지 못했습니다. 수치는 원문을 확인하지 못한 2차 요약입니다.
- 신뢰도 기준 분류: 신뢰도가 낮은 상자만 사람에게 보내고 다시 학습하는 반복([Roboflow 사람 참여 글](https://blog.roboflow.com/human-in-the-loop-ai/), [Superb AI](https://superb-ai.com/blog/auto-labeling-data-workflow/)). 상자 위치 불확실성으로 사람의 주의를 이끄는 논문([arXiv 2605.12303](https://arxiv.org/pdf/2605.12303), 코드는 [프로젝트 페이지](https://mos-ks.github.io/MUHA/)). Ultralytics 강의는 신뢰도가 높다고 검수를 건너뛰면 모델의 체계적 오류가 고정된다고 경고합니다(이 프로젝트의 자동 수락 상자 검수 규칙과 같은 이유).
- 큰 모델로 라벨을 만들어 작은 모델에 옮기기: Autodistill(Grounding DINO 등이 라벨, YOLO가 학습, [PyPI](https://pypi.org/project/autodistill), [Roboflow 글](https://blog.roboflow.com/autodistill/)). 이 프로젝트의 yolo11x에서 yolo11n으로 옮기는 방식과 같은 구조입니다. 사람 검출 정밀도 수치는 찾지 못했습니다. 모델 이용 조건은 확인하지 않았습니다.
- 비전 언어 모델을 심판으로 쓰기: 점수 구간을 보정해서 구간이 좁으면 자동 처리, 넓으면 사람에게 보내는 방식([arXiv 2604.25235](https://arxiv.org/pdf/2604.25235)). 사람 라벨 품질이 좋을수록 구간이 좁아지고, 보정에 쓴 사람 라벨의 편향은 고치지 못한다고 합니다. 알림 검증에 쓴 사례는 찾지 못했습니다.
- 전술 알림 탐지: unravelsports(압박 강도, 대형 탐지), DataBallPy(자료 정리), OpenSTARLab(이벤트 예측과 라벨링 도구)이 있으나 침투와 라인 간격 알림을 사람 합의로 검증한 오픈소스는 찾지 못했습니다. 우리 규칙은 직접 검증해야 합니다.

적용(제안): ① 사람이 판정한 120개(person-check)가 이미 정답이므로, 큰 검증 모델(Grounding DINO, SAM, 비전 언어 모델 등)이 이 판정과 얼마나 일치하는지 측정해 제3의 심판으로 쓸 수 있는지 확인합니다(새 라벨링 없음, 모델 내려받기와 이용 조건 확인 필요). ② 사람은 자동 수락 상자의 무작위 표본(30개)과 심판들이 갈린 경우만 확인하고, 표본 정밀도의 신뢰구간 하한이 95% 미만일 때만 늘립니다.

## 결과 1: 공개 추적 자료로 알림 규칙 타당성 시험 (2026-11-17, Metrica 샘플 1, 2경기)
방법: `scripts/research_rule_validity.py`. 정확한 위치(초당 5회로 줄임)를 운영과 같은 임계값의 `LiveAnalyzer`에 넣고(경기장 105 x 68m, 공격 방향은 킥오프 때 서 있는 쪽으로 정함), 알림 뒤 N초 안에 슛이 났는지 센 비율을 같은 팀과 시간대의 모든 초에서 슛이 날 평소 비율과 비교했습니다. 공격 알림(box_attack, run, isolated)은 그 팀의 슛, 수비 알림(conceded_run, line_drop, gap_wide)은 상대의 슛이 기준입니다. 자료는 `work/public-data-20261117/metrica`(내려받은 원본, 재배포하지 않음).
| 알림 | 알림 수 | 30초 안에 슛 | 평소 비율 | 배수 | 15초 / 60초 배수 | 경기별 일관성 |
|---|---|---|---|---|---|---|
| box_attack | 140 | 37 (26%) | 6% | 4.1 | 6.0 / 2.9 | 두 경기 모두 높음(3.3, 4.9) |
| run | 242 | 28 (12%) | 6% | 1.9 | 2.5 / 1.6 | 1.4, 2.6 |
| conceded_run | 259 | 33 (13%) | 6% | 2.1 | 2.8 / 1.6 | 1.8, 2.5 |
| isolated | 107 | 11 (10%) | 6% | 1.6 | 1.8 / 1.3 | 2.5, 0.8로 불안정, 유의하지 않음 |
| line_drop | 149 | 11 (7%) | 6% | 1.2 | 1.1 / 1.2 | 1.6, 0.9, 유의하지 않음 |
| gap_wide | 88 | 2 (2%) | 6% | 0.37 | 0.37 / 0.65 | 0.40, 0.34 (평소보다 슛이 적게 뒤따름) |
- 해석: box_attack, run, conceded_run은 슛과 뚜렷하게 관련이 있어 규칙이 의미 있다는 근거가 있습니다(15, 30, 60초 모두, 두 경기 모두). isolated와 line_drop은 약하거나 경기마다 달라 근거가 부족합니다. **gap_wide는 알림 뒤에 상대 슛이 평소보다 오히려 적습니다**(배수 0.34~0.65). 팀 전체 줄 간격은 위험 신호가 아니라는 문헌([Forcher 외 2024](https://cir.nii.ac.jp/crid/1360861403644016128): 팀 전체 조밀함은 수비 성공과 관련 없음)과 사용자님 판정(gap_wide 틀림 40%)과 일치합니다.
- 한계: 슛 약 48개(두 경기), 프로 경기와 105 x 68m 경기장이라 우리 아마추어 경기에 그대로 옮길 수 없습니다. 알림이 시간상 모여 있어 p 값은 거친 참고입니다. box_attack은 슛 장면의 일부라 슛이 뒤따르는 것이 당연한 면이 있어 "미래를 예측한다"가 아니라 "규칙이 의미 있다"는 증거입니다. 이 시험은 위치가 정확할 때의 규칙 타당성이며, 우리 영상의 위치 오차는 포함하지 않습니다.
- 결과 파일: `work/public-data-20261117/metrica_validity_{15,30,60}.json`.
- 제안(사용자님 결정 필요): gap_wide를 기본으로 끄거나 "참고용"으로 눌러 놓기, line_drop과 isolated도 같은 취급, box_attack, run, conceded_run은 유지. SkillCorner 10경기(슛 약 260개)로 같은 시험을 반복해 표본을 늘릴 수 있습니다(이용 조건 `data-licenses.md` 5절).

## 결과 2: SkillCorner 20경기 반복 시험 (2026-11-17)
- 방법: `scripts/research_rule_validity_skillcorner.py`. 호주 A리그 공개 자료 20경기(팀 기준 20경기분, 슛 526개), 10 Hz 추적을 5 Hz로 줄여 운영과 같은 기준의 LiveAnalyzer에 입력(모든 알림 종류 켬). 슛은 `player_possession`의 `end_type == shot`. 결과 파일: `work/public-data-20261117/skillcorner_validity_{15,30,60}.json`.
- 30초 기준 평소의 몇 배(경기별로 평소보다 높은 경기 수): box_attack 3.17배(20/20), conceded_run 2.19배(20/20), run 2.11배(20/20), line_drop 1.40배(13/20), isolated 1.42배(14/20), gap_wide 0.39배(0/20).
- 15초와 60초에서도 방향이 같다. gap_wide만 모든 창에서 평소보다 낮다(0.42, 0.50).
- 결론: Metrica 결과가 재현되었다. gap_wide는 위험 신호가 아니므로 기본 끔(`DISABLED_KINDS`, 2026-11-17 적용). line_drop과 isolated는 약한 양의 관계라서 "참고용" 유지.
- 한계: 프로 리그, 방송 추적(화면 밖 선수는 추정 위치), 알림이 시간상 서로 이어져 있어 p값은 참고용, box_attack은 슛 장면의 일부.
- 같은 날 공격 방식별 시험(`scripts/research_phase_outcomes.py`): SkillCorner의 공격 단계 종류와 수비 블록 종류가 1대1로 묶여 있어 "방식 x 블록" 표는 독립 정보가 아니다. 포메이션 상성 분석은 위치 자료에서 포메이션을 직접 계산해야 가능하다(미완료).
- 수준별 전술 조사: `wiki/level-tactics-research.md`.
