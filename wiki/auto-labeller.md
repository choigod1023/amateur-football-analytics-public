# 자동 라벨러 ("AI 침팬지")

작성 2026-11-16. 근거: `app/auto_labeller.py`, `scripts/auto_labeller.py`, `tests/test_auto_labeller.py`, 결과 `work/auto-labels-20261116/` (`evaluation.json`, `judge.json`, `candidates.jsonl`, `manifest.json`).
사람이 판정한 값과 자동 판정은 섞지 않습니다. 자동 라벨은 `work/auto-labels-20261116/`에만 있고 항목마다 `origin: auto_labeller`가 붙습니다. 사람 라벨 저장소의 기존 파일은 건드리지 않았고, `/alerts`에는 새 세션 `person-check3`만 추가했습니다. 영상과 이미지는 외부로 보내지 않았고 로컬 모델(ft_n2, yolo11x, 로컬에 있던 resnet18 가중치)만 썼습니다.

## 무엇을 하는가
1. 후보: ft_n2와 yolo11x 중 한쪽만 찾은 상자(점수 0.25~0.6)를 모읍니다 (`build_person_check.py`와 같은 방식).
2. 판정기: 사용자님이 판정한 상자(person-check1과 2, 120개 중 시험 장면 앞뒤 15초 안의 15개를 뺀 105개, 사람 72개)로 학습한 로지스틱 회귀입니다. 특징은 어느 모델이 찾았는지와 점수, 상자 높이와 가로세로 비율, 화면 위치, 형광 비율과 어두운 비율, 선명도와 대비, 주변과의 색 차이, 녹색 비율, resnet18 임베딩(주성분 6개)입니다.
3. 세 단계: 자동 수락, 자동 기각, 사람 확인 필요. 점수가 0.35~0.45가 아니거나 두 모델이 모두 찾은 상자에는 판정기를 적용하지 않고 전부 사람 확인으로 보냅니다(사람이 판정한 구간이 이 점수대뿐이기 때문입니다).

## 교차검증 결과
방법: 120초 단위 시간 구간이 같은 쪽에 묶이도록 6겹으로 나눕니다(23개 구간). 수락과 기각의 문턱은 각 겹의 학습 부분 안쪽 교차검증으로만 정하고 시험 부분에는 적용만 합니다(중첩 방식).
표본: 105개(사람 72개, 비율 69%). 작은 표본이므로 아래 수치는 오차가 큽니다.

| 특징 | AUC | 세 단계 결과 (수락: 사람 수/수락 수, 기각: 사람 아님 수/기각 수, 사람 확인) |
|---|---|---|
| 검출 모델 정보만 (점수, 누가 찾았나) | 0.71 | 수락 5~14개, 기각 0개, 사람 확인 88~100개 |
| 영상 특징만 | 0.92 | 수락 47/49, 기각 14/17, 사람 확인 39 (λ=1) |
| 영상 특징 + 검출 모델 정보 | 0.91 | 수락 47/49, 기각 21/23, 사람 확인 33 (λ=1) |
| 영상 특징 + 검출 모델 정보 + resnet18 (채택) | 0.93 | 아래 표 |
| resnet18만 | 0.89 | 수락 27/30, 기각 22/24, 사람 확인 51 (λ=1) |

(λ는 규제 세기. 모든 설정을 출력해 두었고 채택 설정은 교차검증 AUC가 가장 높은 것으로 골랐으므로 약간 낙관적입니다.)

채택 설정(영상 특징 + 검출 모델 정보 + resnet18, λ=1)의 수락 목표별 결과 (시험 부분에서 잰 값):

| 수락 문턱을 정하는 안쪽 목표 | 자동 수락 | 수락 중 실제 사람 | 정밀도 | 95% 신뢰 하한 | 자동 기각 | 기각 중 사람 아님 | 사람 확인 필요 |
|---|---|---|---|---|---|---|---|
| 95% | 60 | 56 | 93.3% | 84.1% | 27 | 24 (88.9%) | 18 |
| 98% | 36 | 36 | 100% | 90.4% | 27 | 24 (88.9%) | 42 |
| 100% | 36 | 36 | 100% | 90.4% | 27 | 24 (88.9%) | 42 |

- 안쪽 목표 95%로는 시험 부분의 정밀도가 93.3%로 목표 95%에 못 미쳤습니다. 그래서 규칙대로 더 엄격한 98%를 써서 36/36을 얻었습니다. 이 선택(세 가지 중 하나 고르기)은 같은 시험 결과를 보고 한 것이라 낙관적입니다. 신뢰 하한이 90%라서 "수락 정밀도 95% 이상"은 **통계적으로 확인되지 않았습니다**.
- 최종 판정기(`judge.json`)는 안쪽 목표 98%로 정한 수락 문턱 0.937과 기각 문턱 0.228입니다. 기각 정밀도 88.9%는 목표 90%에 약간 못 미칩니다(기각은 사람을 놓칠 뿐 학습에 틀린 상자를 넣지 않으므로 수락보다 덜 위험합니다).
- 판정된 105개 기준으로 자동으로 정해진 것은 63개(수락 36, 기각 27), 사람 확인 필요는 42개(40%)입니다. 사람 판정 부담은 약 60% 줄어듭니다.

## 새 프레임에 적용한 결과 (50프레임, GPU 약 1분)
- 후보 103개 중 판정기를 적용할 수 있는 것(점수 0.35~0.45)은 33개뿐이었습니다. 나머지 70개는 점수 범위 밖이라 전부 사람 확인으로 남았습니다.
- 적용 범위 33개: 수락 11, 기각 7, 사람 확인 15. 즉 범위 안에서는 55%를 자동으로 정했지만, **후보 전체로 보면 자동으로 정한 것은 18/103(17%)**입니다. 실제 사람 부담 감소는 17%이고, 판정 범위를 넓혀야 커집니다.
- 수락 11개는 `work/auto-labels-20261116/labels/`에 YOLO 형식(프레임 전체 좌표)으로 저장했습니다. 프레임의 나머지 사람은 라벨이 없는 부분 라벨입니다.
- 사람 확인 후보 40개(범위 안 15개를 먼저)를 `/alerts`의 `person-check3`에 올렸습니다.
- 수락 11개의 정확도는 사람이 확인하지 않았습니다. `person-check3`에서 판정하신 것과 겹치지 않으니, 수락된 상자 일부를 사람이 검수해야 위 정밀도가 새 프레임에서도 맞는지 알 수 있습니다.

## 한계
- 훈련 표본이 105개이고 전부 한 경기, 점수 0.35~0.45의 "한쪽만 찾은 상자"입니다. 다른 점수대, 두 모델이 모두 찾은 상자, 다른 경기와 카메라에는 적용할 수 없습니다.
- resnet18 주성분은 라벨을 쓰지 않고 판정된 상자 전체로 한 번 구했습니다(라벨 누설은 아니지만 시험 부분의 사진도 포함).
- 판정 데이터에 같은 선수가 연속 프레임에 나올 수 있습니다. 120초 단위로 묶었지만 같은 장면이 이웃 구간에 걸칠 수 있습니다.
- 카메라 구간 경계를 바로잡아(cam2 약 1495~1735초 제외) 이 도구는 cam2 프레임을 쓰지 않습니다 ([detector-experiments.md](detector-experiments.md)의 알려진 문제 참고).
- 수락 문턱은 후보의 점수 분포가 판정 때와 같다고 가정합니다. 검출기가 바뀌면 다시 학습하고 다시 재야 합니다.

## 자동 수락 상자를 학습에 쓸 때의 위험
- 이전 두 번의 의사 라벨 재학습은 개선되지 않았습니다 ([detector-experiments.md](detector-experiments.md)). 같은 이유(모델이 쉽게 맞히는 상자만 늘어 편향, 틀린 상자가 정답이 됨, 프레임의 다른 사람이 배경으로 학습됨)가 이 도구에도 있습니다.
- 수락 상자는 두 검출기 중 하나는 이미 찾은 상자라서 "검출기가 놓친 사람"의 대표가 아닙니다. 판정기가 영상 모양과 점수로 정한 것이라 새로운 종류의 놓친 사람은 늘리지 못할 수 있습니다.
- 권고(절차): (1) 자동 수락 상자를 학습에 쓰기 전에 무작위 표본 30개 이상을 사람이 검수해서 수락 정밀도를 다시 잰다(95% 미만이면 쓰지 않는다). (2) 부분 라벨 프레임은 상자가 있는 조각만 쓰고, 다른 조각은 배경으로 쓰지 않는다(`build_pseudo_tiles.py`의 방식). (3) 시험은 항상 사용자님이 그린 상자와 시험 구간으로 한다. (4) 학습에 쓴 자동 라벨은 사람 라벨과 따로 보관한다.

## 사용법
```
python scripts/auto_labeller.py evaluate --video <영상> --store <검토 저장소> --out work/auto-labels-20261116
python scripts/auto_labeller.py run --video <영상> --store <검토 저장소> --out work/auto-labels-20261116 --weights-a <ft_n2.pt> --weights-b <yolo11x.pt> --frames 50 --seed 33 --session person-check4
```
- `evaluate`는 CPU로 약 1분입니다. `run`은 50프레임에 GPU를 약 1분 씁니다.
- 판정이 쌓이면(person-check3 등) `scripts/auto_labeller.py`의 `ANSWERS` 목록에 답 파일을 추가하고 `evaluate`를 다시 돌립니다. 판정 답 파일은 `build_person_check.py`가 만든 `spots.json`과 판정 라벨을 합친 형식입니다(`work/person-check*-answers.json`).
