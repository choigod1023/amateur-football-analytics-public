# 외부 검증 모델(자동 심판) 시험 (2026-11-17)

목적: 사용자님이 "AI가 자동으로 처리하고 오탐이 많아 보일 때만 사람이 확인"하는 구조를 원하셔서, 이미 사람이 판정한 상자 120개(`work/person-check1-answers.json`, `person-check2-answers.json`: 사람 82개, 사람 아님 38개)를 정답으로 삼아 외부 모델이 같은 판정을 하는지 쟀습니다. 후보는 한쪽 검출기만 찾은 상자(점수 0.35~0.45 범위, 두 검출기는 ft_n2와 yolo11x)입니다. 정답 라벨은 모델에 보이지 않고 점수 계산 뒤에 비교했습니다.

## 방법과 파일
- 판정 상자 주변 160픽셀 창을 4배 확대해 자르고(`scripts/dump_verifier_crops.py`), 별도 환경 `work/verifier-20261117/venv`(운영 환경과 분리)에서 점수를 매깁니다(`scripts/score_verifiers.py`, CPU). 채점: `scripts/eval_verifiers.py`(전체 AUC와 수락, 기각 규칙). 정직한 평가는 기존 `app/auto_labeller.nested_evaluation`(시간 120초 구간 묶음 6겹, 문턱은 학습 쪽에서만 정함).
- 모델과 이용 조건(모델 카드): Grounding DINO tiny(IDEA-Research), OWLv2 base(Google), SigLIP base(Google) 모두 apache-2.0 ([data-licenses.md](data-licenses.md) 5절). 학습 없이 그대로(제로샷) 썼습니다. 점수 파일 `work/verifier-20261117/scores.json`.

## 결과 (120개, 시간 구간 묶음 교차 검증)
| 심판 | AUC | 수락(수락 중 실제 사람, 95% 하한) | 기각(기각 중 사람 아님) | 사람 확인 필요 |
|---|---|---|---|---|
| 검출 점수만 (기준선) | 0.44 | | | |
| 기존 자동 라벨러 판정기(학습함, 105개, [auto-labeller.md](auto-labeller.md)) | 0.93 | 36/36 (90%) | 24/27 | 42개(40%) |
| Grounding DINO | 0.93 | 64/66 (90%) | 17/20 | 약 34개(28%) |
| OWLv2 | 0.97 | 76/78 (91%) | 34/38 | 4개(3%) |
| OWLv2 + Grounding DINO | 0.96 | 79/80 (93%) | 35/38 | 2개(2%) |
(수락 목표 98%, λ=1 설정. 수락 목표 95%에서는 79/82와 78/82로 하한 88~90%.)
- 해석: 외부 모델은 우리 라벨로 학습하지 않고도 기존 학습 판정기와 같거나 더 좋은 구분 능력을 보였고, 사람이 봐야 하는 비율이 40%에서 약 2~3%로 줄었습니다. 기각에서 놓친 사람은 3개(35/38 기각 중 사람 아님 35개).
- SigLIP(작은 상자를 잘라 "사람 사진인가"를 묻는 방식, 전체 120개): AUC 0.40으로 쓸모없음(우연 수준 이하). 키 20픽셀 안팎의 흐린 상자는 상자만 잘라서는 구분이 안 되고, 주변 장면 전체를 보는 검출형 모델(OWLv2, Grounding DINO)만 통했습니다. 채택하지 않습니다.

## 한계 (낙관 요인)
- 표본 120개, 한 경기, 한 가지 상자 종류(한쪽 검출기만 찾은 0.35~0.45 점수대)입니다. 다른 점수대, 두 검출기가 모두 찾은 상자, 다른 경기에는 적용할 수 없습니다.
- 설정 12가지(모델 조합 3 × 수락 목표 2 × λ 2)를 같은 시험으로 비교했고 가장 좋은 것을 소개했으므로 낙관적입니다. 수락 정밀도의 95% 하한이 90~93%로 학습 자료 기준인 95%에 못 미칩니다. **새 프레임에서 수락 상자의 표본 검수 30개 이상이 있어야 학습에 쓸 수 있습니다**(CLAUDE.md 규칙).
- 판정된 120개는 사람이 그 상자를 사람으로 볼 수 있는지 본 것이어서, 사람이 몰려 있는 박스 안 같은 장면에서의 성능은 알 수 없습니다.
- 심판이 찾은 상자는 두 검출기 중 하나가 이미 찾은 것이라, 모든 검출기가 놓친 사람을 새로 찾지는 못합니다(대량 실행에서 학습 자료에 넣을 때의 한계는 [auto-labeller.md](auto-labeller.md)와 동일).

## 대량 후보에 적용 (2026-11-17)
- 컴퓨터 전원이 갑자기 꺼져(Kernel-Power 41, 오류 코드 없음, 11월 12일 두 번 포함 6일 사이 3번째) 점수 계산이 한 번 중단되었고, `scripts/score_verifiers.py`에 10개마다 중간 저장을 넣어 다시 했습니다. 이후 GPU와 CPU 작업을 동시에 돌리지 않습니다.
- 대상: 1회차(`work/auto-labels-bulk-20261116`)와 2회차(`work/auto-labels-round2-20261117`)의 후보 중 검증된 범위(점수 0.35~0.45, 한쪽 검출기만 찾음) 283개. 범위 밖 후보는 근거가 없어 적용하지 않았습니다(사람 확인 그대로).
- 기준: 사람이 판정한 120개로 OWLv2와 Grounding DINO 점수 두 개의 로지스틱 모델을 맞추고(`scripts/apply_verifiers.py`), 처음에 문턱을 판정 120개로 고르면 수락과 기각이 같은 값(0.79)이 되어 사람 확인 구간이 없어집니다. 새 자료에서는 위험하므로 수락 확률 0.9 이상, 기각 0.2 이하로 넓은 확인 구간을 두었습니다(교차 검증에서 수락 64/65, 기각 31/33, 사람 확인 22개, 문턱을 더 엄격히 해도 수락 오류 1개는 그대로라 정밀도가 좋아지지 않음).
- 결과(283개): 수락 138(1회차 92, 2회차 46), 기각 86, 사람 확인 59. 기존 자동 라벨러와 비교: 둘 다 수락 52, 기존 수락이 새 방식에서 확인 필요로 17 또는 기각으로 4, 기존 확인 필요였던 154개 중 83개 수락 31개 기각, 기존 기각 중 3개가 수락. 판정이 갈린 쪽이 누가 맞는지는 사람 확인 전이라 모릅니다.
- 결과 파일: `work/auto-labels-verifier-20261117/` (`decisions.jsonl` origin verifier_owl_gdino, `judge.json`, `summary.json`). 기존 자동 라벨 파일은 건드리지 않았습니다.
- 수락 상자 표본 검수: `/alerts`의 `person-check5`에 30개를 올렸습니다(`scripts/review_verifier_accepted.py`, 시드 33). 30개 이상에서 정밀도 95% 이상이어야 학습에 쓰고, 미달이면 쓰지 않습니다.
