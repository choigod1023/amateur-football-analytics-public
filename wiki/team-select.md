## 2. 설계
1. 시작 후 처음 약 10초 동안 초당 한 프레임의 사람 상자를 모읍니다(`scripts/team_select_prepare.py`). 보정이 있으면 경기장 안만 씁니다.
2. 상자 상의의 색을 Lab 색 공간의 값 세 개(밝기, a, b)로 바꿉니다. 상의 영역의 중앙값이고 잔디색 픽셀은 뺍니다. 키 30픽셀 이상 상자만 씁니다.
3. 색 값을 두 무리로 나눕니다(`split_teams`). 두 무리 어디에도 가깝지 않은 사람(심판, 골키퍼 등)은 "따로 둔 사람"으로 뺍니다. 두 무리가 서로 가까우면 "색이 비슷합니다" 경고를 같이 보입니다.
4. 코치가 `/team-select`에서 무리별 선수 사진 3장을 보고 "왼쪽이 우리 팀입니다" 또는 "오른쪽이 우리 팀입니다"를 누릅니다. 이어서 한 줄 확인("우리 팀은 사진 왼쪽 어두운 색 옷 팀입니다. 맞습니까?")에서 "맞습니다"를 누르면 저장됩니다. 사진 사이에 새 사진이 만들어졌으면 저장을 거절합니다.
5. 저장 위치는 `<저장소>/service/team_profile.json`입니다(두 무리의 대표 색과 퍼짐, 따로 둔 사람의 색, 고른 날짜와 문장). 중간에 전원이 꺼져도 깨지지 않도록 임시 파일에 쓴 뒤 바꿉니다.
6. 라이브 실행은 `--team-profile <파일>`을 받아 고른 팀은 `--team` 글자, 상대는 다른 글자로 표를 셉니다. 프로필이 있으면 학습 모델과 고정 색 규칙은 팀 글자에 쓰지 않습니다. 옵션을 주지 않으면 기존 동작 그대로입니다(시험으로 확인). 옵션을 줬는데 파일이 없으면 조용히 예전 방식으로 가지 않고 멈춥니다. 파일이 깨졌어도 마찬가지입니다.
7. 저장된 선택을 지우는 단추("예전 방식으로 돌아감")가 있습니다.

사용 순서(코치): ① 킥오프 직후 `python scripts/team_select_prepare.py <영상 또는 스트림> --store <저장소> --start <초> --seconds 10 --calibrations <보정> --camera cam1` → ② 서버의 `/team-select`에서 한 번 고르기 → ③ `run_live_feedback.py ... --team-profile <저장소>/service/team_profile.json`. 운영 서버(8443)는 건드리지 않았고, 서버 경로는 새 파일 `app/team_select_routes.py`와 `review_public.py`의 두 줄(가져오기와 설치)로 추가했습니다. 운영 서버에 반영하려면 사용자님이 재시작을 승인하셔야 합니다.

## 4. 후반 "팀 색 재확인" 띠와 잇는 방법
- 지금 띠(`web/watch-banner.js`의 colour 띠, `app/halftime_report.py`의 `colour_checked`)는 후반 전환 뒤 "두 팀이 옷 색대로 나뉘어 표시되는지 화면에서 확인해 주세요"라고 묻고 "확인했음"을 받습니다. 그 파일들은 다른 세션이 쓰므로 건드리지 않았습니다.
- 후반에 팀은 진영만 바꾸고 옷은 그대로이므로 프로필은 그대로 유효합니다. 옷을 갈아입었을 때만 다시 골라야 합니다.
- 연결 제안(그 세션 담당): ① 띠 문장 뒤에 `/team-select` 링크("옷이 바뀌었으면 다시 고르기")를 넣습니다. ② 후반 전환 직후 몇 초의 선수 색으로 `profile_fit(프로필, 색 목록)`을 계산해 "한쪽 팀이 4명 미만이거나 색으로 나뉘지 않은 사람이 절반을 넘으면" 띠를 빨갛게 하고 링크를 겁니다(함수는 `app/team_color_profile.py`에 있고 시험했으나, 띠와는 연결하지 않았습니다). ③ 다시 고른 뒤 `team_profile.json`이 바뀌면 라이브 실행을 다시 시작해야 합니다(실행 중에는 파일을 다시 읽지 않습니다).

## 5. 한계와 남은 일
- 이 경기에서는 학습 모델이 더 정확합니다. 프로필은 새 옷에서 쓰는 길이고, 정확도 비교는 한 경기와 합성 색뿐입니다.
- 실제 다른 경기, 실제 조끼, 낮 경기(그림자, 햇빛)는 못 재 봤습니다. 키 30픽셀 미만 선수는 색이 불안정합니다.
- 심판과 골키퍼는 "색이 두 팀과 멀면 불명"으로만 다룹니다. 골키퍼는 원래 이 경기에서도 따로 취급해야 하는데 이번 작업에서는 다루지 않았습니다. 어두운 심판이 우리 팀 무리에 섞일 수 있습니다.
- 라이브 실행 중 프로필을 다시 읽지 않습니다. 표를 세는 방식(트랙마다 3번 이상 같은 쪽)은 그대로입니다.
- 오프라인 추적, 보고서 글자와 색, 화면 문구, `startup_check`, 놓친 장면 수집은 아직 이 경기 색 가정입니다(1절 표).
- 전체 시험 모음 미실행, 서버 경로는 시험용 앱에서만 확인했고 운영 서버에서는 확인하지 못했습니다.

원칙: 추적 파일과 사람 라벨이 쓰는 글자(우리 팀 B, 상대 A)는 그대로 두고, 프로필은 "어느 상자가 어느 글자를 받는가"와 "코치가 읽는 글자와 그림 색"만 정합니다. 옵션을 주지 않으면 모든 스크립트가 기존 글자와 색 그대로입니다(시험으로 확인).

### 6-1. 연결한 곳 (모두 옵션 `--team-profile <team_profile.json>`)

### 6-2. 못 고친 곳 (그대로 이 경기 색 가정)
- `app/hard_frames.py`(놓친 장면 세션 담당이라 건드리지 않음): 형광은 A, 어두운 옷은 B로 셈(13, 37-39행 부근). 고치려면 `OfflineTeams(profile).letter_of_box`로 바꾸고 `--team-profile`을 받으면 됩니다.
- `app/auto_labeller.py`: 팀 구분이 아니라 "사람인가" 판정이고, 형광과 어두운 비율은 그 판정의 입력 특징 중 하나입니다. 다른 옷에서 정확한지는 못 쟀고, 그대로 두었습니다.
- `app/team_role_features.py`와 학습 모델(`model.pt`): 형광 범위와 어두운 비율이 특징에 고정이고 클래스가 한 경기 색으로 학습됐습니다. 모델 확률을 프로필로 덮는 방식으로 우회했으며 재학습은 안 했습니다.
- `scripts/startup_check.py`, `scripts/build_event_candidates.py`, `scripts/add_review_scenes.py`, `scripts/build_goal_check_video.py`: 손대지 않음.
- 사람 판정 화면 `web/training-label.js`(/train, /alerts): 지침대로 건드리지 않음. 형광 조끼를 팀 A로 추천하는 문구와 "팀 A/팀 B" 의미는 이 경기의 사람 라벨과 같아야 해서 그대로입니다(추천일 뿐 저장은 사람이 정합니다).
- 보고서 문장(`app/review_text.py` 등)에 들어 있는 "우리 팀"은 원래 있던 글자이고 B팀을 가리킵니다. 프로필 없이 `--team A`로 만든 보고서의 "우리 팀"은 이 작업과 상관없이 맞지 않습니다.
- 실제 영상과 `ffmpeg`로 보고서 전체를 만들어 글자를 눈으로 확인하는 시험은 못 했습니다(단위 시험으로 글자 만들기와 색 바꾸기만 확인).

### 6-3. 시험 1: 이 경기 한 구간의 오프라인 실행 (측정, CPU)
`work/detection-cache-20261112/half1_cam1`의 64~124초(300프레임)를 `track_from_cache.py`로 세 가지로 돌렸습니다. 프로필은 라벨 저장소 35장면으로 만든 것입니다(사람이 우리 팀 쪽을 고른 것으로 간주). 정답이 아니라 기존 모델 결과와의 일치입니다.
| 실행 | A 행 / B 행 / 불명 | 기존 모델 결과와 팀 글자가 같은 행 |
|---|---|---|
| 기존(프로필 없음) | 3162 / 2959 / 727 | - |
| fallback | 2759 / 3166 / 929 | 5171 / 5394 (95.9%) |
| profile | 2547 / 3221 / 1075 | 4966 / 5282 (94.0%) |
- 관중(S)과 심판(R) 행 수는 모델과 같게 유지됩니다(처음 만든 버전은 확률을 0.6으로 끌어올려 관중 2960행이 1268행으로 줄고 심판이 플레이어가 되는 오류가 있어 고쳤고, 시험으로 막았습니다).

### 6-4. 시험 2: 팀 글자 정확도, 프로필 대 모델 대 합치기 (측정, CPU, 사용자님 라벨 기준)
표본: 라벨 저장소 35장면에서 키 30픽셀 이상인 우리 팀과 상대 팀 선수 상자 291개(이전 절의 531개보다 적음: 작은 상자를 뺐습니다). 장면 안 상자는 독립이 아닙니다. 합성 조끼는 5절과 같은 덧칠(한 가지 색)이라 실제 조끼보다 쉽습니다. 표의 칸은 [정답 / 오답 / 불명]이고, 프로필은 한 번에 35장면으로 만든 것(pooled)입니다. 장면 하나로 만든 프로필을 다른 장면에 쓴 값(상자 7,000개 안팎)은 결과 파일에 있고 순서는 같았습니다.
| 상황 | 프로필만(그림) | 프로필만(캐시 색) | 학습 모델만 | fallback(프로필 먼저) | model_first(모델 먼저) |
|---|---|---|---|---|---|
| 이 경기 실제 옷 | 254 / 14 / 23 | 254 / 12 / 25 | 286 / 1 / 4 | 277 / 14 / 0 | 289 / 2 / 0 |
| 상대가 파란 조끼 | 274 / 0 / 17 | 276 / 0 / 15 | 139 / 0 / 152 | 275 / 0 / 16 | 275 / 0 / 16 |
| 상대가 빨간 조끼 | 288 / 0 / 3 | 282 / 0 / 9 | 141 / 0 / 150 | 289 / 0 / 2 | 289 / 0 / 2 |
| 상대가 흰 조끼 | 288 / 0 / 3 | 281 / 0 / 10 | 148 / 0 / 143 | 290 / 0 / 1 | 290 / 0 / 1 |
| 상대가 짙은 회색 | 278 / 4 / 9 | 278 / 4 / 9 | 146 / 0 / 145 | 286 / 4 / 1 | 290 / 0 / 1 |
| 상대가 주황 조끼 | 285 / 0 / 6 | 284 / 0 / 7 | 224 / 0 / 67 | 291 / 0 / 0 | 291 / 0 / 0 |
| 우리 팀이 주황 조끼 | 290 / 0 / 1 | 290 / 0 / 1 | 142 / 16 / 133 | 290 / 1 / 0 | 275 / 16 / 0 |
| 우리 팀이 흰 조끼 | 287 / 0 / 4 | 288 / 0 / 3 | 142 / 1 / 148 | 290 / 0 / 1 | 289 / 1 / 1 |
- **주의: 이 경기 실제 옷에서 학습 모델의 값은 학습에 쓴 장면을 그대로 잰 것이라 낙관적입니다.** 장면 하나씩 빼고 검증한 정직한 값은 오답 2.3%(3-1절)입니다. 위 표에서 이 경기 모델 오답 1개(0.3%)는 그 값이 아닙니다. 프로필은 이 경기의 옷으로 학습한 적이 없어 비교가 공정하지 않다는 점은 그대로 남습니다.
- 이 경기에서 프로필만 쓰면 오답이 14개(4.8%)입니다(3-1절의 8.7%보다 낮은 것은 작은 상자를 뺐기 때문). 프로필 색을 캐시의 평균 색으로 읽어도 거의 같습니다(12개 오답).
- fallback(프로필이 정하고, 애매할 때만 모델)은 합성 조끼 7가지 모두에서 오답 0~4개(1.4% 이하)로 프로필만 쓴 것과 같거나 불명이 줄어 좋습니다. 이 경기에서는 프로필의 오답 14개가 그대로 남습니다.
- model_first(모델 먼저)는 이 경기와 대부분의 합성에서 가장 좋지만, 우리 팀이 주황 조끼를 입으면 오답 16개(5.5%)로 나빠집니다. 학습 모델이 그 옷을 몰라서 틀리는데 그래도 확신하기 때문입니다.
- 모델이 이 옷을 아는지 스스로 알아내는 규칙(프로필이 정한 상자 중 모델이 팀을 답한 비율이 0.9 이상이면 모델 먼저, 아니면 fallback)은 **라벨된 선수 상자에서는** 이 경기 0.985(상자 268개), 합성 7가지 0.49~0.76으로 갈라졌고 `auto` 열이 모든 상황에서 둘 중 좋은 쪽을 골랐습니다. 하지만 **실제 캐시의 날것 검출에서는 갈라지지 않습니다**: 이 경기 자신의 캐시(12개 조각, 키 30픽셀 이상의 경기장 안 상자 64,626개)에서 모델이 팀을 답한 비율은 56%이고, 큰 상자는 24%나 6%입니다(큰 상자를 모델이 관중이라고 부르기 때문). 그래서 이 규칙은 스크립트에 연결하지 않았고(`app/profile_teams.py`의 `choose_mode`는 시험용으로만 남김), 캐시용 기본은 fallback으로 했습니다. 다른 옷의 실제 영상으로 기준을 다시 잡아야 합니다(못 했습니다).
- 결론: **새 경기(다른 옷)는 `--team-profile`과 기본 fallback**, 이 경기를 다시 돌릴 때만 프로필 없이 기존 모델이나 `--profile-mode model`이 낫습니다. 프로필 점수와 모델 점수를 연속값으로 섞는 방식은 시험하지 않았습니다(두 점수의 척도가 달라 보정 자료가 필요합니다).
