# 코치용 벤치 화면 (최소판)

근거: `wiki/live-operations-research.md` R2, R3, R4, `wiki/coach-operating-guide.md`. 만든 날 2026-11-16. 코드: `app/bench_view.py`, `web/bench.html`, `web/bench.js`, `web/bench.css`, 라우트 등록(`app/review_public.py`에 4줄), 시험 `tests/test_bench_view.py` (8개 통과, 전체 pytest 402개 통과).

## 사용법
- 검토 서버가 켜져 있으면 태블릿(가로)이나 노트북 브라우저에서 `/bench`를 엽니다. 서버는 이 화면을 위해 새로 시작할 필요가 없지만, 파이썬 코드가 바뀌었으므로 **운영 중인 서버에는 재시작해야 반영됩니다** (재시작은 사용자님 승인 사항, 이번 작업에서는 하지 않았습니다).
- 라이브 실행을 `--store <저장소>`로 돌리면 `<저장소>/alerts/<세션>/alerts.jsonl`에 알림이 쌓이고, 화면은 1초마다 `GET /api/v1/bench`로 가장 최근 알림을 읽습니다. 가장 최근에 바뀐 **실시간 세션**(사진 판정용 `person_check` 세션은 제외)을 자동으로 고르고, `?session=이름`으로 고를 수도 있습니다.
- 화면 구성: 위쪽 상태 띠(입력 정상, 입력 없음, 입력 상태 모름, 화면 연결 끊김), 가운데 큰 글씨 알림 하나(우선순위 배지, 알림 나이 초 단위 증가, 제목, 한 줄 문구, 이 종류의 판정 근거), 오른쪽 이전 알림 5개.
- 읽기 전용입니다. 이 경로에는 쓰기가 없고(POST는 405), 판정 데이터는 이 컴퓨터 밖으로 나가지 않습니다.

## 우선순위 (R3의 표를 따름)
| 색 | 의미 | 종류 | 근거 |
|---|---|---|---|
| 빨강 급함 | 지금 행동 | 상대 침투 허용, 박스 침투, 입력 없음 | 위키 R3: 빨강은 상대 침투 허용과 박스 침투 |
| 노랑 주의 | 곧 필요 | 고립된 공격수, 수비 라인 뒤 침투(우리 침투) | 고립은 R3의 노랑. **우리 침투는 표에 없어서 제가 노랑으로 정했습니다** (위험이 아니라 곧 쓸 기회이기 때문, 사용자님이 바꿀 수 있음) |
| 회색 참고 | 참고만 | 라인 간격, 라인 하락, 모르는 종류 | R3: 정확도가 낮은 두 종류(라인 간격 3/6, 라인 하락 1/3)는 회색 |

매핑은 `app/bench_view.py`의 `PRIORITY` 한 곳에 있습니다.

## 종류별 맞은 비율
- `alerts/labels/`의 사용자님 판정을 종류별로 세어 "판정 n개 중 m개 맞음"으로 표시합니다. 판정이 5개 미만이면 "표본 적음"을 붙여 노랑 글씨로 보여 줍니다(임의의 퍼센트는 쓰지 않음, R4).
- 사진 판정 세션(`person_check`)과 입력 상태 행의 판정은 세지 않습니다.
- 위키 R4는 n이 10 미만이면 "참고용"이라고 했습니다. 이번 지시는 5개 미만이어서 5로 구현했고, 바꾸려면 `MIN_SAMPLE`을 고칩니다.

## 입력 상태
- `alerts.jsonl`의 상태 행(`kind`가 `no_input`이면 끊김, `input_back`이면 복구; `app/live_input.py`)을 따릅니다. 끊김이 마지막이면 빨간 띠와 "입력 없음"이 나옵니다.
- 하트비트 행(`type` 또는 `kind`가 `heartbeat`)이 있으면 10초 넘게 새 행이 없을 때 "입력 없음"으로 바꿉니다. 아직 하트비트를 쓰는 실행이 없으므로 이 부분은 시험(단위 시험)으로만 확인했습니다.
- 하트비트 행이 없으면 "입력 상태 모름"(노랑 띠)으로 보이고 알림 파일의 마지막 변경 시각을 함께 보여 줍니다. **알림이 없는 시간이 길어도 입력이 끊긴 것은 아닙니다.** 그래서 이 경우 "정상"이라고 쓰지 않습니다.
- 화면 자체가 서버 응답을 5초 넘게 못 받으면 "화면 연결 끊김"(빨강)과 마지막 확인 시각을 보여 주고 마지막 값을 흐리게 유지합니다.

## 한계와 아직 안 한 것
- 알림 나이는 서버가 그 줄을 처음 본 시각부터 셉니다. 서버가 켜지기 전에 이미 있던 줄은 파일의 마지막 변경 시각을 쓰므로 "시간 추정"이라고 표시합니다. 알림 줄에 실제 시각(벽시계)이 없어서(`time`은 영상 초) 생기는 한계이며, 라이브 실행이 벽시계 시각을 줄에 쓰면 정확해집니다.
- 15초가 지난 알림은 흐리게 표시합니다(위키 R3의 자동 폐기를 간단히 옮긴 값, 근거는 제안값).
- 소리와 진동, 푸시(SSE), 지연 초와 보정 상태 표시, 알림 문구 개선은 하지 않았습니다. 문구는 지금 알림 파일의 문구를 그대로 보여 줍니다(문구 수정은 다른 작업에서 진행).
- 접근 제어가 없습니다(검토 서버와 같음). 같은 무선망 안에서만 쓰는 것을 전제로 합니다.
- 확인한 것: 단위 시험과 라우트 시험, 별도 포트의 임시 서버(복사한 저장소)에서 브라우저 화면 확인(정상, 흐림, 입력 없음, 화면 연결 끊김). 확인하지 못한 것: 실제 태블릿, 실제 라이브 실행과의 연결, 장시간 가동.
