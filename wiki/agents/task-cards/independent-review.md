# 작업 카드: 다른 하위 작업 결과 검수 (independent-review)

경로 (Git bash에 먼저 붙여 넣음):
```
R=<REPO_DIR>
W=<WORK_DIR>/work
PY=<WORK_DIR>/outputs/football-coach-server/.venv/Scripts/python.exe
```

## 언제 쓰는가
영상, 리뷰 페이지, 장면 횟수, 지표 보고를 사용자님께 보내기 전. 만든 작업과 다른 하위 작업이 합니다. 검수자는 만든 쪽 보고를 믿지 않고 원본(영상, 위치 기록, 파일)을 다시 봅니다.

## 필요한 입력
- 검수 대상 파일 경로와 만든 쪽 보고(표, 근거 경로).
- 만든 쪽이 따른 작업 카드 이름(그 카드의 "자주 틀리는 것" 교훈 번호를 모두 점검).

## 반드시 점검할 항목 (항목마다 통과/실패/확인 못 함)
표시 위치만 보고 끝내지 않습니다(L16). 주장 하나마다 1~6을 모두 봅니다.
1. 공: 그 초 앞뒤 1초 확대 사진에서 공을 찾아 픽셀로 적음. "공 가진, 공 쪽" 문구와 맞는지(L05, L08).
2. 정지: 키 초 ±4초 격자(`$PY -X utf8 $W/match-1120/coach/hl/grid.py <1|2> <초>`)에서 정지 신호가 있는지(L01).
3. 판정 자체: 주장한 모양(비어 있음, 1대1, 열세, 고립)이 숫자 기준에서 성립하는지. 기준이 글로 없으면 그 자체가 지적(L04). "비어 있음"은 확대해 사람 0명인지(L02), 겹친 선수가 없는지(L03).
4. 자막 시점: 자막이 말하는 사건이 그 화면 구간(멈춤 프레임, 느린 화면은 원본 3초) 안에 있는지(L06).
5. 표시 위치: 원·화살표가 대상 선수 위에 있는지 정지 사진으로(L12).
6. 분류: 장면이 그 편(수비 줄/미드필더/공격)의 주인공 줄과 맞는지(L15), 코치 글에 개발 정보가 없는지(L24).
7. 숫자: 수치마다 표본 크기와 출처 파일이 있는지, 상대 골키퍼가 섞인 지표가 아닌지(L07), 사람 판정과 모델 값이 섞이지 않았는지(L23).
8. 명령: "확인했다"는 줄마다 실제 돌린 명령과 출력이 있는지. 모의 실행만 한 것은 따로 적혔는지(L19). 경로가 실제로 있는지 `ls`(L18).

## 지적 형식 (고정)
| 번호 | 심각도 | 위치(파일, 초 또는 줄) | 무엇이 틀렸나 | 근거(사진 경로, 명령 출력) | 고칠 안 |
- 치명: 사실이 영상과 다름(공, 정지, 인원, 비어 있음), 숫자 기준에서 판정이 뒤집힘, 틀린 수치가 코치에게 보임. 고치기 전에는 보내지 않음.
- 중요: 근거 없음(사진, 표본 없음), 자막과 화면 시점 불일치, 기준이 글로 없음, 편 분류 틀림.
- 사소: 말투, 글자 수 초과, 색, 오타.
- 점검 항목 1~8 가운데 "확인 못 함"이 있으면 이유(예: 야간이라 공이 사진에서 안 보임)를 적습니다.

## 단계
1. 대상 목록을 만듭니다: 장면 문장, 표시, 수치를 하나씩 번호를 붙여 표로.
2. 장면이 10개를 넘으면 치명 후보(공, 비어 있음, 횟수)를 전부, 나머지는 무작위 5개를 봅니다. 몇 개 중 몇 개를 봤는지 적습니다.
3. 항목마다 점검 1~8을 돌리고 사진을 `<검수폴더>/`에 남깁니다(예: `$W/match-1120/coach/check/review-<YYYYMMDD>/`).
4. 지적 표를 씁니다. 지적이 없으면 "본 항목 n개, 치명 0, 중요 0"처럼 본 수를 적습니다.

## 필수 근거 (보고에 붙일 것)
- 점검 항목별 통과/실패 표, 지적 표, 본 항목 수와 전체 수, 사진 경로.

## 끝난 상태
대상의 모든 주장에 점검 결과가 있고, 치명과 중요 지적마다 근거 사진이나 명령 출력이 붙어 있습니다. 검수자는 대상 파일을 고치지 않습니다(고치는 일은 새 브리프).
