## 1. 공격 방향 자동 판정

### 방법
좌표는 저장된 추적에서 `load_half`로 미터로 바꾼 값입니다(+x가 화면 오른쪽). 팀 B가 +x 방향으로 공격하면 B의 자기 골대는 -x 쪽에 있습니다.
1. **위치 평균 비교**: 구간 안에서 B 선수들의 평균 x와 A 선수들의 평균 x를 비교합니다. B가 더 -x 쪽에 서 있으면 B는 +x로 공격한다고 판단합니다. 양 팀 모두 6명 이상 보이는 프레임만 쓰고, 두 평균의 차이가 1m 미만이면 보류합니다.
2. **골키퍼 위치**: 한 팀에서 가장 끝에 선 선수가 골라인에서 12m 이내이고 다음 선수보다 3m 이상 떨어져 있으면 골키퍼로 봅니다(8명 이상 보일 때). B의 골키퍼가 -x 쪽에 있거나 A의 골키퍼가 +x 쪽에 있으면 B는 +x로 공격한다고 판단합니다.

### 측정 결과: 후반 (정답이 알려진 쪽, B는 +x로 공격)
창 길이별로 (맞음, 틀림, 보류) 개수입니다.
| 창 | 위치 평균 비교 | 골키퍼 위치 | 두 방법이 일치할 때 |
|---|---|---|---|
| 10초 | 117, 0, 0 | 84, 13, 20 | 84, 0, 33 |
| 30초 | 39, 0, 0 | 30, 2, 7 | 30, 0, 9 |
| 60초 | 19, 0, 0 | 17, 0, 2 | 17, 0, 2 |
| 120초 | 9, 0, 0 | 8, 0, 1 | 8, 0, 1 |

- 위치 평균 비교는 모든 창에서 틀린 적이 없습니다. 골키퍼 방법은 10초 창에서 판정한 97개 중 13개가 틀렸고(87% 맞음), 창이 길수록 안정적입니다.
- 한계: 같은 경기의 연속 구간이라 창들이 서로 독립이 아닙니다. 팀이 계속 깊게 내려서는 경기나 한 팀이 계속 공격하는 시간대에는 위치 평균 비교가 뒤집힐 수 있으나, 이 경기에서는 관찰되지 않았습니다. 후반 전체 평균은 B가 A보다 평균 13.1m 더 -x 쪽에 섭니다.

### 전반 방향 추정 (전반 방향은 기록상 확인되지 않았었음)
- 킥오프 직후(영상 1:04에서 처음 2~10초): 선수가 B 11명, A 11명 모두 보이고, B의 평균 x는 +14.0m, A는 -19.5m입니다(측정). 킥오프에서는 각 팀이 자기 진영에 서므로 B는 +x 쪽을 지킵니다. 그래서 **B는 -x(화면 왼쪽)로 공격**합니다.
- 전반 전체: B의 평균이 A보다 11.8m 더 +x 쪽입니다(측정, 같은 결론). 골키퍼 방법도 같은 결론입니다(후보 수: B는 -x 쪽 610, +x 쪽 913, A는 -x 쪽 3,918, +x 쪽 132). 10초 창 141개 모두 위치 평균 비교로 -1을 가리켰습니다.
- 사진 확인: 영상 1:06 장면에서 형광 조끼 선수들은 화면 왼쪽 절반에, 어두운 옷 선수들은 오른쪽 절반에 서 있습니다(제가 장면을 직접 보고 확인). 어두운 옷 팀이 오른쪽 골대를 지키고 있으므로 B는 화면 왼쪽으로 공격합니다.
- 결론: 전반 B의 방향은 -1(화면 왼쪽)로 기록과 일치합니다. 이전 기록에 "전반 방향은 아직 직접 확인하지 않았다"는 표시를 "킥오프 위치와 장면 확인으로 -1이 맞음(2026-11-16)"로 바꿔도 됩니다.

### 라이브에서 쓰는 규칙 (설계)
1. 킥오프 신호(사용자가 시작 버튼을 누르거나 선수 11대11이 중앙에 모인 순간)에서 처음 5~10초의 위치 평균으로 판정합니다. 이 시점이 가장 믿을 만합니다.
2. 이후 60초 단위로 위치 평균과 골키퍼 위치를 다시 계산해 처음 판정과 계속 같은지 감시합니다. 두 방법이 다른 방향이면 알림 대신 "방향 확인 필요" 표시만 합니다.
3. 판정 자체는 화면에 "B팀이 화면 왼쪽으로 공격 중"이라고 보여 주고 코치가 한 번 누르면 확정합니다. 자동으로만 확정하지 않습니다.
4. 신뢰 조건: 양 팀 모두 6명 이상 보이고, 평균 차이가 5m 이상이며, 두 방법이 일치할 때. 하프타임 후에는 방향이 반대가 되므로 후반 킥오프에서 다시 판정하고 전반과 반대인지 확인합니다.
- 이 경기에서 후반 킥오프(영상 25:00 근처)는 저장된 후반 추적(영상 29:00부터)에 들어 있지 않아서, 킥오프 판정은 전반에서만 확인했습니다(측정 못 함). 후반 전체 구간 판정은 위 표대로 됩니다.

## 2. 팀 색 자동 확인
### 측정 (영상 1:04부터 10초, 프레임당 1장, 전반 추적의 상자 사용)
저장된 추적의 상자 387개 중 라벨이 A인 것 110개, B인 것 110개, 그 밖의 라벨(S 132개, R 9개, 없음 26개)이었습니다. 규칙은 기존 `shirt_label`의 형광색 비율(상의 영역에서 노랑 연두 계열 픽셀의 비율)입니다. 저장된 라벨은 학습된 분류기의 결과이므로 정답이 아니라 참고값입니다.
| 항목 | 값 |
|---|---|
| B 상자의 형광 비율 | 중앙값 0.0, 상위 90%도 0.0 |
| A 상자의 형광 비율 | 중앙값 0.108, 상위 90% 0.53, 하위 10% 0.0 |
| B 중 형광으로 오판 (문턱 0.05) | 0/110 |
| A 중 형광으로 판정 (문턱 0.05) | 59/110 (54%) |
| A/B 라벨 220개 중 규칙과 일치 | 문턱 0.05에서 169, 문턱 0.14에서 161 |
| A 상자 키 30픽셀 미만 | 67개 중 형광 판정 43% |
| A 상자 키 30~45픽셀 | 26개 중 54% |
| A 상자 키 45픽셀 이상 | 17개 중 94% |
- 문턱을 0.14에서 0.05로 낮추면 일치가 8개 늘었습니다. 두 군집으로 나누는 k-means(중심 0.012와 0.447)는 일치가 더 낮았습니다(전체 387개 중 314개).
- 의미: 어두운 팀은 거의 확실하게 가려지고, 형광 팀은 크게 찍힌 선수일수록 잘 가려집니다. 작게 찍힌 먼 쪽 선수는 약합니다(밤이고 해상도가 낮음). 한 장면의 한 경기 결과입니다.

### 사람이 한 번 확인하는 최소 절차 (설계)
1. 시작 후 처음 10초 동안 키 40픽셀 이상 상자만 모아 형광 비율을 계산합니다.
2. 두 무리로 나누고 각 무리에서 대표 선수 사진 3장씩을 화면에 보여 줍니다: "어느 쪽이 우리 팀(B)입니까? (왼쪽 사진 / 오른쪽 사진)". 코치는 한 번만 누릅니다.
3. 무리가 하나뿐이거나(형광이 없음) 대표 사진이 한쪽으로만 몰리면 "자동 확인 실패, 직접 선택"으로 바꿉니다.
4. 확인 결과를 기억해 두고, 이후 분류기가 한쪽 팀으로만 몰리거나 팀별 인원이 7명 미만으로 떨어지면 "팀 색 재확인" 표시를 띄웁니다.
- 이 절차는 코드로 구현하지 않았습니다(설계). 소요 시간은 코치가 사진을 보고 누르는 5~10초로 짐작합니다(측정 아님).

## 3. 하프타임 요약 자동 생성
### 측정 (전반 저장 추적, CPU)
| 단계 | 시간 |
|---|---|
| 추적 읽기, 미터 변환, 초 단위 계열, 이벤트 찾기 (`load_half`) | 11.6초 |
| 팀 모양 초 계열 (`seconds_series`) | 0.8초 |
| 구역별 비율, 영역 점유, 빈 쪽, 활동량, 간격, 이동 순간, 줄 모양(블록) | 합계 약 0.4초 |
| 공간 지배 계열 (5초 간격) | 1.1초 |
| 전반 보고서 23쪽 (`build_match_report.py`, 영상 장면 자르기와 그리기 포함) | 44초 |
- 합계는 약 1분입니다. 이 경우 3분 안에 가능합니다(측정). PDF로 묶는 단계(`images_to_pdf.py`)는 재 보지 않았습니다.
- 전반 B팀의 계산 결과 예(측정): 박스 침투, 수비 라인 하락, 침투 허용 등 이벤트 10개가 나오고(시각 107, 147, 429, 548, 649, 814, 858, 963, 1360, 1430초), 팀이 12m 이상 앞으로 밀고 올라간 순간이 12번, 물러난 순간이 7번입니다. 상대 진영에 머문 시간 비율은 60.9%입니다. 수비 라인이 비운 쪽은 왼쪽 46.1%, 가운데 0.5%, 오른쪽 48.6%입니다(수비가 가운데로 모여 있다는 뜻으로 보입니다).

### 가능한 조합 (하프타임 안에 보여 줄 것)
1. 한 줄 요약: 평균 몇 명 보였는지(B 9명, A 10명, 측정), 평균 상대 진영 점유 비율, 수비 라인 평균 깊이.
2. 팀 모양(폭, 길이, 줄 간격)과 빈 쪽 비율.
3. 박스 침투와 상대 침투 허용 장면 목록(시각, 종류). 장면 사진은 시간이 더 걸리므로 목록과 시각만 먼저 보여 주고, 사진은 뒤에 채웁니다.
4. 전반 알림 모음(종류별 개수, 같은 알림이 반복된 횟수).
5. 후반을 위한 확인 두 줄: 공격 방향 전환 확인, 팀 색 재확인.
- 시간 예산(추정): 하프타임 10~15분 중 전반 처리가 끝나 있어야 합니다. 현재 실시간에 가까운 처리(4분 영상에 250초, 약 1.04배)에서는 전반을 영상이 끝난 뒤에 처리하면 약 25분이 더 걸립니다. 그래서 전반이 진행되는 동안 처리를 계속 돌려야 합니다.

### 부족한 것 (먼저 만들 것)
1. **라이브 실행이 추적을 저장하지 않습니다**(`run_live_feedback.py`를 확인함). 알림과 영상만 저장됩니다. 요약에는 초마다 팀 위치(미터)를 `positions.jsonl`로 남기는 기능이 필요합니다(설계).
2. 저장된 추적은 오프라인에서 앞뒤를 보고 이은 것입니다(조각 이음, 빈틈 채우기). 라이브 추적은 과거만 보므로 선수 수가 줄어들 수 있고(분석 한 초당 약 10명 수준), 같은 요약이 같은 품질로 나오는지는 측정하지 못했습니다.
3. 이벤트 찾기(`mine_events`)는 골 시각을 입력으로 받습니다. 하프타임에는 골 시각을 코치가 눌러 두는 버튼이 있으면 좋습니다(없어도 이벤트는 나옵니다).

## 4. 상대 팀 패턴 분석
### 정의 (위치 정보만 사용, 공은 쓰지 않음)
1. **우리 수비 진영 진입**: 상대(A) 선수가 우리(B)의 수비 3분의 1(골라인에서 약 30m 이내)에 들어온 순간. 10초 안에 반복되는 진입은 한 번으로 셉니다.
2. **방향**: 진입한 선수들의 평균 좌우 위치를 왼쪽, 가운데, 오른쪽으로 나눕니다(폭 62m를 3등분, 상대 팀 기준의 좌우).
3. 이후 확장: 같은 방식으로 상대가 박스 안에 들어온 횟수, 진입 직전 10초 동안 상대 팀의 전진 폭.
### 측정 (전반, 저장된 추적)
- 진입 34번: 가운데 20, 왼쪽 8, 오른쪽 6 (상대 팀 기준의 좌우, 10초 간격 제한). 표본이 한 경기의 전반뿐이라 경향은 추정입니다.
- 이 값은 상대 선수가 위치한 곳이지 공이 있었던 곳이 아닙니다. 공을 돌리는 측면, 패스 성공, 점유율은 계산하지 않았습니다.
### 코치에게 보이는 방식 (설계)
- "전반에 상대가 우리 수비 진영에 34번 들어왔고, 20번은 가운데로 들어왔습니다." 한 줄과 진입 시각 목록.
